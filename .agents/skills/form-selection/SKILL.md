# Form Selection（形式选择）

为来源有界的语义对象选最小真实形式——不增加无主权威、重复维护、无用机制（theory/theory.md：表达·最小真实形式；harness.md：载体能力分界）。

## 何时使用

- 语义对象要落地：确定用任务表达、局部指令、文档、reference、skill、工具、runtime 配置还是 projection。

## 核心方法

1. **恢复四项使用关系**：受众（谁接收，已知什么）／ 目的（要改变什么理解/判断/记忆/能力）／ 预期行动（阅读、学习、查询、决策、执行还是机械解析）／ 媒介（怎样到达、检索、更新、验证）。
2. **外部关系**：不可变契约、权威源、consumer、生命周期、提示外硬属性（强制/权限/唤醒/原子性/恢复）。
3. **比较相邻真实形式**：逐一问"能不能由更小的现有形式承担"；不因内容像什么而转移所有权。
4. **选最小真实形式**：最小 ≠ 最短文本或最低 token，是权威与维护风险最小。
5. **只做普通落地检查**：不预建维护流程；硬保证交给工具/runtime，文字不产生权限。

## 边界

- 定义/名称不稳 → 交回 concept-articulation；skill 载体候选 → 交 skill-formation，不自行准入。
- 载体能力分界（harness.md）：Markdown 表达不了强制执行、唤醒、权限、原子性、恢复、跨 store 交接、持久身份、后台唤醒、不可逆外部效果、exactly-once——这些要求出现时 Markdown 适用性必须重新检验。
- `no-proposal` 时，给一个能区分候选的使用探针（最小可逆实践），不强行造载体。

## 返回

选定形式 + 一句话理由（对照相邻形式）；或 no-proposal + 使用探针。
