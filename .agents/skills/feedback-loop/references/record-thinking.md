# Record Thinking（capture 细节）

capture 模式的操作细节：把用户偶发的思考、观点、想法、灵感片段，忠实记录为原始想法的保留。

## 判定

记录动机是保存记忆——避免用户因为说过的内容没记录而重复说明；内容是否成熟、正式、值得研究或进入计划，不是记录的前提（016A）。
倾向记录，除非：明显是任务执行指令、用户说「不用记」、纯闲聊寒暄。

## 纪律

1. 基本还原用户所说/所写：保留语义、语气强弱、范围、否定、不确定性和顺序（CORR-2026-08-25-001）。
2. 可修正语法、错别字、断句和不通顺表达，不要求逐字原文；但必须保持语意——修辞变顺不得制造更强的意图、承诺或确定性。
3. 若修正可能改变语意：保留歧义、标记 unknown 或请求澄清，不用流畅表达填补缺失语义。
4. 正文只含用户的话；确有必要补充上下文或标注疑似笔误时，放独立标注的注记，不混入正文。
5. 只追加，不改写既有条目；修正与撤回用新条目注明关系。
6. 机械部分（编号、追加、防覆盖）用 `tools/register.py capture`，不手工编辑。

## 条目形态

```text
### THINK-YYYY-MM-DD-NNN
> 原文（基本还原，只做不改语义的润色）
```

## 不做什么

- 不把记录变成计划、任务、承诺、优先级或 acceptance；
- 不添加解释、推断、判断或承诺；不整理、不归类、不处置（那是 process 模式与其他流程的职责）。
