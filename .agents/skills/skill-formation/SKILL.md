# Skill 形成

不要把 skill 形成当作文档生成。这里要判断的是：一个 skill 方法是否需要可选择加载的载体。在本文中，**skill** 指方法，**skill 载体**指表达该方法、并可被选择加载的包。主要判断是：

> 这种可重复的判断或行动是否应编码为可选择加载的 skill 载体？如果应该，怎样设计最小的载体，既完整表达方法、改变预期行为，又不取得其他拥有者的权威？

创建和 review 是同一个生命周期判断在不同时间的应用。格式完好的文件只是一份候选；它能否继续存在，取决于当前边界与已经观察到的行为。

## 理论来源

以下 living theory 是生成本方法的语义来源：

- [`theory/skill-formation.md`](../../../theory/skill-formation.md) 定义准入对象、相邻形式、生命周期处置、review 维度与证据主张。
- [`theory/gene-expression.md`](../../../theory/gene-expression.md) 确立哲学条目在具体环境中冲出 skill 方法，方法再编码为 skill 载体，并在一次激活中表现为行为结果；三者都不是新的条目或稳定语义根。
- [`theory/harness/theory.md`](../../../theory/harness/theory.md) 提供方法表达与 runtime/base 之间的所有权检验。

[`theory/research/skill-formation.md`](../../../theory/research/skill-formation.md) 只保存生成期间使用的证据、反例与未知，不拥有本方法的语义。[`evals/skill-evaluation/protocol.md`](../../../evals/skill-evaluation/protocol.md) 只拥有匹配对照、fixtures、评分关系与收敛规则等评估契约，也不生成本方法的语义。

主要血统是 P01、P02、P05 和 P15：从真实来源出发，要求证据，保留具体环境的特殊性，并通过实践检验。P03、P04、P06、P09、P11、P14 和 P16 分别约束深化、未知、简化、主次、成本、命名与回归。只有这些血统实际改变设计判断时才引用；列出条目编号，不能证明方法由它们生长而来。

P 条目只记录本方法的生成血统；living theory、research 与 protocol 分别保留语义来源、生成证据和评估契约，standing 不同。它们都不是普通 skill 激活的前置阅读。本 skill 载体已把执行所需的方法内化在下文，普通激活只凭本文件完成主要判断；只有维护者在修订、诊断或重新生成载体时才沿链接审计。任务自身的事实来源仍须按任务要求读取。

## 从差距开始

不要从预设名称、目标目录、一批笔记或“必须产出一个 skill”的假设开始。先恢复以下关系：

1. **Agent 与环境：** 涉及哪个 Agent，以及怎样的模型或 harness 条件、可用上下文、工具和项目边界？
2. **行为对象：** 正在尝试哪种判断或行动？为什么不同实例属于同一类？
3. **已观察差距：** 哪个真实任务、用户纠正、失败轨迹或可复现 baseline 表明行为缺失或不稳定？
4. **重复性：** 同一关系还在哪里出现过？或者，哪些代表性任务能检验它是否会重复出现？
5. **预期改变：** Agent 应该怎样做得不同，必须拒绝什么，哪些部分仍属于其他拥有者？

保留会影响判断的未知。若行为对象或差距是否真实仍不清楚，返回研究需要或 `no-proposal`；不要用一份写得完整的候选掩盖证据缺口。

## 判断 skill 载体是否是最真实的形式

只有下列关系都得到足够支持时，才准入一份候选：

- 行为对象与预期改变足够具体，可以观察；
- 同一种判断或行动关系会跨任务重复，而不只存在于一次交付；
- 正触发、负触发和最近邻拥有者能够区分；
- 指导、例子、条件式 reference 或工具使用方法有理由改变行为；
- 与直接任务表达、已有 skill 载体、项目局部指令、普通文档、reference 或工具相比，skill 载体是更小、更真实的形式；
- 成功行为、拒绝行为和转交最近邻拥有者的行为都能检验；
- 预期收益大于发现噪声、上下文占用、重叠、漂移和维护成本。

编写指令之前，先做 harness 所有权检验：若某项属性必须在 prompt 被忽略、模型被替换、进程重启、并发发生或调用者不可信时仍然成立，它就属于 runtime/base 或其他具有强制能力的机制。skill 可以说明如何在效果或接受边界内工作，却不会因此取得产生效果、合并、发布或人类接受的权威。

以下否定出口都是真实结果：

| 发现 | 返回或拥有者 |
|---|---|
| 一次性工作或任务特有上下文 | 在当前任务中直接表达 |
| 必须在项目或目录中始终出现的规则 | 项目局部指令 |
| 持久理论、事实、决定或来源论证 | 普通 living 文档 |
| 没有独立触发或主要判断的条件细节 | 由现有 skill 或文档拥有的 reference |
| 确定性变换或外部操作 | 脚本或工具；是否调用仍由相应判断拥有者决定 |
| 生命周期、身份、权限、并发、恢复或持久效果保证 | runtime/base 设计 |
| 差距、重复性、边界或结果仍未知 | 研究或 `no-proposal` |

判定一个 skill 方法不应再由独立载体拥有后，不要再创建兼容壳。历史应由版本历史或 archive 保存；一个仍可被发现的壳会继续声称自己拥有现行触发。

## 形成候选

候选通过准入后，从 living theory 与具体环境中推导最小的方法表达。下列关系必须保留，但不要求机械地变成固定标题模板：

- **可发现的身份：** 名称与 description 应指明行为对象、正向用途和重要的非用途。先定义对象，再确定正式名称。
- **一个主要判断：** 所有步骤、references、例子和工具都服务于一个可辨认的行为变化与接受关系。“一个”不等于一句话或一个步骤。
- **来源地位与血统：** 指明当前语义来源，以及相关哲学条目怎样改变方法；把这些改变内化为可执行判断，使普通使用者无需回读 P 或 theory。任务事实的 canonical source 不复制进 skill 载体，生成血统也不能代替方法正文。
- **触发边界：** 包含正例、排除项和最近邻拥有者。受众或词汇相同，不足以形成边界。
- **行动方法：** 提供足够的推理关系、顺序、标准与条件细节，使 Agent 能在真实上下文中完成判断。不要为了节约 token 或显得简洁而删除承重解释。
- **权威与效果：** 说明 skill 可以提出或执行什么，以及什么仍需工具、runtime 拥有者、独立 review 或人类接受。
- **返回关系：** 要求返回决定或产物、支持它的观察、必要时被拒绝的备选、证据等级，以及调用者仍需知道的未知。
- **行为探针：** 在声称完成之前，先明确代表性的正例、反例、最近邻和回归任务。

主要路径留在 `SKILL.md`。只有当材料仅服务于某个条件分支，且没有独立触发或主要判断时，才把它移到 reference。只有确定性操作的输出或退出状态能够检验时，才增加脚本。文件名和落点应按对象身份、权威与生命周期做普通形式检查；它们本身不是制造更多结构的理由。

## Review 已有 skill 载体

先判断它是否还应继续存在，而不是先润色正文。恢复当初支持其准入的证据，再依次检查：

1. **成立性：** 重复行为差距是否仍存在，还是已经被模型、环境、其他 skill、文档或工具关闭？
2. **对象与边界：** 名称、description、正负触发、最近邻拥有者和主要判断，是否仍指向同一个对象？
3. **形式与上下文：** 可选择加载的指导是否仍是最小真实形式？分支细节是否按需展开？是否复制了外部语义源？
4. **Agent 表达：** skill 激活后，Agent 能否在不猜测的情况下恢复来源地位、判断标准、必要推理、允许效果、未知、返回与完成条件？
5. **行为与回归：** 代表性任务是否表现出预期行动、拒绝和转交，同时保留已有能力？
6. **体系关系：** 该 skill 是否与相邻 skills 重叠、矛盾或循环依赖？是否因自身关注而把一个局部问题抬高到不符合实际频率与后果的位置？

选择与证据相称的最小处置：

- **保留：** 对象、边界、形式与行为仍得到支持。
- **改写：** 上述关系仍成立，但现有表达不能可靠地恢复方法。
- **拆分：** 只有出现两个可独立触发、具有不同上下文与失败方式、能够分别检验且结果仍可重组的主要判断时才拆分。篇幅或小节数量不是证据。
- **合并：** 候选实际拥有同一行为对象、触发与成功关系，无法被有意义地分别选择，也没有独立失败或验证边界时才合并。共享术语并不足够。
- **降级：** 内容实为知识/reference、始终加载的局部规则、临时计划、确定性工具或 runtime 要求时，归还给相应形式。
- **删除：** 差距已消失、已由其他拥有者覆盖、方法没有净收益、无法安全维护，或移除后的回归没有观察到损失。
- **`no-proposal`：** 当前证据还不能区分以上处置。

不要因为一个问题刚被发现、描述得具体或格外占据注意力，就扩张整个 skill。改动幅度应与问题频率、后果、证据强度、修复成本，以及它与 skill 主要行为的关系相称。

## 验证行为与主张

运行仓库的机械 validator，检查格式与本地链接。这个结果只能报告为 `format-valid`。

更强的语义证据依照 [`evals/skill-evaluation/protocol.md`](../../../evals/skill-evaluation/protocol.md) 建立：

1. 冻结模型、任务、原始来源、工具、权威、harness 与工作区状态。
2. 比较不加载候选 skill 载体的 baseline，与只加载该载体并发生一次 skill 激活的 treatment。若无法隔离变量，只报告观察，不作因果归因。
3. 把发现与行动分开测试：先看元数据能否正确选择 skill 载体，再看激活后所表达的方法是否改善核心判断。
4. 包含正例、反例、最近邻、上下文和回归任务。对后果严重或波动明显的任务重复 trial，不能把一次成功当作稳定性。
5. 机械 grader 只判断确定性事实；由独立且能看见来源的 reviewer 判断语义保真、边界、行动质量和比例；最终接受仍由人类拥有者决定。

只采用实际成立的最强证据等级：

`format-valid` → `behavior-observed` → `boundary-supported` → `matched-improvement` → `regression-supported`

没有匹配 baseline，就不能归因改善；没有反例或最近邻任务，就不能声称边界得到支持；没有重复的回归证据，就不能声称稳定。

skill 作者可以解释意图，并应用本方法提出修改候选。自评、内部一致、一次成功的自我应用或多个 Agents 达成一致，都不能证明候选已被接受。任何超过机械有效性的主张，都应尽量把作者、执行者、独立语义 reviewer 与人类接受拥有者分开。

## 返回

返回一份紧凑但完整的 skill 形成记录：

- 行为对象、环境、重复差距与有出处的观察；
- 准入决定，以及为什么接受或拒绝相邻形式；
- 对于新候选：主要判断、触发边界、来源、权威边界和已命名的行为探针；
- 对于 review：处置决定，以及支持该改动幅度的证据；
- 机械结果与实际成立的最强语义证据等级；
- 会改变判断的未知、风险与仍需人类作出的决定。

不要把“已创建 skill 载体”或“review 通过”当作文件存在就自动成立的结果。真正的结果是一份有边界的载体候选，以及一个与证据相称的主张：它所表达的 skill 方法是否改变了预期的 Agent 行为。
