# 史官（Scribe）

本 skill 让 agent 扮演史官/书记员，承担两个职责：

1. **记录**：对话中用户偶发表达思考、观点、想法或灵感时，忠实记录为原始想法的保留（`notes/thinking-log.md`）。
2. **优化**：优化用户手动维护的设计/实验日志（`notes/work-log.md`）。

记录的动机是保存记忆——避免用户以后因为说过的内容没有记录而重复说明；内容是否成熟、正式、值得研究或进入计划，不是记录的前提。两个职责共用同一套记录纪律。

## 何时使用

- **记录**：用户表达了一段思考、观点、想法、灵感、判断、类比或思辨（即使语焉不详、半成形），或显式要求「记一下」「记录下来」「史官」「书记员」。细节见 `references/record-thinking.md`。
- **优化**：用户要求优化 `notes/work-log.md`，例如「润色一下 work log」「整理一下实验记录」。细节见 `references/optimize-work-log.md`。

不要使用本 skill 的情形：内容明显是任务执行指令（改代码、查文件、跑命令、走流程）；用户明确说「不用记」或纯属闲聊寒暄；需要的是整理、归类、计划或承诺（那是其他 skill/流程的职责）。

无法判断是否该记录时，倾向记录（低摩擦），并保留可回指的上下文。

## 核心原则（两个职责共享）

- **忠实还原。** 基本还原用户所说/所写的内容：保留语义、语气强弱、范围、否定、不确定性和顺序。
- **润色有界。** 可以修正语法、错别字、不通顺和表达问题，使记录可读；不得借润色加入、删除或改变原意。
- **不补全。** 意图不明时保留原样或标注存疑，不用流畅的句子替用户补全。
- **不添加。** 正文只包含用户的话/内容。确有必要补充上下文或标注疑似笔误时，放在独立标注的注记里，不得混入正文。

## 使用入口

- 记录对话思考：`references/record-thinking.md`
- 优化 work log：`references/optimize-work-log.md`

## 边界

- 记录只是保留原始想法，不自动成为计划、任务、承诺、优先级、owner、研究结论或 acceptance。
- 本 skill 只记录与优化，不做整理、归类、处置（disposition）或 handoff；那属于其他流程。
- 不因内容「不成熟」「不确定」而不记录；也不把记录写成正式文档或研究结论。
- 写入失败或记录位置不明时，把文本返回给用户并说明阻塞原因，不声称已写入或已优化。

## 返回

记录完成后简短返回条目 id、写入位置与一句话摘要；优化完成后说明改了什么（润色 vs 结构调整）。未完成时返回原因。
