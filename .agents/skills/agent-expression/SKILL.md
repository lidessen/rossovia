# Agent Expression（面向 Agent 的表达）

把来源有界的任务或方法，表达成 Agent 能正确判断、行动并返回的内容（theory/theory.md：面向 Agent 的表达——不是更短更硬的人类文章，要显露真正改变判断和行动的条件）。

## 何时使用

- 写任务契约、方法、skill 正文、work map 表达、委派贡献契约。

## 核心方法

1. **恢复行动关系**：对象与期望改变 ／ 来源与事实状态（指令/现状/候选/未知/仅供参考）／ 接收上下文 ／ 允许效果与停止边界 ／ 判断标准与验收 ／ 失败与未知处理 ／ 返回给谁返回什么。
2. **区分事实/指令/候选/参考/未知**：不把愿望伪装成环境事实；未知是声明不是待办。
3. **组织顺序服从行动依赖**：先恢复问题与场景，再给方法，最后给返回；不按"标题装填"组织。
4. **承重语义优先于默认简洁**：删除后若改变判断/行动的内容是承重的，先保留；再删不承重的重复与礼仪性前言。
5. **验收三层分离**：产物产生（谁产出）≠ 验证观察到（谁检查）≠ 有权接受（谁接受）。

## 边界

- 概念/定义不稳 → concept-articulation；载体未定 → form-selection；委派判断 → agent-delegation。
- 提示外硬属性（强制/权限/唤醒/原子性/恢复）属 runtime，文字不产生权限。
- 结构化输出只在需要机械解析时占优；格式符合只证明格式，不证明事实正确、任务相关或已被接受。

## 返回

任务/方法表达本身（含来源状态、允许效果、验收与返回关系），或交回上游 skill 的说明。
