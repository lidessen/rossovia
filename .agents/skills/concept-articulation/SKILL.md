# Concept Articulation（概念形成与指称）

让现实中的区别成为可共同判断的区别（theory/theory.md：概念形成与指称；P14 名不正则言不顺）。

## 何时使用

- 对象/概念/名称/定义有歧义，或要确立正式指称、引入新名词时。
- 一次性歧义句直接澄清，不建 canon。

## 核心方法

1. **从对象证据与来源状态开始**：不接受请求里的名称；先确认对象可指认、来源有据。
2. **恢复最小关系视图**：上位 / 并列 / 外延 / 整体部分 / 关联——概念边界由与其他概念的关系共同显现；最近邻是最可能导致实际误判的概念。
3. **四探针照验边界**：包含（正例入界？）／ 排除（反例出界？）／ 最近邻（与易混淆者可分？）／ 反例（什么不算它？）。
4. **先定义，后指称**：定义足够区分、不求说尽；「最小」服从「充分」——删决定性特征使边界坍塌、塞历史/实现/例子遮住概念身份，都说明定义不对。
5. **选正式指称**：名称受概念边界约束；不因词语被喜欢或读起来顺而采用。
6. **临时 handle**：调查不能等概念稳定时可用，但必须守三边界——状态边界（明示 provisional）、作用域边界（只在命名范围内有效，指回对象证据与未知）、结论边界（不得预设类别/因果/价值，开始牵引证据就替换）。
7. **行动检验**：改名但概念关系不变时，涉及该概念的判断/行动应基本稳定。

## 边界

- 对象不可指认、来源不足、区别不重复，或已有概念拥有该区别 → `no-proposal`（说明缺什么）。
- 名称、定义、概念、对象四者不能互相顶替：已有名称不证明对象找对；例子不等于定义。

## 返回

定义 + 指称 + 与最近邻的区分说明；或 no-proposal + 缺口。
