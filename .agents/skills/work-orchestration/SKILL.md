# Work Orchestration（工作编排与委派）

主 agent 指导自己如何组织工作：按**任务规模**自适应决定是否/创建多少 sub agents，按**任务类型**选择角色或工作动作；把分治的分解与整合视为可复用的两端，委派后再按需要筛选材料并重连整体；review 是评审类任务的编排模式。本 skill 吸收原 agent-delegation（委派机制）与 harness-review（Review 阵容）；规模估算复用 work-estimation。

## 何时使用

多步、复杂、可能受益于并行或深调查的任务开始前（先 `work-estimation` 估规模，再编排）；需要委派子 agent 时；以及装置/设计/文档需要 review 时。

## 核心判断（方法，不是规则清单）

1. **规模判断**：任务一步可逆 → 直接做；多步但串行、依赖清晰 → 外部化 work map；有独立并行面、深调查、多视角收益 → 委派 sub agents；协调成本超过收益 → 收敛回直接/顺序。**上下文保护也是委派收益之一**——任务细节留在子 agent 隔离上下文，不污染主 agent（AGENTS.md 主 agent 角色与上下文纪律）。
2. **类型判断**：这个任务的主要性质是什么（评审 / 深调查 / 核验 / 设计 / 探索 / 一般执行）——复杂任务可拆分为多个类型面。
3. **角色组合**：按类型选参考组合（下表），按规模定数量（小 → 1 个或不委派；大 → 多个，各负责一个独立面）；每个被委派者 = 对象 + 理论参考（选择部分）+ 角色/风格 + 贡献契约。

## 任务类型 → 角色组合（参考，判断式）

| 任务类型 | 参考角色组合 |
|---|---|
| 评审/审查（含 harness 自评） | 工作流设计角色 + 复盘角色 + 2-4 个风格角色（reviewer-styles），理论参考按对象血统（见 Review 模式） |
| 深调查/研究 | 探索者风格 × 独立路径（N 个，各沿一条路径，返回候选/反证/未知） |
| 核验/一致性 | 审计员风格（对照可追溯来源，挑归因失实/单一语义源冲突） |
| 设计 | 架构/工作流设计视角 + 多风格（审计员查一致性、克制者查过度机制化、体验者查可用性） |
| 一般执行 | 有界 worker（Agent as tool，贡献契约：对象/目标/来源/允许效果/返回关系） |

角色描述一律用 reviewer-styles 的**翻译后角色描述**（不写 xSTJ/P07 式标签编号）；组合按任务实际调整，不是穷举规则（行为模式不机制化）。

### 通用工作动作：分治的分解与整合

分治是对整体工作关系的通用处理策略，不是两个固定人格，也不要求由两个 Agent 分别承担。Main、child 或同一个执行者都可以承担其中一端；是否委派、并行或顺序，另由真实依赖与收益判断。分解与整合通常成对出现，但简单任务可以直接完成，没有真实局部边界时不分解，没有下游整体判断时不强行整合。

- **分解动作（原“拆分者”投影）**：从整体义务中找可独立承担的局部变换，明确边界、依赖、authority、允许效果、完成观察和返回关系；只在真实贡献边界成立时拆开。用于构建 work map、判断委派拓扑和区分可并行/必须顺序的部分；盲区是拆过头或丢失整体约束。
- **整合动作（原“整合者”投影）**：把局部结果重新接回整体义务，检查共性、矛盾、缺口、依赖、证据和未决关系，形成带 standing 的整体主张；不能把报告简单拼接或用多数投票代替关系恢复。盲区是过早收敛或掩盖未解释的冲突。

### 独立的材料筛选角色

- **丢弃者（curator）**：一个懂得"扔"的整理者。面对一堆材料（子 agent 结果、评审 aside、候选想法、中间产物），先对每个问：『维护它值得吗？潜在价值 > 维护成本吗？』——高维护低价值的**直接扔**（不整理、不归档、不保留），不为"以后可能有价值"囤积，只留下值得维护的（P06 为道日损；010A 设计修剪；007A 反向：维护成本 > 潜在价值就扔）。用于：结果筛选、评审 aside 处置（采纳/记录/直接扔三选）、候选想法去留、中间产物清理。盲区：可能误扔有长期价值的——判断依据不足的暂留，但默认倾向扔。

### 主 agent：全面综合者

主 agent **不偏科**——既能判断是否需要分治、如何分解（规模/类型判断、委派拓扑），也能执行整合（综合局部结果、意见、证据）；并且是**最终综合者**：分治动作或材料筛选可委派（量大时做中间层），但**最终综合、接受判断归 Main**（唯一综合者；综合意见是恢复关系，不是拼接报告或多数投票）。综合时**辩证**（看到每个候选的对立面、容纳冲突意见）并**抓主要矛盾**（P09：冲突意见先排序主次再裁，不被重复报告/最长篇幅带偏）；难以抉择时给出**有界判断**（基于证据与权衡、标注 uncertain、可回退），不无限发散也不假装确定（AGENTS.md 主 agent 判断）。

## 委派（吸收 agent-delegation）

委派是保持整体关系的有界转交——分出去的是有界贡献，不是整体责任。**委派前先恢复整体义务**（Main 持有整体：目标、硬约束、接受关系、non-goals）。

1. **六准入**（都满足才委派）：可指认的局部变换 ／ 可分来源 ／ 接收者可行动 ／ 返回可重连 ／ 收益 > 成本 ／ Main 可恢复约束。
2. **三问题识别贡献边界**：改变整体的什么？下游哪个判断用它的结果？什么证据重连？
3. **拓扑服从真实依赖**：独立 → 并行；顺序依赖 → 顺序；深调查 → 嵌套（child 不获得父的外层 authority，深度是组织选择）。
4. **贡献契约**：对象与目标、来源与允许效果、完成观察、返回关系（证据重连）、边界与 non-goals、未知处理。
5. **producer/reviewer/接受者分离**：执行者不评估自己；评审者没参与候选形成；接受归 owner。
6. **证据重连综合**：child 返回的是带 standing 的局部主张，不是自动事实；Main 综合是恢复关系，不是拼接报告或多数投票；嵌套委派不改变这项义务。
7. **委托 prompt 最小化**：harness（AGENTS.md 路由 + skills 方法 + 返回定义）设计良好时，委托 prompt **只需"对象与目标、来源/背景、允许效果边界、返回关系"**（若 skill 已定义返回则不重复），不需要方法性 instruction（怎么找路由/怎么执行/怎么返回）——那是 harness 承担的职责。harness 不足时**补 harness**（skill/AGENTS.md），不靠往 prompt 塞 instruction 弥补。

**比例**：局部发现不取得全局主次；新近、具体、写得最长或被多个 Agent 重复报告不因此成为主线（P09）；协调成本超过原工作就没有净贡献（停止扩张）。

## 评审人委派（吸收 agent-delegation）

设计文档/装置需要多人多角度评审时：风格库与生成模板见 `references/reviewer-styles.md`（4 种评审人风格：证据审计者 xSTJ / 模型探索者 xNTP / 用户现实观察者 xSFP / 克制性视角 xSTJ-K，可叠加领域视角；按目的选 2-4 个有区分度组合，不搞全矩阵；Main 作为协调裁判 xNTJ 只综合，不作为被委派的评审人）。每个评审人是全新独立 sub agent（producer/reviewer 分离）；收集 bounded aside（angle/candidate/why-relevant/evidence/unknown/contradiction-or-boundary/next-probe）；Main 汇总分类（一致/冲突/独见）；评审推荐不授权（对象论，接受归 owner）。

## Review 模式（吸收 harness-review）

对装置/设计/文档做系统 review 时的阵容与流程：

- **阵容**：工作流设计角色（整体工作流/架构质量）+ 复盘角色（结合 `notes/` 工作日志复盘实践 vs 设计）+ 2-4 个风格角色（局部逐对象，复用 reviewer-styles：审计员/探索者/体验者/克制者）。
- **理论参考**：每个评审人按对象血统**选 1 个理论组**（哲学序列 / harness 认知 / 表达理论 / 方法要点 / 记录纪律），不读全部 theory（理论权威仍是 `theory/`，分组只是聚焦手段）。
- **汇总分类与处置**：复用本 skill 的评审人委派（一致/冲突/独见 → 采纳/标记冲突/记录独见）。
- **闭环（本模式增量）**：处置后改对象 → `tools/check.py` 自检 + `tools/version.py freeze`。
- **工作流作用检查（review skill 的方法）**：review skill 不只查内部自洽——还要把 skill **放进工作流模拟场景走一遍**，查它在工作流中的作用（衔接断点、冗余、缺环节、是否被路由挂载），再结合 `notes/` 日志看实践是否用上。

## 流程（通用）

1. 恢复任务（对象、目标、约束、验收）；
2. `work-estimation`：规模与工作图；
3. 规模/类型判断 + 选角色组合（上表）；
4. 分配：每个被委派者 = 对象 + 理论参考（选择部分）+ 角色/风格 + 贡献契约（本 skill 委派节）；任务大而模糊时先做**分解动作**恢复 work map/拓扑，必要时再委派承担该动作的 worker；
5. 委派（本 skill 委派节：拓扑、producer/reviewer 分离、证据重连）；
6. 收集后按材料量、风险与维护成本判断是否需要筛选；保留的局部结果执行**整合动作**重连回整体，必要时才委派中间整合者；
7. Main 收集、**最终综合**（全面综合者：恢复关系、找共性/矛盾/缺口；不投票、不直接拼文字、评审推荐不授权）；
8. 处置与闭环（改 → check → version）。

## 边界

- **不替代** work-estimation（规模估算/工作图）——本 skill 是组织/编排/委派决策层；
- 复用 reviewer-styles 风格库；不重复造评审机制；
- 方法式表达（行为模式不机制化）：角色组合是参考判断，不是规则清单/机械阈值；
- 评审人只读、aside 返回、不落盘（留档归 Main）；评审推荐不授权，接受归 owner。
