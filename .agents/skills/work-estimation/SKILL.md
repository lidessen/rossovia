# Work Estimation（工作量判断）

在换算成 token/时间/金钱之前，恢复最小必要工作图、发现分支及当前决策能容忍的粒度（theory/harness.md：work map 驱动；P05 具体问题具体分析）。

## 何时使用

- 多步工作开始前、方案选择需要粒度判断时。
- 不需要：一步、低风险、可逆、完成关系直接可观察的动作（直接做）。

## 核心方法

1. **恢复状态转移**：从什么状态到什么目标状态（状态是改变必要判断/行动的最小事实集）。
2. **构造最小工作图**：节点 = 要改变必要状态、解决 decision-changing unknown、验证硬约束、保留 settle 关系的动作；不发明装饰性步骤。
3. **分开承诺与发现**：discovery branch 写明开关观察（什么条件下这条路走/不走），不把发现当承诺。
4. **按决策选粒度**：只估算到能区分当前选项的分辨率——如果两方案在粗粒度下已可分，不细化。
5. **返回与路由**：返回 estimate（最小工作图 + 分支 + 粒度说明），并指出下一 owner（执行/委派/形式选择/请示）。

## 边界

- 不发明价格、人日、时间点预测；不把节点直接映射成 token、价格或 Work Cell。
- 不批准预算或执行（那是 owner 的事）。
- 无法区分方案时：选有界 probe（最小可逆实践），不伪造 P50/P80/P95。

## 返回

estimate：最小工作图、承诺/发现分界、粒度依据、下一 owner。下一 owner 需要编排/委派（规模/类型判断、角色组合、贡献契约）时 → `work-orchestration`。
