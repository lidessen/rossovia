# Skills 方法要点

> 从归档 `.archive/.agents/skills/` 的 11 个方法 skill 提取的方法要点。这些是旧项目工作流的方法载体（方法表达层），
> 理论来源见 `theory.md`（认识/表达）与 `harness.md`（Agent 环境）。SKILL.md 全文保留在归档；本文件只记录每个方法的
> 核心判断与边界。顺序沿用 bootstrap 的开发工作流路由表。

## planning-inbox（规划收件箱）

- **作用**：低摩擦接收任意想法、观察、疑问、待办和半成形计划，忠实保留（语义保真 capture）并秘书式整理，不扩张承诺、优先级、owner 或授权。
- **核心判断**：capture 与 process 分离；raw 保留语义（可修正语法错别字，不改语意与语气强弱）；clear 前必须把可回读回执写入 history；consume/clear/archive/complete/delete 不能互换。
- **边界**：不把秘书推断变成 canonical obligation、Plan、goal、priority 或 acceptance；无法判断时保持 unknown/hold。

## concept-articulation（概念形成与指称）

- **作用**：从有来源依据的对象、特征、关系与具体用途出发，先形成足以区分最近邻的概念和定义，再选择正式指称，并检验区别是否改变判断或行动。
- **核心方法**：从对象证据与来源状态开始（不接受请求里的名称）→ 恢复最小关系视图（上位/并列/外延/整体部分/关联）→ 四探针照验边界（包含/排除/最近对照/反例）→ 先定义（足够区分不求说尽）再选正式指称 → 用临时 handle 时守住状态/作用域/结论三边界。
- **边界**：对象不能指认、来源不足、区别不重复或已有概念拥有该区别时返回 `no-proposal`；一次性歧义句直接澄清，不建 canon。

## work-estimation（工作量判断）

- **作用**：在换算成 token/时间/金钱前，恢复最小必要工作图、发现分支及当前决策能容忍的粒度。
- **核心方法**：恢复状态转移（从什么状态到什么目标）→ 构造最小工作图（节点要改变必要状态/解决 decision-changing unknown/验证硬约束/保留 settle 关系）→ 分开承诺与发现（discovery branch 写明开关观察）→ 按决策选择粒度（只估算到能区分当前选项的分辨率）→ 返回 estimate 并路由下一 owner。
- **边界**：不发明价格/人日/时间点预测；不把节点直接映射成 Work Cell、token 或价格；不批准预算或执行；无法区分方案时选有界 probe，不伪造 P50/P80/P95。

## form-selection（形式选择）

- **作用**：为已确立且来源有界的语义对象选择最小真实形式（无新载体/任务表达/局部指令/文档/reference/skill/工具/runtime/projection/有限计划）。
- **核心方法**：恢复四项使用关系（受众/目的/预期行动/媒介）+ 外部关系（不可变契约、权威、consumer、生命周期、硬属性）→ 比较相邻真实形式 → 选最小真实形式（最小≠最短，是权威与维护风险最小）→ 只做普通落地检查。
- **边界**：定义或名称不稳时交回概念；skill 载体候选交给 skill-formation，不自行准入；硬保证交给工具/runtime；`no-proposal` 时给一个能区分候选的使用探针。

## agent-delegation（Agent 委派）

- **作用**：判断整体工作中的真实有界贡献是否应交给另一 Agent，选择直接/顺序/并行/嵌套，表达贡献边界，并把带 standing 的局部结果重连回 Main 的整体。
- **核心方法**：先恢复整体义务 → 六准入关系（可指认的局部变换/可分来源/接收者可行动/返回可重连/收益>成本/Main 可恢复约束）→ 三问题识别贡献边界（改变整体的什么/下游哪个判断用/什么证据重连）→ 拓扑服从真实依赖 → 贡献契约八要素 → producer/reviewer/接受者分离 → 证据重连综合。
- **边界**：多主题/多文件/空闲 Agent 不构成委派理由；短任务、耦合判断、共同前提未确立时保持直接；复制同一宽 prompt 只产生伪共识；协调成本超过原工作时停止扩张。

## agent-expression（面向 Agent 的表达）

- **作用**：把来源有界的任务或方法，表达成 Agent 能正确判断、行动并返回的内容。
- **核心方法**：恢复行动关系（对象与目标/来源与状态/接收上下文/允许效果/判断与验收/未知与失败/返回关系）→ 区分事实/指令/候选/参考/未知，不把愿望伪装成环境事实 → 组织顺序服从行动依赖 → 承重语义优先于默认简洁 → 验收三层分离（产物产生/验证观察到/谁有权接受）。
- **边界**：概念不稳交 concept-articulation；载体未定交 form-selection；委派判断交 agent-delegation；提示外硬属性属于 runtime，文字不产生权限。

## human-writing（面向人的写作）

- **作用**：把来源有界的语义对象，按具体读者、目的、场合与媒介，写成使人准确理解、判断或行动的完整自然表达。
- **核心方法**：恢复写作关系（语义对象与来源/读者起点/目的与到达点/场合/媒介边界）→ 守住主张边界（连接也是主张，需要来源或标记的推断）→ 形成整体推进（理解路径而非标题装填）→ 展开论证/例证/未知 → 在完整与成本间修订（承重语义先于 token 经济）→ 从接收效果检验。
- **边界**：对象/概念不稳交 concept-articulation；载体未定交 form-selection；Agent 任务契约交 agent-expression；双受众同步交 dual-audience-expression。

## dual-audience-expression（双受众表达）

- **作用**：让同一语义核分别形成人视图与 Agent 视图，维护唯一权威、派生、同步与语义回归。
- **核心方法**：准入（真实双受众+共享承重语义+可观察的同步关系）→ 恢复共享语义核（对象/来源/范围/权威/证据）→ 按接收关系形成不同视图（人：背景/理由/例子/未知；Agent：对象/来源/允许效果/判断/返回）→ 建立权威/派生/追溯 → 来源先变再同步 → 语义回归（按共享语义与接收效果，不是文本对齐）。
- **边界**：单一受众、无共同语义核、对象不稳时 `no-proposal`；不预建两套视图；派生视图不因便于消费取得第二权威。

## mechanism-design-review（机制设计审查）

- **作用**：在设计准备增加状态、记录、队列、锁、重试、门、hook、registry、协议或生命周期机制时，判断真实对象、现有 owner 与最小充分处置。
- **核心方法**：Review unit 绑定可观察 failure/counterexample、后果和 owner → 三问题：Identity（这是什么谁拥有它，先不接受名称）、Origin（什么真实压力产生它，从 proposed solution 之外恢复）、Destination（什么关系必须变成真，而非功能愿望）→ 比较处置顺序：保持设计→澄清 prompt/skill/文字→复用/收窄已有 owner→确定性检查→才提 `mechanism-candidate` → 计算完整负担（概念/schema/记录/状态/迁移/运维…）。
- **边界**："更可靠/更显式/以后可能需要"不是机制成立理由；假设性风险不能单独成为 case evidence；设计字段前先选表达形态（label/enum/属性组合/投影），字段误当机制时回到机制准入。

## practice-cycle（实践回返）

- **作用**：给定一次真实实践的结果，判断下一项最小实践如何修订或收敛当前理解。
- **核心方法**：定位实际对象（分开观察/推断/候选/未知）→ 命名活矛盾（阻止下一行动的未知）→ 选一个最小可逆实践 → 由真实 owner 执行观察 → 用反观察回看（不能改变后续决策的动作不构成学习）→ 处置（`settle`/`continue`/`route`/`uncertain`）→ 只外化会改变后续决策的学习。
- **边界**：不把重复动作冒充学习；不把格式通过/文件存在/Agent 自称完成当成接受；Principal 改变目标时先废止旧判断再继续。

## skill-formation（Skill 形成）

- **作用**：判断反复出现的 Agent 判断/行动差距是否应编码为可选择加载的 skill 载体，并决定保留/改写/拆分/合并/降级/删除。
- **核心方法**：从差距开始（Agent 与环境/行为对象/已观察差距/重复性/预期改变）→ 准入检验（对象可观察/跨任务重复/触发可分辨/方法可由表达改变/是最小真实形式/行为可检验/收益>成本）→ 形成候选（可发现身份/一个主要判断/来源地位与血统/触发边界/行动方法/权威与效果/返回关系/行为探针）→ Review 六面（成立性/对象与边界/形式与上下文/Agent 表达/行为与回归/体系关系）→ 证据等级 `format-valid → behavior-observed → boundary-supported → matched-improvement → regression-supported`。
- **边界**：一次性工作/项目规则/持久知识/条件细节/确定性变换/runtime 保证各有真实形式（任务表达/局部指令/文档/reference/工具/runtime），不强行造 skill 载体；差距未知时返回研究或 `no-proposal`；不创建兼容壳。

## 关系速记

- 表达三兄弟：`human-writing`（人）、`agent-expression`（Agent）、`dual-audience-expression`（双受众映射）——共享同一语义核来源。
- 判断四步：`concept-articulation`（是什么）→ `form-selection`（用什么载体）→ `agent-expression`（怎么写）→ `skill-formation`（是否沉淀为 skill）。
- 工程三防：`mechanism-design-review`（别过度机制化）、`work-estimation`（别夸大工作量）、`practice-cycle`（别把过程当结果）。
- 协作两轴：`agent-delegation`（是否分、怎么分、怎么合）、`planning-inbox`（怎么低摩擦接住想法并保真）。
