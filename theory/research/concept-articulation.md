# Research — 概念形成、定义与命名

**状态**：`no-proposal`（不提议新增哲学序列条目）

**问题**：在问题处理与 skill 形成中，怎样先确立对象和概念边界，再写定义、选择正式名称；行动尚不能等待时，临时 handle 又怎样不反客为主？

**范围**：研究对象、概念、概念关系、定义、designation/name 的次序与边界。本文不制定 theory 正文，不设计 skill，也不决定文档形式或品牌名称。

## 1. 来源与证据边界

### 现行项目来源

- [`theory/gene-expression.md`](../gene-expression.md) 把「一」界定为对象同一性：先从未分现实中确立「这一个」，随后对象内部的差异才可能形成条目与方法。它是本研究的项目内语义根。
- [`theory/philosophy.md`](../philosophy.md) 的 P14「名不正则言不顺」位于解决·表达环节，必答问题是「如何让实践主体行动」。因此，“名正”不是词语审美，而是表达能否使实际行动不因名实错位受阻。
- P01/P02/P04/P05/P06/P15 分别提供来源、证据、已知边界、特殊性、简化与实践检验的约束；它们是本研究的支持条目，不意味着要把概念形成拆成新的哲学序列条目。

### 一手外部来源

- [ISO 704:2022, *Terminology work — Principles and methods*](https://www.iso.org/standard/79077.html) 的公开范围明确包括对象、概念、定义与 designation 之间的联系，以及术语、专名和定义的形成原则。
- [ISO 1087:2019, *Terminology work and terminology science — Vocabulary*](https://www.iso.org/standard/62330.html) 是现行术语工作词汇标准，2025 年复审确认继续有效。本文引用其条款号：object §3.1.1、extension §3.1.2、domain §3.1.4、characteristic §§3.2.1–3.2.5、concept §§3.2.7–3.2.9、concept relation §§3.2.11–3.2.28、definition §§3.3.1–3.3.5、designation §§3.4.1–3.4.5。
- [W3C SKOS Primer](https://www.w3.org/TR/skos-primer/) 与规范性的 [SKOS Reference](https://www.w3.org/TR/skos-reference/) 把 concept、identifier、lexical label、semantic relation、definition/scope note 分成不同构件。SKOS 是知识组织数据模型，不是本项目概念形成理论；这里只把它用作“概念不等于标签”和“关系参与界定概念”的独立工程证据。

ISO 标准全文并非都由官网公开展示；以下不复刻标准正文，只保留完成本研究所需的短释义和条款指针。SKOS 的工程语义也不能反过来定义现实中的对象。

### archive 历史证据

- [`archive/skills/naming-and-articulation/SKILL.md`](../../archive/skills/naming-and-articulation/SKILL.md) 曾提出“先恢复关系，再选择词”“名称是 handle，不是对象本身”，并允许在对象未完全认识时使用显式 provisional name。
- [`archive/skills/naming-and-articulation/references/articulation-layers.md`](../../archive/skills/naming-and-articulation/references/articulation-layers.md) 区分 name、operative definition、explanation 与 audience projection。
- [`archive/principles/research/naming-and-articulation.md`](../../archive/principles/research/naming-and-articulation.md) 的结论是 `no-proposal`；[`archive/evaluations/2026-07-10-naming-and-articulation-probe.md`](../../archive/evaluations/2026-07-10-naming-and-articulation-probe.md) 只观察到一次受限任务行为，且明确没有 matched baseline、独立 evaluator 或普遍命名质量证据。

这些是历史假说和有限行为证据，不是 living design。其旧 P-ID 血统已经失效，不能直接迁移。

## 2. 基本区分

| 层 | 本研究采用的含义 | 不能替代什么 |
|---|---|---|
| 对象（object） | 可感知或可设想之物；项目首先要从现实材料中确立正在处理的「这一个」 | 不能由目录名、已有术语或漂亮比喻反推对象 |
| 概念（concept） | 由一组特征形成的知识单元；可对应一个独特对象，也可对应一组共享属性的对象 | 不是承载它的字符串，也不是任意主题词 |
| 外延（extension） | 与概念对应的对象集合 | 只列一两个例子通常不能穷尽外延 |
| 内涵（intension） | 构成概念的一组特征 | 不是关于对象的全部事实；非本质实现细节不应混入 |
| 概念关系 | 概念在系统中的类属、整体—部分、并列或关联关系 | 不能只用“像不像”或字面近似代替 |
| 定义（definition） | 用表达描述一个概念，并把它与相关概念区分开 | 定义的对象是概念，不是词形；也不是操作要求、宣传语或百科全文 |
| designation | 在特定领域或论题中，以符号指称概念；可为 term、proper name 或 symbol | designation 只负责指称，不能独自证明概念边界正确 |
| term | 以语言表示一般概念的 designation | 不适合称呼唯一对象时硬充“术语” |
| proper name | 表示个别概念的 designation | 不是一般概念的定义 |
| 临时 handle | 为研究与协作临时指向尚未稳定对象/概念的局部标记 | 不是 preferred term、接受结论或 canonical definition |

ISO 1087 还指出 domain 的边界与粒度按目的确定（§3.1.4），concept 虽不必绑定单一自然语言，却受社会文化分类影响（§3.2.7）。因此不存在脱离目的、受众与领域仍唯一正确的词；但这不等于可以任意命名，因为同一讨论范围内仍需稳定的对象证据和区分特征。

## 3. 关系先于正式名称

ISO 1087 把定义规定为对概念的描述，并要求它能把该概念同相关概念区分开（§3.3.1）。其优先推荐的内涵定义由“直接上位概念 + 区分特征”组成（§3.3.2）。SKOS 也明确：概念独立于用于标记它的词；概念的意义不仅来自自然语言标签，还来自它与其他概念的链接。

由此可采纳的不是“任何时候必须先写好最终定义”的僵硬流水线，而是以下依赖关系：

```text
对象证据与处理目的
  → 概念的特征、外延与关系
  → 可与邻近概念区分的定义
  → 面向领域和受众的正式 designation
```

这是本项目根据现行对象同一性与外部术语学做出的**方法推论**，不是声称 ISO 规定了唯一时间顺序。实际调查会来回修正：候选词可能暴露遗漏的邻近概念，反例可能迫使重写定义；但正式名称不能成为先验锚点，再要求证据迁就它。

P14 在这条链上的作用位于末端检验：名称和表达是否忠实承载已经形成的区别，使实践主体作出正确判断。它不能越过对象同一性替人凭空制造对象，也不能用“名正”掩盖来源或证据不足。

## 4. 怎样形成可区分的概念

### 4.1 先固定问题化视角

先写明：

- 现实中正在指认什么材料、行为、关系或变化；
- 谁需要用这个概念作什么判断；
- 所属 domain/subject 及其粒度；
- 哪些观察会证明当前其实混合了两个对象，或把同一对象误拆成两个。

这一步对应项目的对象同一性。若连处理对象都随说话者漂移，增加定义文字只会把漂移藏起来。

### 4.2 建立最小概念关系图

“最近邻”不是搜索名称相似度，而是找最可能造成实际误判的关系邻居：

- **直接上位概念**：它首先是什么一类东西？
- **并列概念**：在同一划分标准下，它与哪些同级概念相邻？差异特征是什么？
- **下位概念或实例**：哪些明确属于它；哪些只是例子，不能反过来充当定义？
- **整体—部分**：当前说的是整体还是构件，避免把 `part-of` 写成 `is-a`。
- **关联概念**：因果、时序、使用或协作相关，但并非类属关系。

ISO 1087 区分 generic、partitive、coordinate 与 associative relations（§§3.2.13–3.2.23）；SKOS 也把 broader/narrower 与 related 分开，并特意不把所有 broader 链都默认作直接传递。它们共同反驳“只要两个词经常一起出现，就属于同一个概念”的做法。

### 4.3 写包含、排除和反例

对候选概念至少保留：

- **包含**：典型实例与一个边界实例；说明它们满足哪些必要特征。
- **排除**：最近的非实例；说明缺少哪一项区分特征，而不是只说“不算”。
- **易混淆邻居**：写出同一上位概念、共同点和决定性差异。
- **反例/证伪观察**：若出现什么，当前边界必须拆分、合并或重做。

包含/排除是边界探针，不应全部塞进一句定义。SKOS 将 definition、scope note、example、history note 分开，也说明标签、完整定义、使用范围和例子承担不同功能。

## 5. 定义不等于标签

定义和 designation 都表示概念，但功能不同：

- 定义回答“它凭哪些特征属于这一个概念，并与邻居有什么差别”；
- designation 回答“在这个领域和受众中，用什么符号稳定指向它”；
- explanation 回答“为什么这个边界重要，怎样影响当前行动”；
- example 只显示某个实例或用法，不能单独证明完整边界。

优先尝试内涵定义：

```text
候选概念 = 直接上位概念 + 最小区分特征
```

再用包含、排除和最近邻测试它是否过宽、过窄、循环或换词复述。只有能枚举同一划分标准下全部下位概念时，外延定义才完整；开放集合不应伪装成穷尽列表。

以下形式不构成有效定义：

- `form-selection 是用于选择 form 的方法`：标签的循环改写，没有上位概念和区分特征。
- `agent-readable 是 agent 能读的`：把待解释词换成同根词。
- `skill 是一个 SKILL.md 文件`：把当前载体实现误作概念身份。
- `委派就是让 sub-agent 干活`：既没有说明相对直接执行的边界，也没有整体责任和回收关系。

## 6. 临时 handle 与正式命名

现实协作不总能等待概念完全稳定。允许临时 handle，但需要同时满足：

1. **显式状态**：标为 temporary/provisional/working handle，不称“正式名称”“preferred term”或已接受术语。
2. **局部作用域**：说明它在哪个调查、分支或讨论内有效，避免自然扩散成项目 canon。
3. **指回对象证据**：handle 后保留所指材料、未知和待区分邻居；不能只留下一个词。
4. **不承载隐藏结论**：名称不得偷偷预设类别、因果、所有权或评价。例如调查中称 `writer-agent`，不能据此认定它只写、不评审。
5. **晋升门**：只有概念边界、定义、邻近对比和预定受众都稳定，且名称通过实际区分测试，才可提升为正式 designation。
6. **可抛弃**：一旦名字开始牵引证据或误导行动，应直接改名；保留历史别名仅为检索，不维持第二语义源。

SKOS 提供一个有用但有限的类比：concept 可先用 URI 独立标识，再附 preferred/alternative labels；label 不是 concept 本身。项目中的临时 handle 不必实现 SKOS，也不因获得唯一标识就自动获得正确语义。

正式命名时再区分：一般方法、能力或类别通常需要 term；唯一项目、组织或个别对象使用 proper name；代码和文件标识符只是载体层 designation，除非它们确实拥有同一个已定义概念。

## 7. 历史经验的吸收与拒绝

### 吸收候选

- 吸收“先恢复实际关系，再选名称”；现在由对象同一性、ISO 概念系统和 P14 共同解释，不继承旧 P-ID。
- 吸收“name 是可修订 handle，不是 essence”；进一步严格区分临时 handle、term、proper name 与定义。
- 吸收“定义必须有行动相关边界”“无需共享判断时可以不造术语”的停止意识。
- 吸收 archive probe 的负面结论：一次成功产物、既有候选名称和无基线评估，不能证明普遍命名质量。

### 拒绝或暂不采纳

- 不继承 archive 的固定四层产物栈；名称、定义、解释、例子和投影是否都需要，属于后续形式判断。
- 不把“被阻塞的决策”定为概念形成唯一触发；理论研究、跨语言对齐和未来恢复也可能需要稳定概念。
- 不把 canonical placement 纳入本研究核心；源位置与目录归属是后续形式/组织环节的普通检查。
- 不从一次 probe 推导独立 skill 已成立；应由后续 skill-formation 理论和行为对照重新判断。

## 8. 反例与边界探针

| 情形 | 失败在哪里 | 应怎样处理 |
|---|---|---|
| 先爱上 `attention economy` 一词，再把所有注意问题装进去 | designation 绑架对象与外延 | 回到对象证据，按因果与关系拆分；候选词降级为 handle |
| 用 `agent-communication` 包含委派、写作、上下文、skill 形成和工作流诊断 | 一个宽标签遮住多个不同概念与判断 | 找各自上位概念和区分特征；不因旧目录已存在就维持同一性 |
| 把 `SKILL.md` 定义为 skill | 载体变化会让“概念”消失 | 定义重复行为能力与判断；文件只作为当前表达形式 |
| 只列三个正例，没有最近非例 | 不能发现定义过宽 | 增加同上位概念的排除例和区分特征 |
| 把“作者”和“评审者”当作互斥类型 | 可能把本轮角色关系误写为永久类别 | 说明讨论的是同一任务内的责任隔离，而非人的本质类别 |
| 给一次性句子创建 glossary term | 没有反复指称或恢复需求 | 直接写清句子，不形成正式名称 |
| 两个团队都用 `verified`，一个指测试通过、一个指人已接受 | 同标签对应两个概念 | 分开定义和 designation，或明确 domain/status scheme |
| 名字优美、评审者喜欢，但行为选择未改变 | 只有审美证据，没有 P14 的行动效果 | 保持候选状态，增加区分与行动探针 |

## 9. 研究结论

### Adopt

1. 概念表达的依赖顺序采用：**对象证据与目的 → 概念特征和关系 → 定义 → 正式 designation → 行动检验**；允许迭代回返，不允许正式名称支配证据。
2. 概念边界至少由包含、排除、最近邻和反例共同检验；最近邻优先从直接上位、并列、整体—部分和关联关系中找。
3. 定义描述概念并把它与相关概念区分；标签只指称概念，例子只展示实例，三者不得互相顶替。
4. 临时 handle 可提前使用，但必须显式、局部、可抛弃，并携带未知与源证据；它不取得 canonical 地位。
5. 正式名称的好坏最终由目标主体能否稳定作出原先会混淆的判断来检验，而不由词语新颖度或讨论篇幅决定。

### Revise

- archive 的“object → relation → name → operative definition”需修正为：关系和特征先形成概念，定义把边界说出，随后才确认正式 designation；候选词可参与探索，但只能以临时 handle 身份出现。
- archive 的“最小定义”需修正为“足以区别最近邻的定义”。短不是独立目标；删掉区分特征即使更省 token，也是不完整。
- 现行项目口语中的“name”应按对象类型细分为 term、proper name 或临时 handle；无需在普通写作中强制展示术语学标签，但内部判断不能混淆。

### No-proposal

**不提议新增哲学序列条目。** 对象同一性已经承担“先确立这一个”；P14 已承担名实相副并使实践主体行动；来源、证据、边界、特殊性、简化和检验由现有条目提供。这里得到的是这些基础在“概念形成与表达”环境中的方法候选，属于后续理论/skill 的研究输入。

也不提议现在建立全局 glossary、概念数据库、强制 SKOS/ontology、独立命名委员会或新目录。只有后续真实任务反复证明普通文档和现有方法无法保持概念关系时，才重新研究载体或机制。

## 10. 后续验证问题

- 同一模糊材料下，采用本顺序的 agent 是否比 baseline 更少把载体、角色或漂亮词误作概念？
- 在给定正例、最近非例和上位概念后，agent 能否写出真正改变区分的定义，而不是标签复述？
- 使用临时 handle 时，下一位 agent 能否准确复原未知、边界和状态，而不误报为 accepted term？
- 去掉正式名称、只保留对象证据和关系时，概念是否仍可重建；反过来只给名称时，agent 是否会诚实报告无法恢复边界？
- 改名而保持概念关系不变时，后续行动是否稳定；若行动随名字漂移，说明语义仍错误地绑在 designation 上。

这些问题需要 matched baseline/treatment、独立 reviewer 和真实行动任务。未取得这类证据前，本研究只能支持理论候选，不能证明未来 skill 已有效。
