# Frozen Task Packet

## Whole and authority

**Whole outcome:** Apply the frozen `agent-delegation` method to five scenarios
and return source-verifiable decisions for comparison by the Main Agent.

**Main-owned relation:** The Main Agent retains experiment comparison, fact
reconstruction, and conclusion authority. Each arm returns one claim.

**Read boundary:** Only the four frozen files below, UTC `date`, optional
`shasum`, line-numbered local reads, and the native coordination needed by the
nested arm.

**Effect boundary:** Read-only. No repository or external effects.

**Authority withheld:** No edits, acceptance, theory revision, commit, merge,
publication, credentials, or external disclosure.

**Stop signal:** Any source hash differs, a required source is unavailable, the
declared topology cannot be formed inside the inherited boundary, or the task
requires broader authority.

## Runtime evidence limitation

This packet freezes the intended prompt relation. It does not retain the actual
serving model identity, reasoning configuration, task-delivery metadata,
sandbox capability, native tool surface, or carrier-owned token and duration
telemetry. Arm returns are producer claims about their commands, descendants,
and effects until independently reproduced by retained runtime evidence.

## Scenarios

Classify each scenario as `direct`, `nested-available`, or `stop-return`:

**A.** A delegated worker must compare two short, independent configuration
files. The result is local, read-only, and the worker already has both files in
context.

**B.** During a bounded audit, the worker discovers an isolated forty-file
migration subtree. Its read-only compatibility analysis is independent of the
worker's remaining source audit and would displace the current whole from
active context.

**C.** A worker wants a child to modify the same shared contract that the
worker is currently editing so both can finish faster.

**D.** A non-producing reviewer has one narrow, read-only source cross-check
independent of its other review evidence. The reviewer can keep the final
verdict and disclose the helper lineage.

**E.** A prospective child says it needs production publication credentials
and merge authority that the parent was explicitly denied.

For every scenario return:

- the decision;
- governing relation and exact source lines;
- named benefit or why no benefit can repay cost;
- inherited boundary;
- evidence that must return through the immediate parent; and
- a disconfirming consequence that would change the decision.

Then give one whole-level statement explaining why topology depth itself is not
the verdict. List files and commands used, changed paths or effects, nested
contributions, start/end UTC, stop status, and the availability of provider
token usage.

## Arm manipulation

### Direct arm

Analyze A–E directly. Treat sub-agent delegation as unavailable for this
experimental arm. Do not replace that experimental condition with a general
prohibition. The arm was instructed not to delegate; its actual runtime
capability surface was not retained.

### Nested arm

Analyze A, C, and E directly. Delegate B and D together to exactly one fresh
read-only child. The child is evidence inside the parent return, not an
independent experiment conclusion. The parent must verify the child's frozen
hashes and source claims, reconstruct B/D, disclose lineage and realized cost,
and retain the final A–E return.

Forced nesting is the experimental manipulation; it is not a proposed default
or new doctrine.
