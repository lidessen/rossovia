# Todo carrier semantic audit

## Shared mechanics

Both carriers require the worker to:

1. create `todo.md` before changing either requested artifact;
2. keep exactly three Markdown checkbox items using `[ ]` or `[x]` state;
3. revisit and update the file after each artifact write;
4. inspect both final artifacts against `source.md`; and
5. copy the final artifact contents into the structured settlement.

Both carriers receive the same worker-visible intent and acceptance conditions.
Neither contains evaluator-only answers or source facts absent from those
conditions.

## Intended difference

`arm-obligation` uses each item to preserve a concrete task obligation and its
reopen condition:

- repair the primary notice without unsupported claims;
- return to and repair the companion routing index so it agrees with the
  source and notice; and
- reconcile both artifacts before settlement, reopening either when they
  diverge.

`arm-ceremony` uses each item to preserve a generic activity phase:

- Prepare;
- Execute; and
- Finish.

Its phase closure conditions mention only completing the phase and advancing to
the next one. It receives the same instruction length target and todo-update
cadence but does not restate the artifact obligations.

## Claim boundary

This comparison tests obligation-bearing versus ceremonial external todo
content. It does not isolate file persistence from prompt repetition, compare
Work Cell Task API presence, or establish the neural mechanism by which either
carrier affects a model.
