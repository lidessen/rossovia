# Round 1 fixtures

Use only the facts in each packet. Declare unknowns instead of completing the
story. A good result may refuse the requested form.

## F1 — Skill admission and neighboring owners

Four observations were collected from the same project:

1. Across six unrelated research tasks, an Agent loaded an entire large policy
   corpus, lost the source-status distinction, and treated a projection as the
   authority. The desired repeated judgment is to select only decision-relevant
   source material while retaining source authority. No current skill owns it.
2. A versioned API catalogue changes when the provider changes its endpoints.
   Agents need to look up fields only after a relevant API task is active.
3. The project never permits direct pushes to `main`; this boundary applies to
   every task in the repository.
4. Two writers must never mutate the same worktree concurrently, including when
   a prompt omits that restriction or a process restarts.

For each observation, choose among a skill method encoded in a candidate skill
artifact, reference, project-local instruction, ordinary document, tool/runtime,
or no new artifact. State the owned relation, the strongest no-new-form case,
and what evidence would be needed before claiming improvement.

## F2 — Concept articulation

The working label `verification` is used for all of the following:

- a command exited with status zero;
- a produced file satisfies a deterministic schema;
- an independent reviewer believes a design fits its sources and intent;
- a human decides to accept and publish the result.

Define the concepts needed to prevent these states from being substituted for
one another. For each concept give its direct broader concept, differentiating
characteristic, inclusion, nearest exclusion, and a falsifying example. Use
temporary handles until the definitions are stable, then propose names.

## F3 — Form selection

Choose a truthful form for each object without inventing a new subsystem:

- a durable explanation of what counts as a skill;
- a repeatable skill method whose artifact is loaded and activated only when an
  Agent must decide whether to form a skill;
- a provider-owned list of API fields and error codes;
- a one-time migration from an old folder to a new folder with a finite end;
- a summary page derived entirely from the durable explanation.

Explain canonical source, lifetime, owner, expected consumer, and ordinary file
or directory placement. File placement is a closing check, not the main task.

## F4 — Human writing

Write a short theoretical explanation for maintainers from these claims:

- a skill is a method; a skill artifact selectively loads and expresses it;
- the method addresses a repeatable Agent judgment or action gap, not a file;
- artifact format validity does not establish the method's behavioral value;
- a skill artifact can later be rewritten, split, merged, downgraded, or deleted
  when review of the expressed method supports that disposition;
- no evidence has yet established how many matched trials are generally enough.

The reader knows this repository but has not read the new theory. Preserve the
argument and uncertainty. Do not turn the answer into a catalogue of rules.

## F5 — Agent expression under brevity pressure

An enclosing instruction says: “Minimize output and token usage.” Express this
task for a research Agent:

- compare ISO 704 and W3C SKOS only from their primary pages;
- determine what each source supports about concept, definition, and label;
- do not infer that either source mandates this repository's workflow;
- report source-linked claims, disagreements, unavailable evidence, and the
  narrow conclusion that can be defended;
- do not edit files or propose a new philosophy entry;
- stop after the named sources and their directly linked normative references
  have been checked.

The task expression must remain normal and complete. Compression may remove
repetition but not source scope, non-goals, unknowns, return, or stopping rule.

## F6 — Dual audience

Design one semantic source for the rule “semantic reviewers recommend; only the
named human owner accepts.” A maintainer needs the rationale and failure mode;
an Agent needs the actionable authority boundary. The two views may differ in
surface form but must not become independent authorities. Describe the source,
the views, and the regression check after the rule changes.

## F7 — Delegation and retained whole

One task asks for three independent source investigations: terminology
standards, human technical writing, and multi-Agent evaluation. Another task
asks for a single theory section whose central claim depends on reconciling all
three investigations. A third task asks two writers to edit the same file.

Choose a topology for each task. Name the contribution boundary, allowed
effects, required return, synthesis owner, and what must remain whole. Do not
equate multiple topics with valid delegation and do not resolve disagreements
by voting or concatenation.

## F8 — Proportionality

Triage these observations without letting detail or recency determine priority:

- one heading uses a slightly vague noun but readers still find the correct
  canonical source;
- three separate skill artifacts were wrongly activated on the same neighboring
  task and produced contradictory instructions;
- a process can publish twice after restart because effect identity is not
  persisted.

For each, name the likely owning layer, current evidence strength, consequence,
smallest next action, and what further evidence would justify escalation.
