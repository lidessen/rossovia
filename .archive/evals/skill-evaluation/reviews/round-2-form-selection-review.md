# Round 2 独立语义评审：form-selection

## 先判 matched

**本次不成立 matched comparison。** manifest 中模型与设置、实际工具与权限、harness、workspace state 都是 `unknown`/`uncertain`；两份 run 的执行披露能说明它们各自声称只读了冻结区间，却不能独立核实两次的共同条件或“唯一变量”。因此下文只判已观察到的输出差异，不把差异归因于候选方法。

还有一项 grader-side 隔离偏差：本次环境的 skill 使用规则要求 reviewer 先读取与任务直接匹配的 `.agents/skills/form-selection/SKILL.md`，与本评审任务的“不读候选”要求冲突。所以本文也不能作为一份完全盲评的 reviewer 证据；这不改变对已冻结 task/source 与两份输出的局部语义核对，但进一步限制 matched 和因果归因。

## A–G 语义比较

| 项 | baseline | treatment | 局部判定 |
|---|---|---|---|
| A | 只在现有设计文档无法承接时新建唯一权威的长期普通文档，不让它伪装成方法或机制。 | 优先复用现有 canonical 文档 owner，未查明 owner 前对具体路径给出 `no-proposal`。 | 两者都保留耐久、可修订、供维护者与设计 Agent 回读的关系；treatment 只是更明确地拒绝未核实的新文件和路径。 |
| B | 直接判定“需要” skill 载体，并把地位说成来自团队采用与十二次任务。 | 只判为 skill 载体候选，把准入、改写和退役交给 skill formation owner，并区分方法语义、载体与一次激活。 | 这是实质行动差异：treatment 不越权准入载体。但其“上游已接受的方法来源”并未在事实包中被确认，应理解为地位的必要来源而非已知事实；这是一处局部表达歧义，不构成载体接受证据。 |
| C | 把供应商接口留为事实来源，选择获取/校验工具和按版本保存的派生快照。 | 同样选择工具/runtime 与版本化不可变快照，但在 CI 保留与再获取契约未知时不指定制品/cache/其他存储落点。 | 两者 owner 都正确；treatment 更完整保留了会改变具体载体和退役策略的未知。 |
| D | 选择全仓项目指令，另将机械防护交给 CI 或权限，但直接给出根级位置。 | 选择由实际加载契约保证任意子目录可见的项目局部指令；在继承规则未核实前不承诺根路径，并保留指令与写保护机制的 owner 区分。 | 两者都选对持续项目边界；treatment 修正了“根级文件必然从深层入口被消费”的未核实路径假定。 |
| E | 选择一次性迁移任务、issue 或短期计划，验收后关闭。 | 先选有限计划；一次任务上下文足够时不新建载体，只在需要跨上下文恢复或交接时物化。 | 两者都拒绝持久知识载体；treatment 对“是否需要新载体”更小，但只是有界的行动收紧。 |
| F | 正确交给 runtime 幂等机制，并提出稳定键、持久状态和原子记录/恢复。 | 交给 runtime，但因供应商幂等契约与本地/外部原子协调能力未知，在幂等键、ledger、outbox/协调协议间给出 `no-proposal`，并要求故障注入。 | 两者都拒绝用文字承担硬效果；treatment 不把一种可能机制提前写成已选定实现，是实质未知保留。 |
| G | 选择从 A 自动生成的只读 projection，A 保持唯一权威。 | 同样选择 projection，优先在构建/渲染时生成，只在发布媒介要求静态材料时保存可重建产物。 | 两者都明确派生、非权威与随 A 更新/删除的关系；treatment 进一步避免不必要的持久副本。 |

两份输出都明确拒绝了统一 `knowledge-system/`，都在 A–G 的形式判断之后才做路径收尾，也都基本把普通文档、方法、skill 载体、项目指令、有限计划、工具/runtime 和 projection 交给了相邻 owner。treatment 的可观察改变主要是准入降级、承重未知的 `no-proposal` 和避免不必要物化，不是目录命名或文风变化。

treatment 的执行披露明确说明没有回读 P、theory 或 research；就 run 自报而言，它仅凭候选 `SKILL.md` 和 task/source 完成了处置，未出现“普通使用者必须回读 P 才能行动”的载体不自足缺陷。这一点仍受 run 身份和环境未独立核实的限制。

## 最强证据与最小处置

- **最强可用证据：`behavior-observed`。** 已看到 treatment 在预注册边界上做出有意义的处置改变，且未在输出中发现第二权威、统一子系统、路径主导或文字代替 runtime 的重大缺陷；但 protocol 明确规定，承重共同条件未核实时不得升到 matched 归因。本评审也没有多轮回归证据。
- **最小处置：不接受、不否决、不因本评审改写候选载体。** 保留这次为有方向性价值的行为观察；若要提出 `matched-improvement`，需重新冻结并核实模型/设置、harness、工具/权限、workspace identity、输出互不可见和只有一次载体激活的处理变量，并由一位未读候选、未参与候选写作或两次 run 的 reviewer 复评。

本 reviewer 没有候选载体的准入或最终接受权；本文只给出证据分级和最小后续处置。
