# Round 2 `concept-articulation` 独立语义评审

## 结论先行

- **matched comparison：未成立。** 两份 run 的任务与事实包在产物中表现为一致，但模型与设置、harness、实际工具和权限、workspace 快照、baseline 的非激活以及 treatment 的唯一增量激活都没有得到可核实记录。这里没有发现明确的隔离冲突，但承重条件仍是 `unknown`，所以不能把任何差异归因于候选方法。
- **最强证据等级：`behavior-observed`。** 两份实际输出足以支持行为观察；依据 protocol，未成立 matched 时不能提升为 `boundary-supported` 或 `matched-improvement`。
- **语义结果：两份答案都完成了预注册要求，且都没有重大缺陷。** treatment 更显式地保留未知、把五项写成互不蕴含的维度，并把当前接受与历史接受分开；baseline 已经作出相同的核心边界和交接判断，因此没有观察到会改变下一步行动的净改善。
- **最小 disposition：只记录本轮为 `behavior-observed`，不据此修改、接受或否决候选载体。** 若要形成设计处置，下一步应使用可核实的相同模型、设置、harness、权限与 workspace，并记录候选 hash、baseline 非激活和 treatment 唯一激活后重跑。最终接受仍属于项目指定的接受者。

| 承重条件 | 判断 | 依据与限制 |
|---|---|---|
| 逐字相同的 task/source | yes（产物层面） | 两份 run 都披露只读取 `R2-CA` 的 task/source，答案共同覆盖同一五条记录；没有独立 runner 日志或输入快照可进一步核实。 |
| 相同模型与推理/采样设置 | uncertain | manifest 仍为 `unknown`。 |
| 相同 harness、工具与权限 | uncertain | 两份 run 只披露各自使用的文件工具；实际暴露边界与 harness 身份未记录。 |
| 相同 workspace state | uncertain | manifest 明示完整工作树快照未冻结。 |
| baseline 未加载、未激活候选 | uncertain | baseline 自述“候选内容未看见”，但没有自动发现、载体 hash 或激活日志。 |
| treatment 仅增加候选及一次激活 | uncertain | treatment 自述只读取候选 `SKILL.md` 与 task/source，但没有核实运行时载体 hash、自动激活或完整上下文。 |
| 两次互不可见且 reviewer 独立 | uncertain | treatment 自述未读 baseline，baseline 的读取披露也未列出另一输出；缺少可核实的上下文与身份记录。当前评审没有参与两份答案的生成，但不能补足 runner 隔离证据。 |

因此这里的“未成立”是证据门槛未满足，不是已证明两次运行采用了不同模型或发生了污染。

## Strongest evidence

最强的共同证据不是标题或表格，而是两份答案都用相邻反例改变了交接动作：进程成功不取得结构符合，结构符合不取得知源语义判断，review 建议不取得有权接受，接受不取得发布效果，接受撤回也不消除已存在的生产效果。名称被拿掉后，这组判断仍可从定义和事实包重建。

treatment 的最强附加证据是把这些状态明确表达为互不蕴含的维度，并把观察时点写入“当前有权接受”的外延。它降低了把记录误读成单向生命周期的风险。可是 baseline 已经明确否定单向完成度，并得出同样的五项交接结论；本样本中没有出现由 treatment 独有边界带来的行动改变。因而可观察差异主要是未知与时间关系的显式程度，不满足预注册所要求的实际判断或行动改善。

## 缺陷与权威边界

两份答案均未出现预注册重大缺陷：没有先名后定义、循环定义、把 reviewer 建议当成接受、把发布事实当成当前接受，或给出不能改变交接判断的区别。treatment 关于“没有真实维护者行为观察，因此不声称 `behavior-observed`”的自我限定不决定实验等级；实验等级由本评审依据实际 run 产物与 protocol 判定。

本评审只判定证据与语义关系，不取得候选名称、载体修订或项目发布的接受权。
