# 为什么格式合格的 skill 载体仍可能应该删除

格式检查回答的是载体能否被系统正常识别和使用：frontmatter 是否合规、目录名是否一致、链接是否有效。它不回答这个载体所表达的方法有没有改变 Agent 在目标任务上的判断。项目把 skill 看成方法，把文件包看成按任务选择加载的方法载体；因此，载体格式完全合格只是一个必要的包装条件，不能自动成为继续保留它的理由。若把“文件已经合格”当成“skill 已经有价值”，就会把载体本身误当成需要持续改善和保存的行为对象。

现有观察已经显示了这一区别。九个候选载体都通过了格式与链接检查，但其中三个所表达的方法没有改变目标判断，两个还会在相邻任务上被误激活。也就是说，机械合格与行为贡献并不相伴；对后两者而言，载体不仅尚未显示目标收益，其边界还可能把方法带入不该介入的任务。在这种情况下，继续修饰文件并不能替代对方法价值的判断。项目允许改写、拆分、合并、降为其他形式或删除，也没有“创建后必须保留”的规则；如果一个方法无法显示独立的目标贡献，或者它的贡献不足以抵消相邻任务上的错误介入，删除其载体就可能比维持一个形式完备的文件更符合项目目的。

另一项观察也说明，真正会改变判断的是方法及其边界，而不是格式本身：一个候选载体经过边界修订后，Agent 在一次激活对照中作出了此前没有作出的正确拒绝。不过，这次运行是否使用了完全相同的模型和 harness 尚未核实，所以目前只能把它视为值得继续验证的行为信号，不能据此宣称修订已经得到严格的 matched improvement，更不能由一个正例推断所有合格载体都应保留。

因此，当前证据支持的是一个有边界的保留原则：格式合格让载体具备被评估的资格，行为上的独立贡献和适当边界才构成保留理由。已有观察足以让那三个未改变目标判断的候选进入改写、合并、降级或删除的比较，而不足以直接断言它们都必须删除。现在仍不知道多少次 matched trial 才能把结论推广到其他模型和任务，也不知道这些方法是否会在尚未覆盖的任务上显示价值。最终删除前仍需用可比运行区分“方法确实无用”与“当前任务覆盖不足”；但在此之前，格式完全合格本身已经不能阻止删除成为合理选项。
