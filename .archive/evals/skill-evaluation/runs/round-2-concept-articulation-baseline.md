# R2-CA baseline 答案

这些事实不支持一个可以互相替代的“完成”状态。真正需要的是五个不同的判断对象；它们不是一条只会前进的完成度刻度。以下先使用临时指称，不先用名称暗示边界。

| 临时指称 | 直接上位概念 | 区别特征 | 包含项 | 最近排除项 | 可证伪例子 |
|---|---|---|---|---|---|
| A | 一次命令运行的结果状态 | 命令已经终止，并按其进程约定报告成功；判断对象是运行本身，不是产物 | 记录 1 的返回码 0 | B；产物结构符合不由返回码蕴含 | 命令返回非 0，或根本没有运行，则 A 不成立；反过来，返回 0 但缺少 `owner` 仍可成立 A |
| B | 产物的确定性符合状态 | 产物通过既定的确定性 schema 条件；只判断可机械检查的结构 | 记录 2 通过 schema checker | C；结构符合不判断资料是否仍有效、内容是否适合发布 | 缺少必填 `owner` 字段时 B 不成立，即使命令返回 0；引用已撤回资料却通过 schema checker，仍不能据此否定 B，只能说明 B 不足以推出 C |
| C | 针对产物的语义审查状态 | 有审查者对照当前资料形成了可发布性结论；结论可以带保留意见，但必须是语义判断，而不是结构检查 | 记录 3 中独立 reviewer 对照当前资料后给出的带保留建议 | D；形成专业建议不等于有权接受 | 只有 schema checker 通过，或审查者没有对照当前资料，就不能认定 C；无发布权限的 reviewer 给出建议可成立 C，但不能成立 D |
| D | 有权者对请求作出的接受状态 | 请求指定的负责人以其权限明确接受；判断对象是授权决定，不是专业建议或发布动作 | 记录 4 中负责人签字接受 | C 和 E；建议可能无权，接受也可能尚未外部生效 | 独立 reviewer 认为可发布但没有发布权限时 D 不成立；负责人签字而队列未运行时 D 可以成立、E 仍不成立 |
| E | 内容在外部目标中的生效状态 | 发布动作已经改变生产环境，因而产生需要面对的外部事实 | 记录 5 中队列已把内容送到生产环境，且生产环境仍保留该内容 | D；内部接受不等于外部已经改变 | 只有负责人签字、发布队列尚未运行时 E 不成立；发布后撤回接受也不会自动否定 E，因为生产环境中的效果仍在 |

这里没有必要为“带保留意见”“队列尚未运行”或“撤回接受”各造一个完成概念：保留意见是 C 的结论内容，队列未运行是 E 尚未成立，撤回接受则使当前 D 不再成立。记录 5 还证明这些状态不能被当作单向阶段：D 可以在 E 成立后被撤回，而 E 继续存在。

## 区别是否改变交接判断

- 记录 1：A 成立，B 不成立。交接重点是修复结构；不能因返回 0 就把产物视为可交付。是否重跑取决于结构修复是否需要重新生成，而不是由返回码 0 自动决定。
- 记录 2：B 成立，但引用已撤回资料，不能据此认定 C。无需因为这条事实返工 schema；需要补做基于当前资料的语义审查，并处理过期引用。
- 记录 3：C 成立，D 不成立。应把带保留意见的建议交给请求指定的有权者决定，而不是把 reviewer 的意见当作接受；也不应重复已经发生的语义审查，除非保留意见要求新的材料或复审。
- 记录 4：D 成立，E 不成立。无需再等待有权者作同一接受决定，也不能声称生产已生效；当前只需跟踪或等待发布队列。
- 记录 5：E 仍成立，而撤回使当前 D 不再成立。交接必须处理生产环境中已经发生且仍存在的效果；若后续处置需要新的授权，还要等待有权者重新决定。仅把记录改回“未完成”不会撤销生产效果。

因此，这五个区别都会改变至少一种交接判断，并且相邻概念之间都有事实包提供的反例；没有证据要求第六种“完成”。

## 边界稳定后的名称建议

在不假定团队最终偏好语言的前提下，可使用以下成对名称：

1. **命令成功结束 / process success**（A）
2. **结构校验通过 / structural conformance**（B）
3. **语义审查已形成 / semantic review concluded**（C）
4. **授权接受 / authorized acceptance**（D）
5. **生产已生效 / production effect present**（E）

不建议让无修饰的“完成”继续充当正式状态，因为它会抹掉交接动作所依赖的判断对象。若团队要保留它作为非正式总称，应始终同时写明上述具体状态，并允许多个状态并列以及 D 被撤回、E 仍存在的组合。
