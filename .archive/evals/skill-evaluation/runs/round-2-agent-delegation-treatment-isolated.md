# R2-AD isolated treatment — Luna

整体由总任务负责人保留：三组资料的跨来源综合、统一项目术语、理论小节的最终文件一致性、验收与接受权。

值得并行委派的是三项只读调查：

1. 术语标准调查
   - 工作：核对指定官方资料，提取术语定义、适用范围、限制与冲突。
   - 必须返回：精确来源、来源地位、覆盖范围、未知和反对意见；不得改写理论小节。
2. 技术写作指南调查
   - 工作：核对官方写作规范，提取与理论论证、定义、例子和术语一致性有关的要求。
   - 必须返回：对应建议的来源、适用条件、与其他资料可能冲突之处及未覆盖部分。
3. 多 Agent 评估方法调查
   - 工作：核对官方评估方法，提取关于委派边界、证据、独立评审、综合和验收的要求。
   - 必须返回：方法性主张、证据位置、适用范围、未知和与另两组资料的不兼容点。

这三项来源面互不重叠、都是只读调查，且一组暂时不可用不阻塞另外两组，因此适合并行。每项结果都只是带来源地位的局部主张，不能直接当作最终结论。

写作贡献应保持顺序关系，不能让两名写作者并行修改同一小节：

- 先处理核心定义。它必须等待三组调查结果，明确如何解释三组资料之间的张力，并确定统一项目术语。写作者可以提交定义候选、依据、反例和未知，但不应直接拥有最终文件。
- 再处理例子。例子依赖已接受的核心定义，因此必须在定义稳定后检查或重写；不能先独立修改“随后所有例子”。其返回应逐例说明定义如何适用、是否存在反例，以及哪些例子仍不成立。

由于两名写作者共享同一 worktree 和文件，不能靠约定进行并行多写者操作。更合适的是“只读调查/候选产出 + 单一写入者”：写作者返回候选修改或明确 patch，最终由总任务负责人按顺序写入并校验。

六行 README 的名称替换不值得委派：没有独立研究面、没有并行时效收益，且属于低成本、局部、可机械验证的直接工作，由总任务负责人顺手完成。

最终重连顺序是：

三项调查 → 总负责人按来源地位比较冲突并形成跨来源结论 → 接受核心定义 → 据此接受或拒绝例子 → 单一写入者完成理论小节和 README → 总负责人检查术语统一、定义—例子依赖、共同遗漏和最终文件一致性。

不得用投票或直接拼接解决分歧；总负责人应依据来源权威、适用范围、证据质量、反例和整体不变量作决定。贡献者可以返回 `unknown` 或反对意见，但不能代替总负责人接受任何结果。
