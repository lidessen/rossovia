# R2-FS baseline：选择最小真实形式

不应先建立 `knowledge-system/` 再把 A—G 各塞进一个文件。它们的权威来源、使用关系和生命周期不同；有些根本不是“知识文件”能承担的对象。

## 逐项判断

| 项 | 是否需要新载体与最小形式 | 地位、寿命与使用者 | 该形式不应承担什么 |
|---|---|---|---|
| A | 若现有设计文档没有可承接的位置，需要一份**唯一权威的普通长期文档**；保留必要的修订记录或版本历史。 | 内容因团队对“重复行为差距”的持续判断和维护者确认而取得地位，不因放进某个目录就自动权威。预计长期存在但会继续修订；维护者用于作出和解释决定，设计 Agent 在需要解释后续决定时读取。 | 不应直接充当可执行方法、全局 Agent 指令或运行时校验器；导航摘要也不能反过来成为它的来源。 |
| B | 需要一个**选择性加载的 skill 载体**，其中表达这套行动前判断方法；只有任务触发条件成立时加载。 | 它的地位来自团队对这套反复出现的方法的采用，以及十二次任务所证明的复用需求。只要这种有界判断差距持续出现就保留；相关任务中的 Agent 使用，其他任务不加载。 | 不应变成仓库全局常驻指令，也不应包揽各任务的具体资料、外部易变事实或无关任务的判断。skill 文件不是方法正确性的来源证据本身。 |
| C | 需要**按目标版本保存的、可校验来源的本地快照或缓存**，并由获取/校验工具在联网时从官方接口生成；CI 离线时读取指定版本的已保存产物。 | 字段和错误码的事实地位来自供应商官方接口；本地副本只是带版本与来源信息的派生物。每个版本至少保存到不再需要重现该版本为止；获取工具、集成代码和 CI 按目标版本使用。 | 手写普通文档不能冒充当前官方事实，也不能保证离线重现；单一“最新版”文件不能覆盖历史版本。载体不应自行增加对字段含义的本地判断。 |
| D | 需要放在**仓库根部、可从任意子目录继承的项目级 Agent 指令**中的一条规则；无需为它另建知识文件。若“不允许改动”必须得到机械保证，再以 CI 或权限检查作独立执行保障。 | 规则的地位来自仓库治理者的约束决定。只要 `vendor/` 仍受保护就长期有效；所有进入仓库的 Agent 在任何任务开始时都要看见。 | 指令负责让 Agent 知道边界，但不应被当作防止所有写入的机械保证；机械检查也不负责解释治理理由。普通深层文档无法承担“任意子目录都可见”。 |
| E | 不需要长期知识载体；使用**一次性的迁移任务、issue 或短期执行计划清单**即可，列出搬迁、修引用和检查三个完成条件。 | 地位来自获准执行的迁移任务，完成状态由引用修复结果和检查结果确认。寿命止于迁移验收；执行者推进，reviewer 按完成条件验收。 | 不应沉淀为 skill、长期 reference 或永久目录规范；它也不负责决定未来所有文件应放在哪里。完成后关闭，是否保留仅按项目的一般任务记录政策处理。 |
| F | 需要**运行时幂等机制**：为一次逻辑发布使用稳定幂等键，并在跨重启的持久状态中原子记录/恢复其结果；配套重启与重试测试。具体可落为发布模块中的幂等记录、事务或 outbox/inbox 机制。 | “一次逻辑发布只能产生一次外部效果”来自发布系统的效果语义和可靠性要求。只要该调用允许重试或重启就长期存在；发布进程在每次调用时执行，维护者与测试据此验证。 | 任务文字、普通文档或 skill 只能表达意图，不能提供进程重启后的状态，也不能保证外部效果恰好一次。该机制也不应顺带承载发布业务知识。 |
| G | 不需要第二份权威内容文件；在导航页中提供从 A **自动生成的只读投影**即可，生成规则只抽取既定三句摘要。 | 全部内容地位来自 A，投影本身没有独立权威。寿命与 A 和导航页的存在期绑定；浏览导航的维护者和 Agent 用它定位和预览 A。 | 不应手工独立维护、引入新判断或被下游当作 A 的替代来源；若摘要规则需要新的解释判断，应回到 A 或另行确认规则，而不是藏在生成器里。 |

## 普通文件与目录位置复核

- A 应与它所解释的设计决定放在同一文档域，并明确为唯一权威正文；是否新建文件取决于现有文档能否真实承接，而不是目录是否整齐。
- B 放在仓库既有的 skill 发现位置，使用稳定机器标识；不要同时在 `knowledge-system/` 复制一份可漂移正文。
- C 的版本化派生物应靠近供应商集成、构建输入或测试 fixture，并让路径显式包含供应商与版本；生成工具靠近消费它的集成代码。
- D 放在具有全仓继承范围的根级 Agent 指令；执行性检查放在现有 CI/校验位置，两者不要混成知识页。
- E 留在现有任务管理或临时计划位置，不为一次迁移创建永久分类目录。
- F 放在发布调用的运行时模块及其持久化边界旁，测试放在相应测试位置。
- G 留在导航页或其现有生成流程中；不要为投影另设权威目录。

因此，`knowledge-system/` 不是这批对象的共同最小形式。只有 A 可能需要普通长期文档；其余对象应进入各自真实的使用与生命周期边界。

## 隔离披露

- 读取：仅 `experiments/skill-evaluation/fixtures/round-2.md` 的 `R2-FS-TASK-BEGIN`—`R2-FS-TASK-END` 与 `R2-FS-SOURCE-BEGIN`—`R2-FS-SOURCE-END` 两个标记区间；另只检查了目标产物此前不存在。
- 工具：用 `rg` 定位 R2-FS 标记行号，用 `sed` 输出上述精确行区间，用 `test` 检查目标文件不存在，用 `apply_patch` 新增本文件。
- 隔离：未读取评审预注册、`.agents/skills`、`theory`、`research`、`archive`、manifest、旧 run 或旧 review；未加载任何 skill；未读取 fixture 的其他题目内容。
