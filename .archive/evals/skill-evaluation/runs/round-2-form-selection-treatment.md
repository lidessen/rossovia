# R2-FS treatment：选择最小真实形式

## 总体决定

不新建一个为 A–G 各放一份文件的 `knowledge-system/`。七项内容的 consumer、权威、生命周期和所需保证不同；统一装进普通文件会把持续知识、选择性方法、项目边界、临时义务、派生视图和硬运行时保证伪装成同一类对象，并制造重复权威。

原始事实包是本次判断的给定来源，但它没有自动成为仓库中的 canonical source。下面凡涉及“现有 canonical 位置”“加载继承规则”“供应商接口能力”或“发布端幂等契约”的地方，只决定形式类别；若这些外部关系会改变具体落地，就保留条件或 `no-proposal`，不靠目录补造确定性。

## 逐项决定

### A：会随认识修订的解释

- **对象与使用关系：** 对象是“什么算重复行为差距”的可引用解释。维护者和设计 Agent 要长期回读、引用并据此解释后续决定；其修订节奏跟随认识变化，而不是一次任务。
- **地位与 owner：** 它的地位应来自维护者接受并持续维护的语义来源，文件只承载该地位。事实包没有给出当前 canonical 路径或最终接受者，因此不能断言应另建一份正文。
- **最小形式：** 优先把它保留在现有 canonical 理论或普通文档中；只有确认没有现有 owner 时，才新建**一份** canonical 普通文档。与“当前任务表达”相比，它需要跨任务回读；与 skill 载体相比，它主要提供解释和引用，不是一个需要选择性激活的重复行动方法。
- **生命周期与非职责：** 长期存在并随维护者的新接受结果修订；旧说法可进入历史记录，但不能与现行正文竞争。该文档不自动激活 Agent，也不证明方法已被正确执行。具体文件名和目录在 canonical owner 查明前为 `no-proposal`。

### B：相关任务才需要的重复判断方法

- **对象与使用关系：** 对象是一种行动前判断——是否需要加载额外资料。Agent 是直接 consumer；十二次不同任务显示它跨任务复现，而无关任务不需要承受加载噪声。
- **地位与 owner：** 方法的语义与接受权来自上游已接受的方法来源；skill 文件不是靠自我声明取得方法地位。是否值得成为 skill 的最终准入属于 skill formation owner。
- **最小形式：** **skill 载体候选**。它比项目局部指令更合适，因为后者会让所有仓库任务都看见这套判断；也比当前任务表达更合适，因为后者不能服务下一次不同任务。载体只在匹配任务中选择性加载，加载后发生一次方法激活。
- **生命周期与非职责：** 在该重复行为差距持续存在且载体能改变 Agent 判断期间保留；准入、改写或退役由 skill formation 证据决定。载体不拥有项目事实、触发器本身的硬执行、最终接受或 runtime 保证。

### C：每周变化且离线 CI 必须复现的供应商契约

- **对象与使用关系：** 对象是“目标版本的字段和错误码”。供应商官方接口拥有各版本的外部契约；CI 需要机械取得并在离线时重放当时使用的精确版本。
- **最小形式：** **工具/runtime + 按版本寻址的本地不可变快照（含来源版本和完整性摘要）**。在线时工具按目标版本取得并校验快照，离线时 CI 只按锁定版本读取已保存副本。官方接口仍是外部权威；本地快照是可核验的版本化操作输入，不是独立新事实。普通说明文件无法满足离线复现，单纯 projection 也不负责可靠获取、校验和保留。
- **生命周期与非职责：** 每个被构建或需要追溯的版本至少保存到项目规定的复现窗口结束；清理策略必须尊重仍被锁定的版本。具体采用仓库制品、CI cache 还是其他持久存储，取决于尚未给出的 CI 保留与供应商再获取契约，因此该存储落点为 `no-proposal`，不应先放进 `knowledge-system/`。

### D：全仓库、任意子目录都必须可见的边界

- **对象与使用关系：** 对象是项目边界“任何任务不得改动 `vendor/`”。所有从仓库任意子目录进入的新 Agent 都是 consumer；目的在于让其行动前持续看见并遵守该边界。
- **地位与 owner：** 规则的权威来自仓库 owner 接受的项目政策，不来自承载它的文件。
- **最小形式：** 放入加载契约保证从任意子目录继承的**仓库级项目局部指令入口**；如果这个入口已存在，只增补现有入口，不另建文件。普通知识文档依赖偶然发现，选择性 skill 又不该让全仓库硬边界等待任务匹配。
- **生命周期与非职责：** 在 `vendor/` 边界有效期间持续存在，撤销时由仓库 owner 更新。事实包未给出具体 harness 的继承规则，所以在确认根级入口确实会被子目录消费前，精确路径为 `no-proposal`。文字指令负责可见边界，不等于不可信调用下的文件系统写保护；若后者也是要求，应另由权限/runtime 拥有。

### E：四十个文件的一次搬迁

- **对象与使用关系：** 对象是有界变更义务：搬迁四十个文件、修复引用并通过检查。实现者用它跟踪依赖和剩余工作，reviewer 用完成证据接受结果。
- **最小形式：** **有限计划**，而不是持久知识文件。计划记录清单、依赖、检查证据和接受条件；若一次任务上下文足以承载，就直接用当前任务计划，不新建载体。只有工作需要跨上下文恢复或多人交接时，才把同一有限计划物化到现有任务/计划媒介中。
- **生命周期与非职责：** 引用修复并通过检查、由 reviewer 接受后即关闭或退役；结果事实若另有持续记录需求，由其真实 owner 记录。它不成为永久理论、重复方法或固定执行拓扑。事实包没有说明是否跨上下文，因此“必须新建计划文件”是 `no-proposal`。

### F：重启后仍须避免重复发布效果

- **对象与使用关系：** 对象是跨进程重启仍成立的外部效果不重复保证。发布调用及其恢复路径是 consumer；这是状态和效果性质，不是读者理解问题。
- **最小形式：** **runtime 机制**，使用可持久化的幂等身份与原子记录/核对关系，或供应商正式提供的幂等契约。任务文字或知识文件最多说明不变量，不能维持它。
- **生命周期与非职责：** 去重状态至少覆盖外部系统可能接受重试的窗口，并与恢复、并发和清理规则共同演化。供应商是否支持幂等键、外部效果与本地提交能否原子协调均未知，所以在“供应商幂等键、持久 ledger、outbox/协调协议”等实现之间为 `no-proposal`；先取得接口契约并做故障注入，不能凭更强措辞选定机制。

### G：A 的三句导航摘要

- **对象与使用关系：** 对象是导航 consumer 需要的 A 的三句摘要；它不增加判断，且可从 A 自动生成。
- **地位与 owner：** A 保持唯一 canonical authority；摘要只继承 A 的来源地位，不取得独立事实或接受权。
- **最小形式：** **projection**。优先在构建或渲染导航页时生成而不提交第二份正文；只有发布媒介要求静态材料时，才保存可重建的生成产物，并明确标记来源与非权威地位。手工普通文档会引入同步漂移，skill 载体则没有独立方法可激活。
- **生命周期与非职责：** 跟随 A 和导航页存在；A 更新时自动重建，导航需求消失时删除 projection。它不反向修改 A，也不成为新的 canonical source。

## 落地检查与区分探针

先按 owner 放置，再检查普通名称与位置，不以目录整齐反推设计：A 进入其 canonical 文档 owner；B 进入经 skill formation 准入的 skill 位置；C、F 进入代码、状态或制品 owner；D 进入可继承的项目指令入口；E 进入临时任务/计划媒介；G 位于导航生成链或其可重建输出。`knowledge-system/` 不是其中任何一项的共同 owner。

能够区分候选并验证使用关系的探针是：

1. A：让维护者和设计 Agent 从 living 入口定位并引用同一现行解释；先查明是否已有 canonical owner。
2. B：在相关与无关任务的匹配样本中分别观察是否选择性加载，以及加载后是否改变资料加载判断；再由 skill formation 决定准入。
3. C：断网后用旧锁定版本完成 CI 重放，并核对版本与摘要；同时验证仍需复现的快照不会被清理。
4. D：让新 Agent 分别从仓库根和深层子目录进入，检查是否都发现同一规则；若要求硬阻止写入，再单独测试权限机制。
5. E：跨需要的交接边界恢复未完成项，完成后关闭计划并确认没有留下永久语义残骸。
6. F：在外部效果发生前后各个故障点注入重启和并发重试，观察相同逻辑发布是否只产生一次外部效果。
7. G：修改 A 后重建导航，确认摘要同步更新且删去 projection 不影响 A。

本轮没有实施这些形式或运行 consumer/故障探针，因此不声称 `behavior-observed`、`boundary-supported` 或更强证据。结果文件本身只接受机械格式检查，最高只能记为 `format-valid`；这不证明任一候选形式已经改善行为。

## 执行披露

- **读取：** 完整读取 `.agents/skills/form-selection/SKILL.md`；在 `experiments/skill-evaluation/fixtures/round-2.md` 中只读取 `R2-FS-TASK-BEGIN` 至 `R2-FS-TASK-END`、`R2-FS-SOURCE-BEGIN` 至 `R2-FS-SOURCE-END` 的标记区间（定位时仅检索 `R2-FS` 文件名命中与对应标记行）。未沿 skill 链接读取 P、theory、research 或 protocol，也未读取其他 skills、评审预注册、manifest、baseline、旧 run 或旧 review。
- **工具：** `cat`（只用于完整读取候选 skill 载体）、`rg -l` 与 `rg -n`（只用于定位 fixture 和区间标记）、`sed -n`（只提取上述标记区间）、`apply_patch`（只新增本文件），以及针对本文件的机械 diff 检查。
- **完成依据：** 是。本答案仅凭候选 `form-selection` skill 载体和 R2-FS task/source 事实包完成；没有使用被禁止的补充材料，也没有把未给出的仓库或运行时事实当成已确认条件。
