# 形式选择

决定一个已经确立的意义应当以什么形式存在，并怎样到达实际使用者。不要从用户顺口提出的产物名、熟悉的模板、空目录，或对文章、schema、skill 载体的偏好出发。先恢复对象、来源和真实使用关系，再选择能够如实承载它们的最小形式。

这个 skill 的主要判断是：

> 给定一个来源有界的语义对象，以及它的受众、目的、预期行动、媒介和外部契约，哪一种形式能够完整保持必要意义与权威，同时引入最少的不必要持久性、重复、机制和维护？

判断关系如下：

```text
语义对象与来源状态
  × 受众 · 目的 · 预期行动 · 媒介
  × 外部契约 · 拥有者 · 所需生命周期
    → 值得比较的候选形式与相邻 owner
      → 最小真实形式或 no-proposal
        → 若产生载体，再做普通的名称与位置检查
```

这是一项形式判断，不是写作流程。形式选定以后，内容仍须由相应的写作、方法、工具、runtime 或计划工作完成。

## 理论来源

以下 living theory 是生成本方法的语义来源：

- [`theory/expression.md`](../../../theory/expression.md) 确立表达的保真变换、四项使用关系、最小真实形式，以及文件名与目录只属于普通落地检查。
- [`theory/skill-formation.md`](../../../theory/skill-formation.md) 区分 skill 载体与一次任务表达、项目局部指令、普通文档、reference、工具和 runtime/base。
- [`theory/gene-expression.md`](../../../theory/gene-expression.md) 区分 skill 方法、skill 载体与一次激活，防止把形式本身误称为方法或行为结果。
- [`theory/harness/theory.md`](../../../theory/harness/theory.md) 提供对方法表达、有限计划、projection、机制、效果、证据和接受权的所有权检验。

[`theory/research/expression-and-form.md`](../../../theory/research/expression-and-form.md) 只保存生成期间使用的公开证据、archive 经验、反例和未知，不拥有本方法的语义。[`evals/skill-evaluation/protocol.md`](../../../evals/skill-evaluation/protocol.md) 只拥有匹配对照、边界 fixture、证据等级与收敛条件等评估契约。

主要血统是 P01、P05 与 P14：所表达的对象及其来源必须保持同一，具体使用关系会改变形式，形式应让真实意义进入预期主体的理解与行动。P06、P09、P11 与 P15 进一步约束简化、主次、成本和行为检验。这些关系改变形式判断，但条目编号清单本身不能直接推出某种载体。

P 条目只记录本方法的生成血统；living theory、research 与 protocol 分别保留语义来源、生成证据和评估契约，standing 不同。它们都不是普通 skill 激活的前置阅读。本 skill 载体已把形式判断内化在下文，普通激活只凭本文件作出取舍；只有维护者在修订、诊断或重新生成载体时才沿链接审计。当前形式判断所依赖的对象与外部契约仍须按任务读取。

## 使用边界

当语义对象已经确立，而工作缺口是要在不同载体或所有权关系之间取舍时使用本 skill。典型情形包括：

- 请求预先假定必须创建文档、skill、schema、计划、新文件或 runtime 功能，但尚未说明它怎样被使用；
- 持久知识、一次性指令、重复方法、硬保证与派生视图被混作同一类内容；
- 同一个语义对象需要面向人、Agent 或程序的不同视图，又不能形成多个权威源；
- 外部契约已经限制了载体，但剩余组织方式、拥有者和生命周期仍待决定；
- 新建载体或调整结构的维护成本，可能高于直接使用现有权威源或当前任务上下文。

不要用本 skill 确立对象是什么、概念边界在哪里或正式名称叫什么；这些问题应回到来源研究或 `concept-articulation`。不要用它为人或 Agent 组织、论证、排序和写出具体内容。识别出 skill 载体只是把它列为候选；某个重复方法是否真的值得成为 skill，以及创建、改写、拆分、合并或删除，属于 `skill-formation`。必须跨提示变化、进程重启、并发或不可信调用仍然成立的生命周期、权限、恢复、效果和证据保证，属于工具、runtime 或其他机制，不能由形式选择或更强措辞创造。

以下情况返回 `no-proposal`：语义对象或来源地位未定；受众、消费方式或预期用途存在会改变取舍的未知；候选形式之间尚无可辨别差异；必要外部契约尚未取得。应指出缺失的是哪项关系、谁拥有它，以及什么调查或使用探针可以推进。不要因为当前不确定，就先创建一个通用容器“以后再说”。

## 恢复使用关系

先确定正在表达的语义对象及其当前权威。若存在 canonical source，说明它在哪里；区分已接受的事实或决定、研究材料、候选、指令、临时义务、参考与未知。形式判断一旦暴露定义或名称不稳，就把问题交回上游，不能让文件、目录或格式替概念制造确定性。

随后把四项使用关系放在一起恢复：

1. **受众。** 谁或什么接收这份表达；已经知道什么；使用何种词汇；拥有何种权限和判断能力。
2. **目的。** 这份表达为什么现在需要存在；它应改变哪种理解、判断、记忆或能力。
3. **预期行动。** 接收者实际要阅读、学习、查询、比较、决策、执行、转交，还是让程序机械解析。
4. **媒介。** 表达怎样送达、发现、加载、更新、检查和保留；上下文、注意力与维护成本怎样发生。

目的与行动要分开。改变理解可以是完整目的而没有即时步骤；查询 reference 是一种行动，却不等于使用者的最终目的。

在比较形式之前，还要恢复会改变选择的外部关系：

- 是否存在不可改变的 schema、API、法律形态、发布渠道或项目加载规则；
- 哪个来源拥有事实或决定的权威，谁负责更新，谁拥有最终接受权；
- 形式要服务哪个 consumer，consumer 是直接阅读、选择性加载、机械解析，还是接收派生视图；
- 内容需要存在一次任务、一个项目阶段、一个版本周期，还是长期保存；完成后如何更新、派生、退役或删除；
- 需要的是文字可表达的判断，还是必须由机制维持的确定性变换、权限、状态或效果。

真实外部契约可以尽早排除候选，但不能补造不受来源支持的内容，也不能把权威转交给载体。

## 比较相邻的真实形式

只比较能够保持上述关系的候选，不必让每个任务机械走遍整张表。

| 候选形式 | 适用关系 | 它不因此拥有 |
|---|---|---|
| **不创建新载体** | 现有 canonical source 或当前行动已经足以承载使用关系；新增载体不会改善访问、证据或生命周期 | 尚不存在的解释、方法或保证 |
| **当前任务表达** | 某一次交付需要上下文和方向，且不需要独立的跨任务身份 | 持久事实、可复用方法或项目级规则 |
| **项目局部指令** | 某项边界需要在指定项目或目录中持续出现，而不是按任务选择性发现 | runtime 强制或一般理论 |
| **理论或普通文档** | 定义、论证、事实、决定、设计或来源关系需要被人或 Agent 持久回读 | 自动激活、执行或接受 |
| **reference** | 已激活的方法或文档只在特定分支需要条件性细节，而且这些细节没有独立触发与主要判断 | 独立的行为 owner |
| **skill 载体** | 一类重复的 Agent 判断或行动需要选择性加载的方法表达，而且这种表达能够改变行为 | 自身准入、项目事实、硬效果或人类接受 |
| **工具或 runtime** | 需要确定性变换、外部操作，或某项硬属性必须跨提示变化、重启、并发或不可信调用保持 | 何时以及为何使用的全部语义判断，除非另有 owner |
| **projection** | 某个 consumer 需要 canonical source 的派生视图，而且派生或同步关系可以检查 | 独立事实、状态或权威 |
| **有限计划** | 一项有界变更在完成前需要临时保存义务、依赖、证据、综合与接受条件 | 持久理论、永久方法或固定执行拓扑 |

外部契约规定的载体可能横跨这些类别。例如，同一个 schema 可以是普通契约文档、工具输入，或由权威源生成的 projection。此时应判断其权威、拥有者和生命周期，而不是按表面语法归类。

不同使用关系确实需要时，可以组合形式，但必须能重新说明各自权威。一份 canonical document 加一个 Agent-facing projection，可能比把所有内容塞进一个万能文件，或手工维护两个现行正文更小、更真实。主题或受众相同不足以要求拆分；放在同一物理文件里也不代表语义上只有一个对象或 owner。

## 选择最小真实形式

优先选择满足以下条件的单一形式或明确组合：

- 承载所有会改变预期理解、判断或行动的意义与边界；
- 保持来源状态、canonical authority、未知、效果、证据和接受关系；
- 在真实媒介与外部契约下可发现、可消费、可更新；
- 引入最少的不必要持久性、选择性加载噪声、重复权威、机制和维护；
- 更新或退役节奏与它所代表关系的生命周期一致；
- 把概念形成、具体写作、skill 准入、确定性操作、runtime 强制和最终接受交给真实 owner。

“最小”不是最短文字、最少文件、最低 token 或最低结构化程度。完整论证、长 reference、有限计划，甚至由一个语义源产生的多个声明式视图，都可能比一条含混句子或万能文档具有更小的权威与维护风险。反过来，一个对象很重要，也不能单凭重要性推出新文件、skill 或机制。

若两个候选仍然都合理，比较各自真正防止的失败和新增的成本。现有 owner 能保持同一关系时，优先复用。证据仍不足以区分时，返回 `no-proposal` 和一个能区分候选的使用探针，不要默认选择更复杂的形式。

## 只做普通的落地检查

只有选定了需要落地的载体，才按该载体的实际比例检查名称与位置：

- 名称是否指向已经定义的对象，而不是历史阶段、过宽主题或想象中的用途；
- 目录是否符合 owner、受众、权威和生命周期；
- canonical source、reference、索引、摘要与 projection 是否被清楚区分，而不是呈现为竞争权威；
- living 入口是否能发现它，并且不会把 `archive/` 当作现行设计；
- 必要的 rename 或 move 是否同步更新 living 引用，而没有复制出第二份权威源。

检查到这里就停止，除非具体且重复的失败证明存在更大的结构问题。一个显眼的路径问题、刚发现的命名缺陷，或 Agent 恰好被分配了结构评审，都不能把文件位置抬升为独立理论、独立 skill 或全项目重组的中心。

## 检验形式决定

在所承诺的使用关系上检查结果：

- 目标受众能否找到它，并据此完成指定目的和行动；
- 一次性任务是否避免了不必要的持久载体；
- 持久知识是否能够回读，又没有伪装成自动激活的方法；
- skill 载体候选是否交给 `skill-formation`，而不是被本 skill 直接准入；
- 硬保证是否交给工具或 runtime，而不是声称由措辞“强制”；
- projection 能否从声明的 canonical source 重建，并保持非权威地位；
- 有限计划完成后能否退役，不留下永久语义残骸；
- 名称与位置检查是否只纠正实际错位，没有扩张成无关重构。

需要更强证据时，依照评估协议冻结任务、来源、模型、工具、harness、权威与工作区，对比 baseline 和只加载本 skill 载体并发生一次 skill 激活的 treatment；分别测试发现与激活后的行动，并覆盖正例、反例、外部契约、最近邻 owner、混合形式和回归案例。由能看到来源的独立 reviewer 判断语义保真、边界归属、比例性和维护主张。

机械校验只能建立 `format-valid`。一次看起来合理的建议或成功的自我应用，不能证明形式选择已经改善。只采用实际成立的最强证据等级：

`format-valid` → `behavior-observed` → `boundary-supported` → `matched-improvement` → `regression-supported`

## 交付

交付一项能够让调用者重建判断的形式决定，而不是通用产物清单或写作模板。按实际需要说明：

- 语义对象、来源状态、当前 canonical source 与承重未知；
- 受众、目的、预期行动、媒介、consumer、外部契约和所需生命周期；
- 真正比较过的候选，以及接受或排除它们的实质理由；
- 选定形式或 `no-proposal`，以及它为何是最小真实形式；
- 仍在载体之外的权威、派生、更新、效果、证据、接受和退役关系；
- 仅在选择了载体时给出普通的名称与位置检查结果；
- 能区分候选的探针或已观察结果，以及实际达到的最强证据等级；
- 已交回概念形成、具体写作、skill formation、工具/runtime 或人类接受 owner 的相邻工作。

省略不可能改变决定的候选和实现细节，但保留会改变对象、权威、生命周期或使用方式的关系。不要把“选好了载体”当成内容已经正确、机制已经生效，或目标已经被最终接受。
