# 实践回返

状态：项目内 incubation candidate。本文表达一个可选择加载的方法，不取得项目事实、运行时
生命周期、权限、自动重试或最终接受权。

主要判断：

> 给定当前实践和实际结果，下一项最小实践是什么，才能改变或 settle 当前理解？

## 何时使用

使用于：

- 一次设计、调查或实现刚产生结果，结果需要改变下一判断；
- 先前尝试失败、边界含混或留下可区分的未知；
- 工作需要从当前观察恢复下一项有界 probe，而不是继续沿用原计划；
- 用户或 Principal 改变了目标、边界、对象关系或接受条件。

不使用于：

- 一次可逆、一步完成且结果不会改变后续判断的工作；
- 仅需建立工作图、依赖和发现分支的估算问题（转交 `work-estimation`）；
- 需要定义概念、选择载体、编写面向人的文本、委派拓扑或强制 runtime 保证的问题；
- 由 domain method 已经拥有的具体判断。应保留 owner，并在结果中路由过去，而不是包一层
  通用循环。

## 开始前恢复

先从真实对象和来源恢复：

```text
当前对象与目标状态：
本次实践及其实际结果：
来源地位与硬约束：
当前矛盾或阻止下一行动的未知：
最小可逆实践：
能改变当前判断的反观察：
```

过去的计划只证明当时的意图，不证明当前现实；格式通过、文件存在和 Agent 自称完成也不等于
目标被接受。

如果 Principal 改变了活动目标、硬边界、概念关系、权限或接受条件，先废止受影响的旧判断，
明确旧假设、新不变量、影响面和最小反证 probe，再继续。普通 execute、continue 或格式化
请求不需要制造 receipt。

## 方法

1. **定位实际对象。** 读取当前状态、上一结果和约束，分开观察、推断、候选与未知。
2. **命名活矛盾。** 说清什么阻止下一项有效行动；若矛盾属于其他 owner，直接 route，不创建
   总循环。
3. **选择一个最小实践。** 选择能改变当前理解、且不可逆面最小的调查、设计回返、实现切片、
   review 或外部行动；不要因为存在未来工作就先写完整计划。
4. **由真实 owner 执行并观察。** 实践可以由 Main、委派 Agent、工具、Work Cell 或人执行；
   本方法不接管执行、权限、持久效果或接受。
5. **用反观察回看。** 记录实际发生了什么、它改变了哪个判断、哪些结果仍未确认。看似成功但
   不能改变后续决策的动作不构成学习。
6. **给出处置。**
   - `settle`：接受条件已满足，说明证据和剩余风险；
   - `continue`：从新状态选择下一项最小实践；
   - `route`：交给概念、形式、设计、委派、实现或接受 owner；
   - `uncertain`：证据不足，说明缺口和回返触发器。
7. **只外化会改变后续决策的学习。** 需要交接、批准或避免重复误判时，写入现有 Plan、Task、
   Run evidence 或 planning record；不创建 round counter、万能 queue、自动 retry 或第二份
   planning authority。

## 返回

返回足以让下一 owner 恢复判断的记录：

- 实际对象、实践、来源和 baseline；
- 观察到的结果与被反例排除的替代；
- 当前 disposition（`settle` / `continue` / `route` / `uncertain`）；
- 下一项最小实践、owner、允许效果和仍然未知；
- evidence standing，明确区分 mechanical、semantic review、acceptance 与 runtime guarantee。

## 边界与行为探针

- 不把重复动作冒充学习；必须有能改变下一判断的观察。
- 不把 skill 的文字变成权限、生命周期、并发、恢复或持久效果保证。
- 不把一次成功、自评或格式验证写成 matched improvement。
- 正例：阶段 review 结果改变下一项 owner-specific probe；反例：一步格式修复不创建循环；
  最近邻：需求/设计/领域方法拥有矛盾时 route；回归：新 round 不能抹掉旧未知或把未接受
  的候选改成完成。

当前最强主张是 `behavior-observed`；达到 `matched-improvement` 前仍需冻结 baseline/treatment、
独立语义 review 和相称回归。
