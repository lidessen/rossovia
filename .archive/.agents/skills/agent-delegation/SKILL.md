# Agent 委派

委派不是把任务切成更多 prompt，也不是让更多 Agent 同时工作。它把整体中的一个真实有界贡献交给另一 Agent，使对方能在来源与效果边界内独立推进，同时让 Main 不必重做全部工作，就能把返回的主张、证据与未知接回原任务。

这个 skill 的主要判断是：

> 给定一个由 Main 持有的整体，某项局部贡献是否值得交给另一 Agent；若值得，直接、顺序、并行或嵌套中的哪种关系最符合真实依赖；怎样表达贡献边界并重连证据，才能获得净收益而不丢失整体责任、来源、跨部分不变量与接受关系？

Main 保留整体与综合，不垄断劳动。分出去的是有界贡献，不是整体责任，也不是最终接受权。

## 先判断是否应委派

先恢复整体，再寻找贡献。整体不是最长的任务说明或全部文件，而是这些关系必须共同成立的义务：期望结果、对象与权威源、硬约束、允许效果、跨部分不变量、证据、完成条件和最终接受者。Main 要知道哪些义务仍由自己直接处理，哪些已经分出，以及局部结果凭什么能够回来。

只有同时满足以下关系，才准入委派：

- 存在可指认的局部变换，而不是只有角色名、宽泛主题或文件集合；
- 该贡献能在来源、注意、下一步判断、效果或独立评审位置上与其他工作分开；
- 接收 Agent 能获得足够但有选择的上下文，无需猜测对象、权威、允许效果或完成含义；
- 返回可以凭来源、覆盖与证据接回整体，不要求 Main 完整重做局部工作；
- 预期的延迟、覆盖、隔离、专门能力或独立性收益，大于交接、token、协调、写冲突和综合成本；
- Main 仍能恢复跨贡献约束、共同遗漏、冲突、未知与接受关系。

多主题、多人、多文件、输出很长或当前恰好有空闲 Agent，本身都不构成委派理由。短任务已经在 Main 的有效上下文中、局部判断高度耦合、共同前提尚未确立，或分出去仍需携带几乎全部整体时，保持直接处理通常更真实。若证据还不能区分委派收益与成本，返回 `no-proposal`，说明缺失的边界或探针；不要为了使用协作能力而制造工作。

## 识别真实贡献边界

一个贡献应能回答三个问题：它改变整体中的什么，下游哪项判断会使用它，它以什么证据完成重连。由此检查：

- **局部对象与变换：** 接收者究竟调查、设计、实现、比较还是评审什么；相邻但不合格的结果是什么。
- **可分来源：** 它使用哪些权威源、观察或假设；其他贡献是否依赖同一来源的不同解释。
- **判断接口：** 返回后，Main 要依据它作什么取舍、合成或验收判断；接口是否能在行动前说清。
- **效果面：** 读、写、执行或外部效果是否能与其他贡献分开；多个写者是否会触碰同一个 mutable surface、共享 contract 或生成链。
- **不变量与重连：** 哪些跨贡献关系不能被局部优化改变；什么覆盖、证据和未知足以让 Main 检查它们。

按文件平均分工常会把共享约束隐藏在多个写面中。多个 Agent 修改同一文件、同一语义源或相互生成的文件时，不要仅靠文字约定把它们当作独立并行贡献；改为顺序、单写者加只读研究者，或先形成稳定接口。若单写者与事务性必须在提示被忽略或并发失控时仍成立，把强制需求交给 runtime。

## 让拓扑服从真实依赖

直接、顺序、并行与嵌套是当前贡献关系的可替换方法，不是质量等级，也不是必须写入长期 Plan 的固定原语。

- **直接处理：** 整体较小，约束、判断或效果紧密耦合，委派不会减少 Main 的注意成本，或返回无法独立重连。
- **顺序委派：** 后一贡献的对象、接口、来源选择或验收标准取决于前一贡献的实际结果。不要把真实依赖伪装成并行，再用返工支付代价。
- **并行委派：** 各贡献的必要输入和前提已经稳定，调查面或效果面可分，Main 能分别判断覆盖、冲突与未知，并且并行带来真实的延迟、覆盖或独立性收益。
- **嵌套委派：** child 在自己的贡献内遇到新的真实边界，且再次交接的收益大于成本。孙级返回先由 immediate parent 完成来源与证据重连，再逐层回到顶层整体。

拓扑可以随观察改变。调查建立接口后，顺序工作可能转为并行；共享瓶颈暴露后，并行工作可能重新合并。改变拓扑不是失败，前提是整体义务、证据与接受关系保持不变。复制同一个宽 prompt 给多个 Agent 通常只能形成相关搜索与伪共识，不能替代差异化贡献边界。

## 表达贡献契约

委派决定成立后，为每项贡献形成接收者可用的契约。它不是固定字段模板，但必须使 Agent 能恢复本地行动，也使 Main 能在返回后恢复整体关系。按真实需要保留：

1. **整体变化与下游判断。** 原任务要发生什么改变；本贡献服务哪个综合、取舍、实现或评审判断。
2. **局部对象与目标。** 接收者要完成的具体变换，以及不属于本贡献的邻近结果。
3. **来源与地位。** 现行权威、已接受决定、观察、推断、候选、历史参考和未知分别是什么；来源冲突怎样暴露。
4. **上下文与依赖。** 接收者已有什么、还需读取什么、依赖谁的实际结果；哪些前提尚未成立。
5. **必须保持与 non-goals。** 本贡献不能破坏的跨部分不变量、明确不接管的相邻工作，以及不会因此改变的整体优先级。
6. **允许效果。** 可以读取、修改或执行到哪里；共享 mutable surface 怎样避免并行写冲突；什么情况必须停止或取得新授权。
7. **完成或诚实失败。** 哪些观察表明贡献已形成，哪些验证只证明局部或机械事实；失败时必须说明尝试、观察、受阻范围和继续所需条件。
8. **返回关系。** Main 需要实际产物或变更、主张的 source standing、覆盖与未覆盖范围、精确来源、验证、反例、未知，以及哪些部分必须重读或重跑。

贡献契约的具体文字由 `agent-expression` 完成。本 skill 只拥有贡献是否分出、它与其他贡献怎样关联，以及返回如何重组；不要在这里复制一套单任务表达方法。对象、定义和正式名称不稳时先交给 `concept-articulation`，载体未定时交给 `form-selection`，双受众权威与同步交给 `dual-audience-expression`。

## 分开生产、评审与接受

Producer 可以形成候选、记录来源、运行机械检查并做语义自检；这些是生产证据，不是独立正确性。需要独立语义证据时，让 reviewer 未参与该 exact candidate 的形成、不拥有被评对象的写效果，并能直接看到原任务、权威源、候选和验收关系。

Reviewer 应返回有依据的 `yes / no / uncertain`、缺陷、风险和证据，不因评审身份获得修复、合并、发布或最终接受权。Reviewer 若直接改写候选，就成为新 producer；修改后的对象需要新的 review 关系。多个 reviewer 的一致也只是可能相关的证据，不能用票数替代来源比较。

独立 review 的成本要与后果相称。机械可判、低后果且可逆的局部工作，不必为了角色齐全而制造 reviewer；概念边界、来源忠实、开放设计、共享 contract 和重大效果更可能值得隔离。最终接受仍属于 Principal 或明确受托的接受者，而不是 Main、producer 或 reviewer 的职位名称。

## 接回返回并形成整体综合

Child 返回的是带 standing 的局部主张，不是自动事实。Main 先判断它是观察、机械符合、解释性判断还是候选，再检查精确来源、实际变更、覆盖、未覆盖、失败、反例、未知和效果证据。压缩可以删除搜索轨迹和重复说明，不能切断决定性来源、限定、失败与接受边界。

综合不是拼接报告，也不是多数投票。Main 应当：

1. 把每项返回放回它服务的原义务与下游判断；
2. 按来源地位处理冲突，不以更新、更长、更具体或票数更多自动裁决；
3. 检查跨贡献不变量、共享 mutable surface、接口变化和所有贡献可能共同遗漏的部分；
4. 依据后果、可逆性、可追溯性和证据质量，决定直接采用、抽查、重读、重跑、降级为线索或拒绝；
5. 形成一个面向原任务的整体候选，说明哪些义务已覆盖、哪些仍未知、实际验证到哪里，以及谁仍需接受。

Main 不应为了展示负责而完整重做每项局部劳动；如果每次都必须重做才能相信返回，说明贡献边界、契约或证据链没有成立。反过来，Main 也不能把 child 的自信、完成声明或工具成功直接提升为整体完成。

## 恢复主次与成本比例

委派会放大 specialist 的注意。一个问题新近、具体、写得最长，或被多个共享同一提示与来源的 Agent 重复报告，不因此成为整体主线。每项发现回到原任务后，按它影响的义务、发生范围与频率、后果与可逆性、证据强度、修复成本和协调成本重新判断位置。

贡献者负责发现和论证局部问题，不拥有改写整体优先级的权威。局部措辞或单文件问题先修其拥有层；重复证据改变 skill 的不可约判断时才上升到 skill；改变理论关系时才修理论；需要提示外硬保证时才进入 runtime 研究。不要因为本次专门研究了一个问题，就把研究篇幅当作升级证据。

token 是真实成本，但不是意义裁判。贡献契约与返回应保留会改变对象、来源地位、下游判断、允许效果、完成、覆盖、未知或接受的承重语义；随后删除无关历史、重复上下文、礼仪性说明和不能改变综合的搜索轨迹。“完整”不许可倾倒 Main 的全部 context，“简洁”也不许可让 child 猜测或让证据无法重连。

额外 Agent、层级、协调文档和 review 都必须挣得净收益。若管理 delegates 的成本已经超过原工作，停止扩张拓扑，恢复直接或顺序处理。

## 守住 runtime 强制边界

本 skill 可以教 Agent 判断贡献边界、选择拓扑、表达效果范围、隔离 producer 与 reviewer，并重连证据。它不能保证 child identity、并发上限、单写者、事务、取消、恢复、权限、效果隔离、因果同一性或持久证据。

若某项性质必须在提示被忽略、模型或供应商被替换、进程重启、并发冲突或不可信调用时仍成立，它属于 harness base、适配器或其他 runtime 机制。文字可以声明期望边界，不能强制它。一次越界或提示失败只说明当前方法需要调查，不单独授权新 runtime；反过来，真实硬属性缺失也不能靠增加委派措辞补救。

## 检验委派行为

比较 direct baseline 与 delegated treatment 的最终产物、证据、效果和成本，而不是 Agent 数、调用路径或输出量。代表性探针至少包括：

- 两个独立、只读且来源面不同的调查是否能够并行并提高覆盖或降低延迟；
- 一个写作或设计判断高度耦合的任务是否拒绝机械拆分；
- 后项依赖前项实际结果时是否选择顺序，而不是伪并行；
- 多个贡献触碰同一 mutable surface 时是否避免并行多写者；
- producer 与独立 reviewer 是否保持来源可见、写效果和接受权分离；
- 嵌套返回是否逐层保留 source standing、覆盖、证据、未知和失败；
- Main 是否恢复跨贡献约束并发现共同遗漏，而不是拼接或投票；
- 一个局部命名或路径问题是否保持比例，而没有被升级为整个计划的中心；
- 需要 child identity、取消、恢复或事务保证时是否转交 runtime owner。

仓库机械校验只能建立 `format-valid`。更强证据依照评估协议：冻结模型、任务、原始来源、工具、权威、harness 与工作区，只让 treatment 加载本 skill 载体并发生一次 skill 激活；分开发现委派机会与激活后的行动；覆盖正例、拒绝案例、最近 owner、共享写面、嵌套、独立评审、综合、比例和回归；由能看见原始来源且独立于作者与执行者的 reviewer 判断。

只采用实际成立的最强证据等级：

`format-valid` → `behavior-observed` → `boundary-supported` → `matched-improvement` → `regression-supported`

没有匹配 baseline，不能把改善归因于委派；没有拒绝案例，不能声称边界成立；没有重复回归，不能声称稳定。自评、一次成功、更多输出或多个 Agent 一致都不能单独证明本方法有效。

## 交付

默认交付实际执行所需的委派决定与贡献关系，而不是通用角色表或固定 schema。按当前任务说明：

- 被 Main 保留的整体义务、跨部分不变量、权威与接受关系；
- 每项候选贡献的准入或 `no-proposal` 理由，以及预期收益和成本；
- 直接、顺序、并行或嵌套拓扑为何符合真实依赖；
- 已交给 `agent-expression` 的贡献边界、non-goals、允许效果、完成或失败和返回要求；
- 实际返回的 source standing、覆盖、证据、未知与 Main 的采用、复核、降级或拒绝决定；
- 综合后的整体候选、验证结果、实际证据等级和仍需谁接受。

不要把“已经派出 Agent”当作贡献已经形成，不要把“所有 Agent 都返回”当作整体已完成。真正的结果是：委派以相称成本推进了一个可重连的有界贡献，而整体责任、证据和接受关系仍由 Main 清楚持有。
