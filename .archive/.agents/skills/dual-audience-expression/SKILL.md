# 双受众表达

让同一个有来源边界的语义对象，分别以人能够准确理解、Agent 能够正确判断和行动的方式出现，同时只保留一个权威回答。人的视图和 Agent 的视图不必同文、同序或同样详细；它们必须能够回到同一语义核，并在其中任何承重事实变化后共同恢复一致。

这个 skill 的主要判断是：

> 给定一个确实同时服务人和 Agent 的来源有界语义核，怎样形成适合两种接收关系的不同视图，又不让任一派生视图成为第二 canon，并使来源、权威、变化、同步、冲突和语义回归关系可以重建？

这里的“一个语义源”是语义权威关系，不是物理文件数量要求。一个文件可以错误地混有多个权威，多个文件也可以在明确的来源和派生关系下共同承载一个权威语义核。

## 理论来源

以下 living theory 是生成本方法的语义来源：

- [`theory/expression.md`](../../../theory/expression.md) 确立表达是使用关系中的保真变换，双受众可以有不同视图，但共享承重语义与唯一权威。
- [`theory/gene-expression.md`](../../../theory/gene-expression.md) 区分语义源、skill 方法、skill 载体、skill 激活与表型，防止派生表达取得上游权威。

[`theory/research/expression-and-form.md`](../../../theory/research/expression-and-form.md) 只保存生成期间使用的公开证据、archive 经验、反例与未知，不拥有本方法的语义。[`evals/skill-evaluation/protocol.md`](../../../evals/skill-evaluation/protocol.md) 只拥有行为对照、边界 fixture、语义评审、证据等级与收敛条件等评估契约。

主要血统是 P01、P05 与 P14：表达必须持续回到真实来源，同一意义会因具体接收关系而形成不同视图，而表达是否成立要看它能否使实践主体正确理解或行动。P02、P04、P06、P09、P11、P15 与 P16 分别约束证据、未知、删减、主次、维护成本、接收检验和回归时点。只有这些关系实际改变当前判断时才指出血统；条目编号本身不是设计证据。

P 条目只记录本方法的生成血统；living theory、research 与 protocol 分别保留语义来源、生成证据和评估契约，standing 不同。它们都不是普通 skill 激活的前置阅读。本 skill 载体已把双受众判断内化在下文，普通激活只凭本文件维护权威、派生与回归关系；只有维护者在修订、诊断或重新生成载体时才沿链接审计。两种视图共同依赖的实际语义源仍须按当前任务读取。

## 准入与最近邻

只有同时满足以下关系，才使用本 skill：

- 存在一个可指认、来源状态足够稳定的语义对象；
- 人和 Agent 都是实际接收者，并且两者需要恢复的理解、判断或行动不同；
- 两个视图需要被分别组织、保存、复制或生成，因而存在真实的漂移、冲突或同步问题；
- 对象定义、事实状态、硬约束、权威或接受边界中至少有一部分必须由两种视图共同保持；
- 更新关系和回归可以被观察，而不是只凭作者声称“内容一致”。

以下情况不应建立双受众结构：只有一个真实受众；第二种视图只是偶尔阅读同一现行正文；两份内容没有共同的承重语义；对象或来源仍不稳定；或者当前只是一次性转述。纯粹面向人的成品交给 `human-writing`，纯粹面向 Agent 的任务或方法表达交给 `agent-expression`。没有真正双受众关系时，直接转交最近 owner，不为将来可能需要而预建两套视图。

本 skill 也不接管相邻判断：

- 对象、定义、最近邻区别与正式指称不稳时，交给 `concept-articulation`。
- 内容是否应成为文档、projection、skill、任务表达、工具或 runtime，以及物理落点是否成立，交给 `form-selection`；本 skill 只在形式关系已足够确定后维护双视图。
- 人类视图内部怎样展开论证和形成自然文字，由 `human-writing` 负责；Agent 视图内部怎样形成可判断、可行动、可返回的内容，由 `agent-expression` 负责。
- 权限、身份、生命周期、并发、持久状态、恢复和不可绕过的效果保证属于 runtime 或其他机制。两个一致的文本也不能强制这些性质。
- 是否委派、怎样拆分贡献、谁综合以及作者与评审如何隔离，属于 `agent-delegation`；双视图结构不自动产生委派拓扑。

若缺少可识别的语义核、权威、真实双受众关系或可检验的同步关系，返回 `no-proposal`，并说明缺失关系及应由谁补足。不要用一个“通用模板”掩盖上游未知。

## 恢复共享语义核

先从来源中恢复两种视图都不能自行改写的承重关系，而不是把现有两份文字机械求交集。至少分清：

1. **对象与定义：** 两种视图说的是不是同一个对象，哪些区别决定对象身份。
2. **来源与状态：** 哪些内容是已接受事实、决定或约束，哪些是观察、推断、候选、历史参考或未知；现行权威在哪里。
3. **范围与硬约束：** 主张适用于何时、何处、何种对象；什么会改变可行判断或允许行动。
4. **权威与效果：** 谁能修改语义核，两个视图各自可以指导或产生什么，但不能据此取得什么权力。
5. **证据与接受：** 哪些观察支持主张，什么只证明格式或局部行为，谁拥有最终接受权。

这些关系构成共享语义核，不等于要创建一个新的“核心文件”。如果现有 living source 已经给出唯一权威回答，就让它继续拥有语义；双受众层只声明引用、包含、生成或同步关系。若当前没有能够承担权威的来源，先转交形式与来源工作，不能把两个派生视图中的某一个擅自提升为 canon。

任何复制都必须保留来源地位。派生视图因为更容易阅读、更靠近执行入口、更新得更晚或结构更完整，并不会成为第二权威。别名、摘要、嵌入段落、生成文件和局部副本都应能指回其语义来源，并说明何种内容是派生、何种内容是该视图独有。

## 按接收关系形成不同视图

共享语义核约束真值和权威，不要求两个视图字面相同或信息对称。分别恢复两种接收关系：

- **人类视图**通常需要问题背景、理由、证据关系、取舍、例子、争议、未知和阅读导航，使具体读者能够理解、判断或接受。
- **Agent 视图**通常需要对象与目标、来源状态、上下文、允许效果、判断条件、失败语义、返回和验收关系，使具体 Agent 能在权限内行动并交还证据。

“通常”不是固定模板。只有会改变该接收者理解、判断、行动或接受的内容才进入相应视图。历史背景可能只服务人的判断；一个已经被权威源采纳的执行边界可能只需在 Agent 入口突出。视图独有内容要有自己的来源和状态，不能因为另一视图没有同文就被误判为漂移。

形成每个视图时，调用其最近 owner 完成实际表达：人的理解推进由 `human-writing` 处理，Agent 的行动表达由 `agent-expression` 处理。本 skill 负责的是两者与共享语义核之间的映射、权威和回归，不把两个专项方法重新复制一遍。

## 建立权威、派生与追溯关系

让维护者能够回答以下问题，而不强制采用固定 schema：

- 对每项共享承重语义，唯一权威回答在哪里；
- 人类视图和 Agent 视图分别通过引用、包含、人工转写还是生成取得它；
- 哪些段落或字段是受众特有内容，谁拥有其来源；
- 哪类源变化会影响哪个视图，由什么事件触发同步；
- 谁可以修改来源、谁维护派生视图、谁评审语义一致、谁最终接受；
- 一个视图暂时落后、冲突或无法生成时，接收者如何看见这一状态。

追溯可以是链接、声明的生成规则、有边界的映射表、来源标记或与风险相称的其他办法。不要要求每句话都建立昂贵的双向映射；高风险硬约束需要明确、可检查的联系，低风险说明可以由较轻的来源引用承担。物理文件越多不必然越危险，隐含权威和无法重建的复制才会增加漂移。

## 按来源顺序变化和同步

正常变化从拥有该语义的来源开始：

1. 判断变化的是共享语义、某个视图独有内容，还是单纯措辞；不要把所有文字改动都升级成双视图事件。
2. 若共享语义要变，先在有权威的来源中完成调查、状态标记、评审或接受；派生视图不能先行改写事实，再倒逼来源追认。
3. 找出受影响的理解、判断、行动、效果与接受关系，而不只搜索相同词句。
4. 分别修订或重新生成两个视图；视图可保持不同结构，只需使受影响的语义和接收效果重新成立。
5. 运行语义回归，暴露仍未同步、来源冲突、无法重建或验证失败的部分。
6. 只有来源、两个视图和必要验证的状态都可见时，才声称本次同步完成；最终内容接受仍属于真实接受者。

若某个视图在实践中暴露上游定义或事实错误，把问题返回权威源，而不是只在该视图中修出一个更合理的真相。紧急情况下确需局部偏离，应明示偏离、原因、影响、临时状态和回归条件，不能让临时修补静默成为新 canon。

## 暴露漂移与冲突

漂移不是两个文件字面不同，而是它们对同一承重语义给出不能共同成立或不能回到权威源的回答。重点检查：对象或名称指向变化；事实、决定和未知的状态变化；范围、优先级与硬约束变化；Agent 行动或效果边界变化；证据与接受权变化；来源链接或生成关系失效。

发现冲突时，不按“最新文件”“更详细版本”“执行入口优先”或多数表述自动裁决。指出冲突的具体语义、各自主张和来源状态、影响到的理解或行动、真正的权威拥有者，以及在裁决前哪些结论或动作必须暂停。能安全继续的无争议部分仍可交付，不把一个局部冲突夸大成整个系统不可用。

同步失败必须可见。不要为了通过检查而把两个视图改成同一句话，也不要删除不确定性。尚未解决、生成失败、review 未完成或某一视图已过期，都应以接收者能够理解的方式暴露，直到恢复关系或明确退役该视图。

## 做语义回归，而不是文本对齐

回归以共享语义和接收效果为单位。对每项会改变行为的关系，检查：

- 人类视图是否让目标读者恢复正确对象、主张、理由、范围、未知和接受边界；
- Agent 视图是否让目标 Agent 恢复正确对象、来源状态、行动边界、失败处理、返回和验收关系；
- 两者是否都能回到同一权威回答，没有把派生内容升格；
- 一个源变化是否触发了所有真正受影响的视图，又没有把无关措辞差异误报为失败；
- 冲突、过期和验证失败是否向接收者显露。

文本 diff、链接检查和生成成功可以作为机械信号，但不能证明语义一致。反过来，两个视图措辞、次序和篇幅明显不同，只要承重语义与各自接收效果成立，也不构成失败。高后果关系应使用代表性理解题、行动 fixture 或独立语义 reviewer；低风险关系可以采用较轻的抽查，检验强度与漂移后果、变化频率和维护成本相称。

## 保持完整而不过度复制

压缩前先识别共享和各视图独有的承重语义。删除后若会改变对象身份、来源状态、主张强度、范围、优先级、行动与效果边界、失败处理、追溯关系或接受权，就不能只为节约 token、减少文件或追求字面对称而删除。

保住这些关系后，删除不能改变理解或行动的重复、无信息总结、过度映射和穷举式同步说明。一个视图不需要复制另一视图的全部理由或步骤来证明完整；共享语义核也不需要成为装下所有受众特有内容的巨型总文档。目标是足够且无无效负担，而不是两份一样长的“完整版”。

## 验证与交付

代表性行为探针至少包括：一个权威源生成结构不同的人类说明与 Agent 入口；共享硬约束变化后两个视图都正确更新；只服务人的背景变化不触发无关 Agent 改写；一份较新的派生视图与权威源冲突时拒绝以新旧或详略裁决；只有一个真实受众时转交最近 owner；面对必须不可绕过的权限要求转交 runtime。

仓库机械校验只能报告 `format-valid`。更强证据依照评估协议建立：冻结模型、任务、原始来源、工具、权威、harness 与工作区，只让 treatment 加载本 skill 载体并发生一次 skill 激活；分开测试发现与激活后的行为；覆盖正例、边界、最近 owner、漂移、冲突、同步和回归；由能够查看来源且独立于作者与执行者的 reviewer 判断语义保真、权威、接收效果和比例。

只采用实际成立的最强证据等级：

`format-valid` → `behavior-observed` → `boundary-supported` → `matched-improvement` → `regression-supported`

默认交付实际需要的人类视图、Agent 视图及足以维护它们的来源与同步关系，而不是一份通用字段清单。说明唯一权威源、派生方式、受众特有内容、变化触发、验证结果、可见冲突与仍需谁接受。若无法成立，交付有理由的 `no-proposal` 或准确的阻塞关系。

自评、两份文字看起来一致、一次生成成功或机械 diff 归零，都不能证明双受众表达已成立。真正的结果是：两个接收者分别得到适合自己的表达，任何共享承重语义仍只有一个权威回答，而且一次变化后这组关系可以被重建和检验。
