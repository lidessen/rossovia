# 概念形成与指称

让现实中有依据的区别成为可以共同判断的区别。不要从润色一个候选词、解释沿用名称或寻找漂亮命名开始；先恢复正在处理的对象、来源允许成立的特征和关系，以及这项区别在具体情境中要服务什么判断或行动。正式指称只能建立在这些关系之上。

这个 skill 的主要判断是：

> 给定对象证据与具体用途，怎样形成足以把目标对象同最容易导致实际误判的邻近对象区分开的概念边界，怎样定义并正式指称这个概念，以及形成的区别是否改善了预期判断或行动？

它们之间有如下生成依赖：

```text
对象证据与具体用途
  → 特征、内涵、外延与概念关系
  → 足以区分的定义
  → 正式 designation（指称）
  → 实际判断或行动中的区别检验
```

候选名称暴露遗漏的邻居、反例击穿边界或行动检验失败时，可以回到前面重做。这种往返不能倒置权威：名称可以帮助调查，不能要求对象证据迁就名称。

## 理论来源

以下 living theory 是生成本方法的语义来源：

- [`theory/concept-articulation.md`](../../../theory/concept-articulation.md) 确立对象、概念、定义与指称的关系，临时 handle、最近邻检验和行动标准。
- [`theory/expression.md`](../../../theory/expression.md) 要求表达忠于来源，在简洁与 token 压力下保留承重语义，并把写作与形式选择归还各自拥有者。

[`theory/research/concept-articulation.md`](../../../theory/research/concept-articulation.md) 只保存生成期间使用的证据、历史材料限度、反例与未知，不拥有本方法的语义。[`evals/skill-evaluation/protocol.md`](../../../evals/skill-evaluation/protocol.md) 只拥有匹配对照、边界 fixture、评审关系、证据等级与收敛条件等评估契约。

本方法主要来自 P14：正式指称只有把真实区别如实带入实践才算合适。P01、P02 使对象与概念持续对来源和证据负责；P04 让未定边界保持为未知；P05 使领域、用途、受众与粒度进入判断；P06 允许删去无助区分的内容，却不允许删掉决定性特征；P15 要求用行动检验区别。这些条目实际改变方法，并非装饰性的血统；本 skill 也不新增哲学序列条目。

P 条目只记录本方法的生成血统；living theory、research 与 protocol 分别保留语义来源、生成证据和评估契约，standing 不同。它们都不是普通 skill 激活的前置阅读。本 skill 载体已把概念判断内化在下文，普通激活只凭本文件行动；只有维护者在修订、诊断或重新生成载体时才沿链接审计。当前概念任务的对象证据仍须按任务需要读取。

## 使用边界

当一个可重复判断确实依赖概念区别时使用本 skill，例如：

- 同一个工作名称指向了不同对象、关系、状态或权威；
- 定义循环、绑定当前实现、外延过宽，或无法排除最近非实例；
- 相邻概念反复造成路由、所有权、接受或行动错误；
- 研究、跨环境恢复或反复协作需要共享且稳定的术语；
- 现有名称似乎正在把证据牵向预设类别或结论。

不要因为一句话还能更清楚、一个名字还能更好听，便启动完整的概念形成。相邻工作的所有权应明确转交：

- 已形成意义怎样向具体读者解释、论证、排序和形成自然语气，属于 `human-writing`；本 skill 不接管文风。
- 意义应成为文章、表格、schema、skill 载体、reference、文件还是目录，以及普通的文件名与目录落点检查，属于 `form-selection`；本 skill 不选择形式载体。
- 概念稳定以后，名称是否易记、优雅、符合品牌或编辑偏好，属于相应产品、品牌或编辑判断；审美不能反证概念成立。
- 一项重复方法是否值得成为选择性加载的 skill 载体，以及该载体应保留、改写、拆分、合并、降级还是删除，属于 `skill-formation`。
- 把已有语义写成对象、目标、上下文、允许效果、返回和完成条件等 Agent 任务契约，属于 `agent-expression`；本 skill 不编写这类契约。生命周期、权限、身份、并发、恢复和接受保证则属于 harness 或 runtime，换一个名称不能创设这些性质。

以下情形应返回 `no-proposal`，不要为了显得完整而制造术语或结构：对象尚不能指认；来源不足以支持边界；区别不会重复出现或不会改变判断；领域、用途或预期行动缺失；已有概念已经拥有这项区别。一次性的歧义句通常只需直接澄清，不需要建立 canon。

## 从对象与用途开始

先记录观察和来源，而不是先接受请求中的名称。至少恢复到另一位 Agent 能重建同一问题的程度：

1. **对象证据与来源状态。** 正在指向哪些材料、行为、关系、状态或变化；哪些是已接受事实、观察、推断、候选、历史参考、他人观点或未知；来源的权威、范围与冲突在哪里。
2. **具体区别用途。** 谁需要在什么领域、以什么粒度分清什么；这项区别要改变何种理解、判断、路由、责任或行动。
3. **同一性威胁。** 什么观察会表明原先把两个对象错误合并，或把同一个对象错误拆分。
4. **现有 handle。** 当前名称在哪里使用，携带了哪些可能未经证实的假设。使用事实只是用法证据，不是概念同一性的证据。

始终区分对象、概念、定义、指称、例子与载体：

- **对象**是现实或思想中这次正在考察的东西。
- **概念**是由相关特征与概念关系形成、使对象能够被认识和区分的知识单元。
- **内涵**是构成概念的特征集合；**外延**是在当前领域中归入该概念的全部对象。
- **定义**表达足以把该概念同相关概念区分开的内涵。
- **designation（指称）**是在特定领域用 term、proper name 或符号指向概念。
- **例子**展示一个实例或边界，不能代替整个外延或定义。
- 文件、schema、界面标签或 `SKILL.md` 只是载体；当前承载或实现一个概念，不会使载体等同于概念。

这些区别若还没有证据支持，应指出需要补做的调查与它阻止了哪项判断。不要用自信、流畅的说明把缺口写成既定事实。

## 恢复足以区分的关系边界

只建立能够暴露当前实际混淆的最小关系视图，不必顺势建设全局 ontology。检查：

- **直接上位概念：** 在当前划分标准下，它首先是哪一类东西？
- **并列概念：** 哪些概念与它共享上位概念，哪项特征决定彼此归属？
- **实例或下位概念：** 哪些明确实例和边界实例落入外延，为什么？
- **整体—部分关系：** 候选对象是整体、组成部分还是两者都不是？不能把 `part-of` 写成 `is-a`。
- **关联关系：** 哪些概念只是在因果、时间、操作或协作上相连，而不属于同一类别？

最近邻应按实际误判风险选择，而不是按字面相似度选择。随后用四种探针照验边界：

- **包含：** 至少给出一个典型实例；材料允许时再给一个边界实例，并指出使它们进入外延的特征。
- **排除：** 给出最近的非实例，指出它缺少或冲突的是哪项区分特征。
- **最近对照：** 说明双方共享什么上位概念或关系，以及哪项差异真正决定判断。
- **反例：** 指出什么观察会迫使当前概念拆分、合并、收窄、扩展或彻底重建。

当这些信息决定边界时，它们是承重语义，不能只为节省 token 压成一句话；与区别无关的历史、实现细节和重复例子也不应无限保留。

## 先定义，再选择正式指称

候选定义首先要足以区分，之后才谈最小。实际关系适合时，可以从下面的结构开始：

```text
概念 = 直接上位概念 + 区分特征
```

若真实概念关系需要其他定义形式，就服从该关系。不要把开放集合伪装成穷尽枚举，也不要把整体—部分关系写成普通类属关系。逐项检验候选定义：

- 与最近排除项相比，外延是否过宽；
- 与合法边界实例相比，外延是否过窄；
- 是否循环定义，或只是用同根词替换原名称；
- 是否意外依赖当前实现、文件或其他载体；
- 是否暗中加入了来源没有支持的因果、价值、所有权、权威或永久性；
- 是否因追求简短或 token 经济而删掉决定性特征。

定义是有来源边界的候选主张，不是对现实的终局裁决。保留会改变定义的未知、证据冲突和修订条件。

只有概念边界与定义已足以服务具体用途，才选择或确认正式 designation。指称种类与词汇应匹配领域和受众：term 指向一般概念，proper name 指向个别概念，代码标识符或文件名则是载体层的指称。正式名称应在当前讨论范围内稳定指向，不吞掉最近邻区别，也不必把整份定义塞进词形。新奇、优雅、简短、利益相关方喜欢或命名检查通过，都不能在缺少区别检验时证明它正确。

## 如实使用临时 handle

调查和协作无法等待概念稳定时，可以使用临时 handle，但要同时守住以下边界：

- 明示其 `temporary`、`provisional` 或 `working` 状态，不把它冒充 accepted、preferred term 或已接受定义；
- 写明局部作用域，并使它能回到对象证据、尚未解决的邻近概念和未知；
- 不让措辞偷带类别、因果、价值、所有权、角色或权威主张；
- 一旦它开始错误牵引证据或行动，就替换它；
- 只有边界、定义、目标受众和区别用途稳定且经过行动检验，才将它提升为正式指称；
- 旧 handle 确有检索价值时，只作为别名保留，不能形成第二语义权威。

临时 handle 是可抛弃的索引，不是较弱的 canon。证据只支持临时指称时，就如实返回该状态，不强行给出正式名称。

## 在判断和行动中检验区别

检验应发生在混淆真正造成影响的地方。向预期主体提供代表性的包含项、排除项与最近邻案例，观察定义和指称能否使其选对对象、拥有者、来源、状态或下一步。按实际需要加入这些检验：

- 移除名称但保留对象证据和关系后，概念仍应能够被重建；这证明 concept 不等于 designation。
- 只给名称而不给证据与关系时，应明确无法恢复边界，不应补造确定性。
- 保持概念关系不变而更换名称时，预期判断或行动不应实质改变。
- 遇到反例时，应回修边界，而不是用修辞保卫原定义。
- 局部区别不得在没有相称证据时膨胀成全局 taxonomy、glossary、理论变更或运行机制。

仓库机械校验只能报告 `format-valid`。更强主张依照评估协议建立：冻结模型、任务、来源、工具、harness 与环境，只让对照组在是否加载本 skill 载体并发生一次 skill 激活上不同；分开测试发现与激活后的行动；覆盖正例、反例、最近 owner、上下文和回归；让作者、执行者、能够查看来源的独立 reviewer 与人类接受者保持分离。

只采用实际成立的最强证据级别：

`format-valid` → `behavior-observed` → `boundary-supported` → `matched-improvement` → `regression-supported`

一个成功例子、自评结论或受欢迎的名称都不能证明概念或本 skill 已经成立。最终接受仍属于人或明确受托的接受者。

## 交付

默认交付一份能够被后续工作直接使用的完整概念记录，而不是一张只有候选词的清单。结构可以随任务调整，但应保留所有会改变重建、判断、行动或接受的关系：

- 对象证据、来源状态、领域、预期主体，以及要改变的判断或行动；
- 必要时使用的临时 handle、作用域和未解决状态；
- 相关特征、内涵、外延和最小关系视图；
- 包含、排除、最近对照与反例；
- 候选定义、关键未知和修订条件；
- 只在提升条件成立时给出的正式指称及其种类；
- 行动探针与已观察结果，或仍需完成的准确验证；
- 被排除的相邻概念，或有理由的 `no-proposal`；
- 权威边界、当前最强证据级别，以及仍需谁来接受。

不要因为上层提示偏好短输出，就删掉来源状态、决定性差异、未知或验证；也不要把“正常完整表达”理解成无限展开。只保留会改变对象恢复、概念区别、预期判断、行动或接受的内容，删去装饰性重复。
