# P15 reading candidate：实践是检验真理的唯一标准

状态：`reading-candidate / source-current / independent-review-complete / research-open / acceptance-pending`；不是万能测试门、机械
验证器、runtime gate、自动接受规则或实现授权。

本文件只解释现行源中的 P15。它处理解决阶段的检验手段：一个关于对象、关系或方法的主张，不能只凭
来源、解释、文件存在或执行意图获得更强 standing；应在相称的具体实践中让主张面对对象，观察结果，并
据此保留、修订或降低主张。实践结果仍有范围、归因和未知，不能越过独立评审或接受关系。

## 源与对象

唯一源是 [`theory/philosophy.md` P15](../philosophy.md#L35)：

> P15｜实践是检验真理的唯一标准｜解决·检验·手段

当前 living 序列只给出 P15 在问题处理领域中的坐标。它不把“实践”解释成任何外部动作，也不把“真理”
解释成一次运行的成功；本 reading 只形成“主张—相称实践—可观察结果—主张 standing”之间的关系。主张
的范围、对象和接受条件不清时，先回到对象、概念或证据 owner，不能用实践名义跳过问题化。

## 最小定义与边界

在当前问题处理领域，P15 的暂定定义是：

> 对一个已经指认对象、范围和主张的候选判断，选择能够在具体条件下使主张面对对象并产生可观察结果的
> 相称实践；按结果、范围、归因和反例更新主张的 standing。实践是检验主张的必要落点，但一次执行、
> 文件存在、格式通过、自评成功或接受决定都不能互相冒充。

P15 的对象是主张与具体实践检验之间的关系，主要判断是“当前主张需要什么实践，实践结果改变它的
   standing 到何种程度”。它不拥有主张的最终事实权、独立语义评审、Principal acceptance、runtime
   lifecycle、权限或效果；这些关系仍由相应 owner 持有。

### 最近邻

- **P04「知之为知之，不知为不知」**处理当前对象、关系或结论得到多少来源和证据支持；P15 处理是否有
  相称实践把主张带回对象。文档中明确写出一个主张，不等于已经完成实践检验。
- **P08「井蛙不可语海，夏虫不可语冰」**处理问题边界、视域和适用范围；P15 要求把实践检验放入具体
  条件、对象和允许效果中。范围外的结果不能直接被 P15 或 P08 偷换成全局结论。
- **P16「慎终如始，则无败事」**处理检验覆盖哪些时点；P15 处理检验手段是否真正接触对象并产生结果。
  有实践不代表开始、执行中、结束或采用后的所有时点都已覆盖。
- **P03「实践—认识—再实践」**处理实践、认识和下一实践的往复关系；P15 处理一个主张如何在相称实践中
  接受检验。P03 能说明结果怎样回到下一认识，不能代替 P15 的具体检验条件。

### 包含、排除与成对案例

- **包含：** 对一个候选方法的“它会改变下一项实践”主张，固定任务、来源、环境和输出关系，比较不加载
  与加载方法的行动，并记录 action、route、unknown 和 review。若运行身份或激活不可核验，结果只能保留
  `behavior-observed / attribution-uncertain`，不能写成 matched 或 accepted。
- **包含：** 对一个 WorkCell Binding 不可变的设计主张，若有可重建的 host fixture 在指定条件下尝试
  改变 Binding 并记录结果，该实践可以检验 fixture 范围内的主张；范围外、归因和接受仍需单独记录。
- **排除：** `SKILL.md` 能加载、validator 通过、文件存在或协议字段齐全，只证明载体或机械契约的局部
  事实；不能因此证明 Agent 行为、协议语义或主张为真。
- **排除：** 一次 executor 成功、provider report、Agent 自评或 reviewer 推荐不能自动取得接受、长期稳定、
  host effect 或 runtime guarantee。
- **排除：** 为了“有实践”而创建 synthetic Run、无 consumer 的 fixture、固定测试数量或全局验证门；实践
  必须服务一个已指认的主张和能改变判断的反观察。

### 当前主线案例的证据上限

`planning/records/method-skill-probe-round-3.md` 已在真实 planning/design case 上观察到：baseline 与 treatment
在 Case B 的下一行动和 disposition 上出现差异，因而支持局部 `behavior-observed`。但 runner identity、
model、harness、workspace、权限、candidate activation 和 output schema 未完全核验，独立 review 也指出
归因仍为 `unknown`。这说明实践结果可以改变“继续、route 或重开”的 planning 判断，同时也说明 P15 不允许
把一次差异升级成 candidate acceptance、matched improvement 或长期 regression。

## 生成性候选

当 P15 与 `practice-cycle`、`work-estimation`、evidence maintenance 或 WorkCell design review 相遇时，
可以长出“先命名主张，再选择最小相称实践，观察反事实或反观察，按范围和归因更新 standing，并把未决接受
交回 owner”的方法。它可以支持 planning probe、fixture 选择和 evidence standing maintenance；但不成为
全局 test plan、自动质量门、验证器、重试器、接受器或 runtime policy。

该方法与 `practice-cycle` 仍有边界：P15 解释为什么主张必须落到实践检验；`practice-cycle` 解释给定一次
实践结果后如何选择下一项最小实践或 route。前者不是后者的总循环，后者也不取得“真理”或接受权。

## 当前未知与 review 出口

- 不同主张、风险和效果边界所需的“相称实践”仍需具体 domain/use 复核；本 reading 不能规定统一 Run、
  fixture、测试数量或 acceptance rubric。
- 当前 method probe 的结果是 planning-level behavior observation，尚不能证明 P15 reading 本身已经
  改变 Agent 行为；没有 P15 专属 matched comparison、regression 或 reading acceptance。
- WorkCell B1–B4 仍是 design/边界 fixture；除非出现真实、可重建的 host practice，否则不能把它们写成
  P15 behavior evidence 或 protocol acceptance。
- 若“实践”在真实案例中不能改变主张 standing、下一行动或 owner route，或与 P04/P08/P16 无法区分，应
  回修 candidate 或返回 `no-proposal`，不创建统一检验机制。

后续 review 应检查：源行未变；P15 没有退化成“执行过就是真的”、测试数量规则或接受门；P04/P08/P16/P03
最近邻能改变实际判断；现有 method probe 的 `behavior-observed / attribution-uncertain` 上限没有被
夸大；实践结果、语义 review、接受和采用后回归仍然分开。
