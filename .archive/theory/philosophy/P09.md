# P09 reading candidate：抓住主要矛盾

状态：`reading-candidate / source-current / independent-review-complete / acceptance-pending / research-open`；
不是全局 priority queue、任务排序器、owner 路由器、资源分配规则或 runtime scheduler。

本文件只解释现行源中的 P09。它处理解决阶段的主次判断：在同一对象、目标和约束下，多个冲突
同时存在时，识别哪一个冲突的变化会改变其他冲突的状态或当前目标的可行性，再把注意力集中到
这个承重关系上。它不把“主要”理解成声量最大、最紧急、最容易做或对所有对象都优先。

## 源与对象

唯一源是 [`theory/philosophy.md` P09](../philosophy.md#L23)：

> P09｜抓住主要矛盾｜解决·主次

本 reading 不把源行扩成普遍排序或调度规则。当前 living 序列只给出它在问题处理领域中的
坐标：在已经界定对象、范围和冲突后，判断哪个关系对当前解决路径具有支配性，并保留其他冲突
的存在与回返条件。

## 最小定义与边界

在当前问题处理领域，P09 的暂定定义是：

> 在同一对象、目标、范围和约束内，比较并存冲突对当前解决可行性和其他冲突状态的依赖关系；
> 优先处理会改变其他冲突、关键约束或下一项解决判断的那个承重冲突，同时保留非主要冲突的
> 证据、owner、风险和回返条件。主要性是局部、条件性的判断，不是永久排序。

P09 的对象是解决阶段的冲突关系与承重性，主要判断是“哪个冲突的变化会使其他冲突或当前解决
   路径发生改变”。它不发放 priority、不替 owner 决定 route、不分配资源、不授权 effect，也不
   取得 runtime scheduler 或 acceptance authority。

### 最近邻

- **P05「具体问题具体分析」**判断哪些特殊条件会改变分析；P09 在问题和条件已界定后判断并存
  冲突的主次，不能用“主要”跳过具体条件。
- **P07「天下难事，必作于易」**选择可行入口；入口可以不是主要矛盾，主要矛盾也未必最容易先做。
- **P08「井蛙不可语海，夏虫不可语冰」**界定问题/观察的适用范围；P09 只能在同一 scope 内判断
  主次，不能把范围外事实纳入排序或把 scope boundary 写成次要问题。
- **P10「为之于未有，治之于未乱」**判断何时介入；P09 判断解决路径中的承重冲突，不能由主次
  推出固定提前量或紧急度。
- **P11「治大国若烹小鲜」**判断解决动作的扰动/协调成本；P09 可以指出哪项冲突值得先处理，
  但不取得如何执行或付出多少成本的 authority。

## 包含、排除与成对案例

- **包含：** 在同一 WorkCell design object 中，同时存在“协议是否需要 replay contract”和“如何
  限定 provider/session lineage”两个冲突；只有在证据显示前者会改变后者的 consumer、owner 或
  contract 形状时，才可把前者暂定为当前主要冲突，并保留后者的 unknown 与回返条件。
- **包含：** 若一个安全/acceptance 约束会使多个设计选择全部失效，它可能是当前解决路径的承重
  冲突；判断仍限于该 object 和证据，不自动取得全局 priority。
- **排除：** 把最紧急、最昂贵、最容易或最吵的问题自动叫“主要”；这些特征需要与对象、目标、
  约束和依赖关系结合，否则只是印象。
- **排除：** 把 P09 写成队列顺序、owner route、资源分配、deadline 或 scheduler policy；这些
  是下游 planning、owner 或 runtime 的不同关系。
- **排除：** 为了突出主要冲突删除其他冲突的 source、unknown、风险、owner 或回返条件；主次判断
  必须保留非主要项可被重新纳入的条件。

### 成对案例

1. **承重冲突：** 当前 object 的 consumer 不明导致 replay contract 形状无法判断，而 provider
   session 的实现细节暂不改变这项设计判断；在 bounded review 中可把 consumer/contract relation
   作为暂定主要冲突，但不把它写成 WorkCell 已接受的 priority。
2. **非主要不等于无关：** provider session 的 lineage risk 当前不改变 contract shape，但仍保留
   为 unknown、owner route 和 revisit condition；若新证据显示它改变 acceptance 或安全约束，主次
   可以重排。
3. **假主要：** 一个文档字段最容易改或某个请求声音最大，但它不改变其他冲突、硬约束或解决路径；
   它不能仅凭易做或显眼成为 P09 的主要矛盾。

## 生成性候选

当 P09 与 planning、agent-delegation 或 WorkCell design 相遇时，可以长出“在明确 scope 内按
承重关系集中解决，并保留其他冲突回返”的方法。它可支持 `agent-delegation` 的贡献边界、
`practice-cycle` 的下一项判断或设计 review 的局部 conflict analysis；但它不成为全局优先级器、
任务队列、资源调度器、接受门或 runtime scheduler。
