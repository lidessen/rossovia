# P11 reading candidate：治大国若烹小鲜

状态：`reading-candidate / source-current / independent-review-complete / acceptance-pending / research-open`；
不是哲学源行、预算策略、token 优化器、成本阈值、runtime 性能保证或实现授权。

本文件只解释现行源中的 P11。它处理解决阶段的扰动代价：当方案、效果、owner 和约束已经足够明确
时，比较执行路径会带来多少不必要的翻动、协调、重复调用或风险暴露，并保留那些虽有代价但为安全、
证据或必要组合所承重的动作。它不把“少动”变成永恒仪式，也不以成本名义删除分析中的未知或硬约束。

## 最小定义与边界

在当前问题处理领域，P11 的暂定定义是：

> 在外部已经给出相称对象、已接受或待比较的解决方案、允许效果、硬约束、owner 和接受边界时，
> 比较不同执行路径的必要动作、扰动、协调和风险代价，减少不改变当前解决目标的反复翻动，同时
> 保留为安全、证据、可逆性或必要组合所承重的动作。

P11 的对象是解决阶段执行路径的扰动/代价，主要判断是“怎样完成已经形成的解决动作，才能避免不必要
的翻动与协调，而不损失必要效果或约束”。P11 只支持相称比较，不拥有方案 admission、预算批准、
owner 路由、runtime 性能保证或自动执行权；它也不替 P06 删除分析复杂性、不替 P10 选择介入窗口。

### 最近邻

- **P06「为学日益，为道日损」**处理分析阶段哪些复杂性可删而不改变当前判断；P11 处理解决阶段
  已决定或正在比较的执行路径如何减少扰动。不能因执行成本高就删掉承重的 source、unknown、
  contract 或安全约束。
- **P10「为之于未有，治之于未乱」**处理何时介入状态窗口；P11 处理介入动作本身如何少做不必要
  的翻动。早介入不保证低成本，低成本也不证明时机正确。
- **P09「抓住主要矛盾」**处理哪个冲突承重；P11 在主要冲突和允许效果已被外部 owner/设计确定后
  比较执行代价，不能把代价最小的路径自动写成主要矛盾。
- **P04「知之为知之，不知为不知」**要求成本、覆盖、未知和风险证据如实标记；未知的成本不能用
  “少动”措辞伪装成低风险。
- **P15「实践是检验真理的唯一标准」**处理通过相称实践检验结果；P11 的较低扰动只是执行预测或
  tradeoff，不是结果接受或真理判断。

## 包含、排除与成对案例

- **包含：** 假设一个未来 owner-backed replay/lineage contract 已被接受，两个执行路径都能达到
  同一允许效果；比较一次性重建与重复 host call 的 workspace 翻动、协调次数、失败暴露和回退
  成本，并将安全或证据所需的额外动作保留为承重关系。结果交给相应 owner/acceptance 判断。
- **包含：** 在当前 WorkCell design review 中，记录 event 的 typed observation、consumer/owner
  unknown、sequence/gap/restart contract 未定，并据此暂不把 event bus、replay store 或 session
  resume 塞进 core。这是 P06 对同一候选机制关系的分析删减；只有未来 owner-backed contract/effect
  成立后，才可用 P11 比较执行扰动。F1→F2 不是同一 runtime object 的状态迁移，当前 fixture 不构成
  P11 behavior evidence。
- **排除：** 仅凭“动作少”就删掉 source、unknown、硬约束、取消/恢复边界或证据记录；这些关系
  若承重，不能由 P11 删除。
- **排除：** 为 P11 创建统一 token/time/money threshold、固定调用次数、全局成本函数、retry 上限
  或 runtime optimization policy；代价必须随对象、效果、风险和接受关系确定。
- **排除：** 用一次 build 成功、较短文档、较少 Agent 或较低表面操作数冒充实际扰动/结果改善；
  没有可观察 consumer、执行环境和后果时，应保持 unknown 或 `no-proposal`。

### 成对案例

1. **条件性低扰动路径：** 假设同一候选机制关系下的已接受 replay contract 有两个均可行的 host 路径，其中一条
   重复翻动外部 workspace 且失败后难以回退，另一条在保持证据和安全约束的前提下只执行一次有界
   变更；比较结果改变执行路径选择。这是 P11 的扰动判断，不是自动优化保证。
2. **假成本结论：** 只有一个尚未命名 consumer/owner 的设计字段，却因为它“暂时少做”就声称成本
   已降低；对象、效果、风险和接受边界都未知，不能形成 P11 结论。
3. **阶段错位：** 为减少未来 host call 而删除当前尚未确认是否承重的 replay/lineage contract；
   这把解决阶段的成本判断倒灌成分析阶段的 P06 删除，且可能损失证据和回退关系。

## 生成性候选

当 P11 与 WorkCell、harness 或迭代实践相遇时，可以长出“在解决动作和允许效果已经形成后，比较
必要动作与不必要扰动，并把安全、证据和回退的代价显式保留”的方法。它可支持必要组合判断、执行
路径 review 和 adoption-window 的 balancing cost 观察，但不成为全局预算器、成本函数、重试器或
runtime 优化机制。
