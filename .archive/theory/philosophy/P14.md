# P14 reading candidate：名不正则言不顺

状态：`reading-candidate / source-current / independent-review-complete / acceptance-pending / research-open`；
不是 glossary、命名委员会、名称即权威、接口权限机制或固定命名流程。

本文件只解释现行源中的 P14。它处理解决阶段的表达：正式名称必须稳定指向已经界定的对象、角色或关系，
并使目标主体能据此作出正确区别；名称不正时，后续描述、责任和行动会错位。名称本身不创造对象、事实、
权限或生命周期。

## 源与对象

唯一源是 [`theory/philosophy.md` P14](../philosophy.md#L33)：

> P14｜名不正则言不顺｜解决·表达

本 reading 不把源行扩成“名字不好看就不能工作”，也不让词语反向支配对象。当前 living 序列只给出它在
问题处理领域中的坐标：当对象、角色、关系和边界已经足以形成区别后，选择能让目标受众稳定指向和行动的
正式 designation，并在误判时回到概念/对象证据。

## 最小定义与边界

在当前问题处理领域，P14 的暂定定义是：

> 对已经形成足够区别的对象、角色或关系，选择在指定领域和受众内能稳定指向、避免最近邻误判并支持
> 正确行动的正式名称；若名称与对象、生命周期或关系错位，表达和行动会错位，应回到定义、证据或作用域
> 重新修订。名称只是 designation，不取得对象事实、owner、权限、接受或 runtime authority。

P14 的对象是名称、所指对象/关系和行动之间的表达对齐，主要判断是“这个名称能否让目标主体正确区分并
   采取对应行动”。它不创建全局 glossary、不替概念 articulation 形成对象、不授予权限，也不因为名称稳定
   就证明协议或事实已被接受。

### 最近邻

- **P01「实事求是」**约束名称不能脱离对象事实；P14 处理在已有对象/关系边界上如何指称，不能用名称
  替代调查或证据。
- **P04「知之为知之，不知为不知」**要求未知保持未知；P14 不能用一个正式词掩盖未定边界或把候选
  关系写成 known。
- **P08「井蛙不可语海，夏虫不可语冰」**界定名称和结论的作用域；P14 的正式 designation 仍需说明
  领域/受众，不能把局部名称外推为全局名称。
- **P06「为学日益，为道日损」**要求删掉不改变当前判断的复杂性；P14 可以压缩表达，但不能删除
  会导致最近邻误判的区分特征。
- **P15「实践是检验真理的唯一标准」**可在后续真实使用中检验名称是否支持正确区分；P15 只提供
  实践检验关系，不授予 acceptance 权，命名是否接受仍由指定 acceptance owner 决定。

## 包含、排除与成对案例

- **包含：** WorkCell 设计中，若一个名称同时让人把 request、run、record 或 evidence 当成同一
  生命周期对象，就应回到对象/关系边界，选择能区分阶段和责任的 designation；这只是命名 candidate，
  不等于协议已接受。
- **包含：** 一个临时 handle 可以在调查中帮助指向尚未稳定的对象，但必须标明 provisional、scope 和
  unknown；等概念关系稳定后，才考虑正式 designation。
- **排除：** 因为一个词在文件、SDK 或供应商中常见，就让它自动成为当前 canonical term；频率不证明
  所指对象相同，也不证明生命周期、owner 或 authority 相同。
- **排除：** 把名称从 `cellInput` 改成更顺口的词就当作协议简化；如果对象边界、输入/请求关系、生命周期
  和受众没有变，改名本身不解决语义问题；如果它们确实变了，需要先修概念/协议关系再选名称。
- **排除：** 名称含有 `run`、`record`、`binding` 或 `input` 等词，不代表对应 runtime、持久化、绑定或
  权限机制已经存在；designation 不能创设机制。

### 成对案例

1. **名称与对象对齐：** 在当前 design candidate 中，若某个对象只表示“向一次运行提交的事实请求”，
   名称应能与 WorkCell 的 spec、binding、run 和 record 区分；这支持表达和 review，不改变任何协议 standing。
2. **名称与对象错位：** 若一个临时 handle 被写成 canonical input，而它实际混合了 request、context、
   provider session 和 effect authority，目标受众可能误判责任和生命周期；正确回返是重做对象/关系区分，
   不是先加 alias 或实现兼容层。
3. **名称不创权：** 把某个候选对象命名为 `acceptedRecord` 不会使它获得 acceptance；把它命名为
   `ownerBinding` 也不证明 owner 已经确认。名称必须服从证据和接受关系。

## 生成性候选

当 P14 与 WorkCell、concept-articulation、agent-expression 或 dual-audience-expression 相遇时，可以
   长出“对象/关系先形成、designation 后对齐、行动失败可回修”的命名方法。它可支持协议命名 review、
   人类/Agent 双受众的同一语义投影和 provisional handle 管理；但它不成为全局 glossary、命名委员会、
   权限系统、acceptance gate、runtime registry 或自动 rename 工具。
