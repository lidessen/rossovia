# P16 reading candidate：慎终如始，则无败事

状态：`source-current / reading-candidate / research-open / independent-review-complete / conditional-revision-applied / follow-up-clean / acceptance-pending`；不是哲学源行、全程成功保证、长期监控仪式、runtime gate 或实现授权。

本文件只从现行哲学序列的 P16 源行重建 reading candidate。它处理解决阶段检验的时点：一个
方案或主张不能因为开始时认真、执行中有记录或最后出现成功输出，就默认整个过程和采用后仍与
原目标、边界和验收关系一致。

## 源与对象

唯一源是 [`theory/philosophy.md` P16](../philosophy.md#L37)：

> P16｜慎终如始，则无败事｜解决·检验·时点

P16 回答的是：在解决和检验的时间展开中，如何让结束时的判断不脱离开始时已经确立的目的、
范围、约束和检验关系。它关注的是检验覆盖的时点连续性，不是要求每个任务都增加固定检查次数。

## 最小定义与边界

在当前问题处理领域，P16 的暂定定义是：

> 对一个正在推进的方案或主张，先依据其目的、风险、consumer 和接受关系判断哪些时间变化会
> 改变当前检验；只在适用的开始、关键变化、执行中、结束或采用后时点，检查当前行为与起初已
> 接受的目的、范围、约束、证据和结果关系是否仍然一致。未适用的时点记录 `not-applicable`
> 及理由；发现漂移、遗漏或未观察部分时，保留未知并把纠偏、停止或继续交由相应 owner 判断。

这里的“慎”是保持承重关系和检验敏感度，“终”与“始”是时点上的关系，不是机械重复同一清单；
“则无败事”表达的是避免因过程末端失守而失败的方向，不是任何系统、任务或采用周期的无失败
保证。P16 不规定统一的 checkpoint schema、监控时长、告警阈值或长期 memory。

### 最近邻

- **P15「实践是检验真理的唯一标准」**回答用什么相称实践检验主张；P16 回答在什么时间覆盖
  这些检验。一次实践成功不等于时点覆盖完整。
- **P03「实践、认识、再实践、再认识」**回答结果怎样改变下一认识和实践；P16 只在适用的
  关键时点暴露检验关系是否断裂，不替 P03 规定反馈循环或固定次数。
- **P10「为之于未有，治之于未乱」**回答何时介入；P16 关注整个推进期间是否保持开始时的
  检验关系，不把及时介入替代全过程观察。
- **P04「知之为知之，不知为不知」**要求未观察、未覆盖或已漂移的部分保留未知；P16 不允许
  用最后一次成功结果填平中间或采用后的未知。
- **P11「治大国若烹小鲜」**处理执行扰动和成本；P16 不以检查次数为价值，也不取得资源/成本
  权限。

### 包含、排除与反例

- **包含：** 对一个已说明目的、风险、consumer 和接受关系的设计候选，选出真正可能改变判断的
  开始、变化后、执行结束或采用时点；如果某个时点不可观察或不适用于对象，分别保留 unknown
  或记录 `not-applicable` 及理由，再由 owner 判断是否继续、补观察、停止或回返。
- **排除：** 把 P16 变成无限轮询、永久监控、固定 checklist、所有任务的强制 gate 或“最后
  检查通过所以全过程安全”；检查的时点必须与对象风险和 consumer 关系相称。
- **排除：** 把“谨慎”解释成不行动、等待所有未知消失或拒绝事后纠偏；P16 仍允许在有限未知
  下行动，只要求不把未覆盖写成已确认。
- **反例：** 开始时接受的是一个 bounded purpose，执行中目标或 effect 已改变，结束时只凭
  输出格式通过就声称原主张成立；这说明时点关系断裂，P15/P16 的边界均被误报。

## 生成性候选

当 P16 与 Agent、WorkCell 或 planning 环境冲撞时，可以长出“按风险与 consumer 选择适用时点的
检验回看”候选方法：保存起始对象与目的，在真正改变关系的节点观察 delta，并把时间覆盖结果
交给相应 owner 作为下一判断的材料。它可以支撑 iterative improvement、evidence review 或
adoption regression 的设计，但不生成统一监控服务、长期记录协议、runtime gate 或 WorkCell core
字段。
