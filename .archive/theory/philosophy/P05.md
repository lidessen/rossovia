# P05 reading candidate：具体问题具体分析

状态：`source-current / reading-candidate / independent-review-complete / acceptance-pending / research-open`；不是哲学源行、living theory、skill 载体或 runtime 规则。

本文件只解释现行源中的 P05，不把“具体”扩成无限背景收集、拒绝复用或自动个性化规则。它
承接 P01–P04 的认识边界，进入分析阶段；当前 source/边界 review 已完成，仍需明确 reading acceptance。

## 源与对象

唯一源是 [`theory/philosophy.md` P05](../philosophy.md#L15)：

> P05｜具体问题具体分析｜分析·特殊性

P05 回答分析阶段的特殊性问题：面对一个已被指认的问题，哪些具体条件使它不能被一个抽象
模板直接代替；分析必须把对象当前的状态、关系、限制和用途带回判断，而不是只套用一般规则。

## 最小定义与边界

在当前问题处理领域，P05 的暂定定义是：

> 以具体问题的对象、条件、关系和目的为材料，判断哪些特殊性会改变当前分析，或使相应的
> 下游 owner/protocol 重新评估处置；保留能改变判断的差异，同时允许一般规律作为比较和
> 约束，不把“具体”误解为每个问题都完全独特或必须收集所有背景。

“具体”在这里是分析对象与条件的关系，不是文档细节数量、用户画像、实现载体或任意定制；
“分析”也不是直接决定优先级、入口、接受或 runtime policy。P05 不取得 source、domain owner、
acceptance 或外部效果权威。

### 最近邻

- **P01「实事求是」**规定认识从实际来源出发并求规律；P05 在已有问题对象上判断哪些特殊
  条件改变分析。P05 不替代 P01 的来源关系，也不把“具体”当作事实本身。
- **P04「知之为知之，不知为不知」**规定当前认识的已知/未知状态；P05 规定已知材料中的
  特殊条件怎样改变分析。未知仍须保留，不能用“具体分析”补造事实。
- **P07「天下难事，必作于易」**回答从哪里形成可行入口；P05 回答对象的特殊条件，不自动
  选择最小入口或工作顺序。
- **P08「井蛙不可语海，夏虫不可语冰」**回答问题范围、视域和不可强行沟通的边界；P05
  分析范围内的特殊关系，不能把对象尚未界定直接写成特殊性。
- **P09「抓住主要矛盾」**回答多个矛盾中先处理哪一个；P05 可提供矛盾的具体条件，但不取得
  主次排序权。
- **P06「为学日益，为道日损」**回答分析中删减与保留的方向；P05 先判断哪些差异确实改变
  当前问题，P06 才能据此删去无关复杂性，二者不合并。

## 包含、排除与反例

- **包含：** WorkCell 的 active Binding expiry/revocation 不能只套用“运行前物化、运行中
  不可变”的一般 baseline；是否已开始 host effect、host policy 是否撤销、是否有安全 owner、
  是否需要保留未知结果，都会改变分析；下游 host/security 或 protocol owner 是否改变处置仍
  由其自身决定。当前协议仍是 design candidate，这只是 `design/fixture observation` 生成性例子。
- **包含：** 有 replay consumer 与没有 replay consumer 的机制案例表面都谈 Event，但 consumer、
  失败后果和恢复目的不同，不能由“需要更可靠”这一抽象句直接合并分析；这是
  `design/fixture observation`，不是当前 runtime consumer 事实或机制接受。
- **排除：** 只增加背景字段、上下文段落或用户画像，却不能指出哪项特殊性改变了判断；这是
  文档膨胀，不是 P05。
- **排除：** 因为对象存在一般规律，就拒绝查看当前条件；这把一般性误当成具体分析的完成。
- **反例：** 若替换具体条件后，分析、owner route 或处置仍完全相同，当前差异可能不是承重
  特殊性；若一项差异改变了事实、问题范围或接受关系，却仍套用旧处置，P05 边界被击穿。
- **父 item 关系：** P05 的特殊性不能吞并 P07 的入口、P09 的主次或 P08 的问题边界；这些
  关系需在父 item 层用具体成对案例继续检查。

### 成对案例

以下是 design/fixture cases，不是 runtime Run：

1. **承重差异：** 同一“活动 Binding 过期/撤销”的设计对象，案例 A 是 admission 前尚未开始
   host effect，案例 B 是活动 host call 已经开始且撤销 policy；这项条件会改变需要谁审查、
   是否必须表达未知效果以及应保留哪些事实。P05 只识别该差异改变分析，host/security 与
   protocol owner 才决定具体处置。
2. **非承重增加：** 在案例 A 的对象条件不变时，额外加入 provider 名称、格式偏好或与失败
   无关的历史背景，但没有改变 host effect、policy、owner 或目标；分析和下游处置不变，这些
   信息量不构成 P05 的“具体性”。

## 生成性候选

当 P05 与设计/开发环境冲撞时，可以长出“先恢复会改变判断的具体条件，再把差异交给相应
下游 owner/protocol 重新评估”的方法。它可以支撑 `concept-articulation`、`work-estimation`、
`mechanism-design-review` 或 domain review，但不成为万能定制 skill、背景收集要求、任务排序器
或 runtime gate。
