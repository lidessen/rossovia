# P10 reading candidate：为之于未有，治之于未乱

状态：`reading-candidate / source-current / independent-review-complete / acceptance-pending / research-open`；
不是哲学源行、固定提前量、预防策略、deadline、scheduler、timeout、revocation policy 或实现授权。

本文件只解释现行源中的 P10。它处理解决阶段的时机：当对象、风险状态和允许效果已经足够明确时，
判断是否应在问题尚未扩大、状态尚未进入更难治理的区间时介入。它不把“早”本身当成正确，也不把
分析入口、任务优先级或当前设计观察误写成已经可以执行的效果。

## 最小定义与边界

在当前问题处理领域，P10 的暂定定义是：

> 在外部已经给出相称对象、状态窗口、风险暴露、允许效果、owner 和接受边界的前提下，比较何时
> 介入能够避免问题进入更难处理或更高风险的状态；“未有/未乱”是相对于当前候选关系和可观察
> 状态而言，不是普遍越早越好，也不跳过证据或效果边界。

P10 的对象是解决阶段的介入窗口，主要判断是“在外部前提已成立时，现在介入与延后介入是否改变
可逆性、风险或处置关系”。P10 只比较时机差异，不拥有对象/状态/效果的 admission 或授权判断；
它不决定从哪里开始分析、不提供 deadline/timeout、不替 owner 接受效果，也不建立 scheduler、cutoff、
revocation 或自动预防机制。

### 最近邻

- **P07「天下难事，必作于易」**处理从哪里形成可行的分析入口；P10 处理何时介入已相称的解决
  对象。入口较小不等于时机更早，分析顺序也不等于 effect authorization。
- **P09「抓住主要矛盾」**处理同一范围内哪个局部冲突承重；P10 处理在该对象和冲突已经被识别后
  哪个状态窗口改变介入判断。主次不能推出固定时间，时机也不能替代主次判断。
- **P11「治大国若烹小鲜」**处理已接受方案的执行扰动和成本；P10 先判断何时介入，不能从“早”
  推出执行路径、频率或成本策略。
- **P04「知之为知之，不知为不知」**要求状态窗口、覆盖范围和风险证据如实标记；P10 不能把
  假设的安全点写成已知状态。
- **P16「慎终如始，则无败事」**处理检验的时点覆盖与长期收束；P10 处理解决动作的介入窗口，
  不以一次早期动作替代结束或采用后的回看。

## 包含、排除与成对案例

- **包含：** 假设一个未来真实 host case 已由外部 owner 明确候选 Binding identity、expiry/revocation
  contract、允许效果和可观察状态窗口；比较在状态仍可逆时处理与等待到风险已经扩大时处理，
  结果用于决定下一项 design/owner review。它仍需由相应 owner 接受或拒绝，不自动取得 runtime 权。
- **包含：** 在当前 WorkCell design review 中，先记录同一候选关系的 source/owner/unknown fixture，
  明确这是 P07 的分析入口；只有未来形成 owner/protocol-accepted contract/effect 和状态窗口，
  才可以把“何时介入”作为 P10 问题。当前具体 Binding identity 仍 unknown，F1→F2 不是 runtime
  状态迁移；这个边界观察不构成 P10 行为证据。
- **排除：** 把所有问题都设成越早越好、把某个固定提前量写成规则，或仅凭“未乱”文字创建
  proactive scheduler、deadline、timeout、cutoff 或 revocation policy。
- **排除：** 把容易建立的 fixture、较小的任务或最先写出的文档当成 P10 的时机结论；那是
  P07 的入口问题，若没有相称 effect 和状态证据就应保持 unknown。
- **排除：** 为了提前介入而跳过 source、owner、acceptance、取消/恢复或证据边界；提前动作本身
  不能取得这些关系。

### 成对案例

1. **条件性时机判断：** 假设同一候选关系下的 Binding 已有 owner-backed expiry contract，状态仍
   可逆且风险在继续暴露；在当前窗口采取已接受的 bounded effect，比等到 Binding 失效后再处理
   更能改变下一项处置判断。这里改变的是介入时点，不是建立 scheduler。
2. **假时机结论：** 只有一个很小的 source/owner fixture，尚无 effect、状态窗口或接受 owner，
   却因为它“先做”就宣称风险已被治理；这把 P07 的入口误写成 P10 的解决时机。
3. **过度扩张：** 把 P10 解释为每个任务必须提前检查、按固定周期轮询或自动 revoke；这把
   source-backed reading 越过 owner/protocol/effect boundary，不能由源行支持。
