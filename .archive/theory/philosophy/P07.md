# P07 reading candidate：天下难事，必作于易

状态：`reading-candidate / source-current / independent-review-complete / acceptance-pending / research-open`；
不是哲学源行、任务拆分器、优先级规则、速率保证或 runtime 调度机制。

本文件只解释现行源中的 P07。它处理分析阶段的入手点：在目标仍然较大、关系仍有未知时，
先找到一个足以形成真实判断或贡献的可行起点。这里的“易”不是简单、快速或低价值，而是
当前条件下能够承担下一次观察、检验或回返的最小有效入口。

## 源与对象

唯一源是 [`theory/philosophy.md` P07](../philosophy.md#L18)：

> P07｜天下难事，必作于易｜分析·入手点

本 reading 不替源行补历史注释，也不把它扩展成“所有工作必须从最小任务开始”。当前 living
序列只给出它在问题处理领域中的坐标：分析复杂对象时，识别可以先承接真实判断的入口。

## 最小定义与边界

在当前问题处理领域，P07 的暂定定义是：

> 面对尚未能一次承接的难事，先选择一个与目标有真实关系、范围可界定、结果能改变下一项
> 判断的可行入口，再根据该结果继续展开；入口的可行性不等于整体成功，也不等于它必须是
> 最短、最快或最容易的动作。

P07 的对象是分析阶段的起点与第一项可承接贡献，主要判断是“从哪里开始，才能让下一次判断
> 有真实支撑”。它不决定整体主次、不批准任务拆分、不提供资源预算，也不替 owner、acceptance
> 或 runtime scheduler 作决定。

### 最近邻

- **P05「具体问题具体分析」**先判断哪些特殊条件改变分析；P07 在这些条件被保留后寻找可行
  入手点。若入口选择会掩盖承重条件，应回到 P05，而不是以“易”删掉条件。
- **P06「为学日益，为道日损」**判断哪些复杂性可删而不改变当前判断；P07 判断从哪个仍保留
  真实关系的入口开始，不能把简化误写成入手点。
- **P09「抓住主要矛盾」**判断多个矛盾中的主次；P07 可以从一个可承接的入口开始，但不能
  因为入口较小就声称它是主要矛盾或取得全局优先级。
- **P10「为之于未有，治之于未乱」**处理何时介入与风险暴露；P07 处理从哪里开始，不能从
  入手点推出固定提前量、预防策略或时间表。
- **P04「知之为知之，不知为不知」**要求入口的结果和覆盖范围如实标记；P07 不能把一个小的
  局部贡献写成整体已知或整体完成。

## 包含、排除与成对案例

- **包含：** 当前整个 planning goal 中，先补一个能改变后续 owner、standing 或关系判断的
  bounded review，再决定是否进入下一个 reading、WorkCell 关系或 evidence branch；该 review
  是入口，不是整项设计或实现。
- **包含：** 对一个尚未接受的 WorkCell 关系，先做一个可回读的 source/consumer/unknown
  fixture，使下一步能判断是否需要真实 host；fixture 的结果可以是“不足以推进”，仍然是有效
  入口结果。
- **排除：** 把“拆成小任务”本身当成 P07；若拆分不能产生可判定结果，或只是把未知分散到更多
  文件，它没有形成 P07 所说的真实入口。
- **排除：** 把容易完成的文档、最快的代码或最低成本的动作自动放在最前；入口仍需与目标、
  约束、证据和下一判断保持关系。
- **排除：** 以入口很小为由跳过 acceptance、owner、反例或 source lineage；这些缺口应保持为
  unknown 或路由给相应 owner。

### 成对案例

1. **有效入口：** P06/P11 boundary review 先固定同一候选 WorkCell mechanism 关系，记录 source、
   阶段、owner 和未知，再判断需要不需要真实 host；它缩小了下一项判断，但没有声称具体 runtime
   object、WorkCell 已接受或已经实现。
2. **假入口：** 只把 `design/` 下一个文件改名或增加一个没有 consumer 的字段；动作很小，
   但不改变任何可回读判断，因此没有形成 P07 入口。
3. **过度扩张：** 先做一个能运行的 base prototype，再用它反推协议必须如此；这把入口越过了
   design acceptance 与 implementation authorization，也没有保留“结果不足”的可能。

## 生成性候选

当 P07 与 planning、research 或 design 相遇时，可以长出“先选最小有效探针/贡献，再按结果
回返”的工作方法。它可支持 `planning-inbox` 的路由、`work-estimation` 的工作图恢复、
`practice-cycle` 的下一项实践选择，或某个设计关系的 bounded fixture；但它不成为统一任务
分解器、优先级队列、速度优化器或 runtime scheduler。
