## 最小定义与边界

在当前问题处理领域，P06 的暂定定义是：

> 在分析一个对象或方案时，先保留会改变对象身份、主张强度、约束、证据、owner route 或下一
> 判断的承重关系，再去掉不能改变当前判断的冗余、无关分支和不必要复杂性；“损”是让理解回到
> 足够而非最短，不是删掉未知、证据或硬约束。

P06 的对象是分析中的复杂性与承重关系，主要判断是“什么可以删而不损失当前分析”。它不批准
预算、不决定实现成本、不替 P05 判断特殊性、不替 P07 选择入手点，也不取得 P11 的执行/扰动
authority。

### 最近邻

- **P05「具体问题具体分析」**先判断哪些具体条件会改变当前分析；P06 再据此删除不承重的
  复杂性。若差异是否承重尚未确定，不能先用 P06 删除它。
- **P07「天下难事，必作于易」**回答从哪里形成可行入口；P06 回答分析中保留与删去什么，
  不自动决定从易处开始或拆分工作。
- **P09「抓住主要矛盾」**回答多个矛盾中先处理哪个；P06 可以减少不影响主要判断的表示，
  但不取得优先级或 owner routing。
- **P11「治大国若烹小鲜」**回答解决阶段如何控制扰动/执行成本；P06 属分析阶段的繁简，
  二者都可能反对无谓动作，但不能由 P06 推出执行代价或操作频率。
- **P04「知之为知之，不知为不知」**要求未知保持为未知；P06 不能以“简化”为名删掉未知
  标记、来源或证据缺口。

## 包含、排除与成对案例

- **包含：** WorkCell planning 中，将已经完成的 A/B/C/D review、owner 缺口和实现门分别保留
  为可回读关系，同时删除“先做 event bus / registry / session resume”的未支持机制分支；
  这里保留 unknown 和不授权边界，删除的是不改变当前决定的 speculative mechanism。
- **包含：** 在全局 planning work graph 中，不把 token/time/money 估算加入当前节点，因为当前
  决策只需要 item standing、依赖和发现分支；这不是声称资源永远不重要。
- **排除：** 为了短文、较少字段或更快 review 删除 source link、unknown、owner、反例或接受
  条件；这些内容若改变下一判断就是承重语义。
- **排除：** 把“减少动作”直接当成 P06；如果动作属于已经决定的 host/security 或 runtime
  owner，处置应路由到 P11/机制/实现 owner。

### 成对案例

1. **承重保留：** 当前 WorkCell record 里，`retention owner unknown` 看似可删，但删除它会使
   下一项 owner/acceptance 判断消失；它不能被 P06 删除。相反，重复解释 provider session 不能
   作为 lineage authority 的段落若不改变关系，可压缩但不能改写成 provider authority。
2. **非承重删减：** 一个 planning item 已经有 source、standing、owner、依赖和 return condition；
   额外复制同一结论到多个 projection 不改变判断，可以去除或改成链接，前提是唯一权威和回读
   关系仍然可恢复。
3. **差异未定：** 某字段是否会影响 consumer route 尚未调查时，不能以 P06 先删掉；应保留为
   unknown 或交给 P02/P05 的调查与具体分析。

但不成为全局压缩器、token 优化器、预算策略、测试删除规则或 runtime 成本机制。
