# Skill formation theory

> 活树版。本文解释一个 skill 方法何时应编码为选择性加载的 skill 载体、载体怎样保持边界、凭什么继续存在。
> 证据来源与未决问题见 [`research/skill-formation.md`](research/skill-formation.md)。本文不创建具体
> skill，不规定 `SKILL.md` 模板，不授权运行时机制，也不修订哲学序列。

## 定位与血统

[`gene-expression.md`](gene-expression.md) 已经确立：条目是「二」，skill 是条目在具体环境中经由「冲」
长出的方法集；skill 载体把方法编码为可选择加载的表达，一次激活的实际行为与产物才是表型。本文处理的是
其中更窄的问题：一个已经从条目长出的方法，何时应编码为**选择性加载的 skill 载体**，以及这种载体何时
应当改变或退出。

**主血统：** P01（来源）、P02（证据）、P05（特殊性）、P15（检验·手段）。
**支持：** P03（深化）、P04（已知边界）、P06（简化）、P09（主次）、P11（成本）、P14（表达）、
P16（检验·时点）。

这些条目在 Agent 环境中形成几组冲撞：经验需要复用，但不能从想要的形式倒推问题；方法需要稳定，但每次
激活都会占用发现面、注意与上下文；名称必须可发现，但名称不能代替对象；文字可以合理，行为却未必改变；
提示可以指导判断，却不能保存生命周期、权限、恢复或效果权威。skill-formation 就产生于这些关系之间。

## Thesis

**skill 载体是在相关任务中被选择性加载、用来表达某个 skill 方法并改变 Agent 重复判断或行动的载体。** 它的对象不是文件本身，
不是一批知识，也不是「重要性」本身，而是以下关系：

```text
Agent × 一类任务 × 被处理对象 × 具体环境
                         ↓
                 重复的判断或行动差距
                         ↓ 方法表达
                   可观察的行为变化
```

因此，skill 载体的同一性由它所表达方法的**行为对象、主要判断、触发边界和成功关系**共同保持，而不由名称、目录、
篇幅或实现载体保持。「一个主要判断」也不等于一步或一句口号；同一判断可以需要多步、reference 或工具，
但这些部分必须共同服务同一个可辨认的行为变化。

`SKILL.md` 是当前环境的一种载体。载体合法只说明表达能被装载，不说明对象成立、方法正确或行为改善。

## 形成：从方法生成到形式成立

条目在环境中冲出方法，并不自动推出这个方法应被编码为 skill 载体。载体作为形式成立，还需要几个关系同时为真：

- **对象可指认：** 能说清哪个 Agent 在什么环境中，对什么对象缺少哪类判断或行动；「写得更好」或
  「更智能」没有形成对象同一性。
- **差距有现实来源：** 真实任务、用户纠正、失败轨迹或可复现 baseline 显示了差距。偏好的 skill 名称、
  目录空位或单次灵感不能成为来源。
- **关系可重复：** 复用的是跨任务重现的判断关系，不是把一次交付保存成永久方法。重复不要求提示词相同，
  但必须能说明不同实例为何属于同一类。
- **触发可分辨：** 正例、反例和最近邻之间存在可表达的边界，使 Agent 有理由在相关时加载、无关时不加载。
- **方法可由表达改变：** 所需的是判断、行动路径、例子、按需材料或工具调用关系；若必须在提示被忽略、
  模型替换或进程重启后仍然成立，它就不是 skill 能拥有的属性。
- **生成关系已经内化：** 相关条目与理论怎样改变判断，必须成为 skill 方法本身可执行的关系，而不只是 P 编号、
  理论链接或一句血统声明。普通使用者激活 skill 后无需回读条目或理论，便能恢复主要判断、边界、行动、
  未知和返回；回读只服务作者的生成、维护者的审计诊断，或明确以理论为对象的任务。
- **skill 载体是较小的真实形式：** 直接回答、现有 skill 载体、项目局部指令、普通文档、reference 或工具不能以更低
  成本保持同一关系。新的形式必须挣得它带来的发现噪声、上下文占用、冲突和维护成本。
- **结果可观察：** 能区分应该发生的行为、不得发生的行为和应转交给相邻拥有者的行为；否则无法知道方法
  是否成立。

这些不是为了把创建变成仪式。它们共同说明一件事：**skill 载体的准入对象，是可重复、可激活、可由方法表达
改变并可通过行为观察检验的 Agent 判断或行动差距。** 承重关系未知时，真实形式是继续研究或保留局部表达，
而不是先创建再用存在本身证明需要。

## 相邻形式与所有权

形式的边界取决于它必须保持的关系，不取决于内容看起来像什么：

| 形式 | 它拥有的关系 | 不因此拥有 |
|---|---|---|
| 一次任务表达 | 当前请求所需的局部上下文与指示 | 跨任务方法、长期事实 |
| 项目局部指令 | 在指定项目或目录中始终成立的工作边界 | 选择性触发、运行时强制 |
| 普通文档 | 可回读的理论、事实、设计、决定及其来源 | 自动触发、执行或接受权威 |
| reference | 已激活方法在特定分支才需要的细节 | 独立触发与主要判断 |
| skill 载体 | 一类任务中的 skill 方法及其发现、加载与行动边界 | 项目事实、长期决定、效果与接受 |
| 脚本或工具 | 确定性变换或外部能力接口 | 何时以及为何使用的全部语义判断 |
| runtime / base | 生命周期、身份、权限、并发、恢复、效果边界与持久证据 | 领域判断质量和人类接受 |

一个 skill 载体可以连接这些形式，但连接不转移所有权。它所表达的方法可以教 Agent 何时读取文档或调用工具，不能把外部
语义源复制成自己的事实；它可以表达安全方法，不能以更强措辞替代 runtime 的硬边界。
[`harness/theory.md`](harness/theory.md) 的所有权测试在这里仍然成立：若方法改变而 Task、Run、effect、evidence 与
acceptance 契约仍保持真实，变化属于方法表达；若必须改变这些契约，问题已经越过 skill。

名称、文件名和目录是形式的一部分，应帮助 Agent 发现对象并辨认其地位，但它们不另行创造对象。路径调整
跟随对象、权威和生命周期的变化；它是正常的表达维护，不自动获得独立理论或新 skill 的地位。

## 生命周期：存在是持续的主张

skill 载体的形成不是一次性认证。模型能力、系统提示、项目边界、邻接载体和任务分布都会变化；载体继续
存在，就持续主张「这个差距仍在、这个形式仍合适、这段表达仍有净收益」。生命周期因此是实践—认识的往复，
不是在旧文本上无限累加规则。

- **创建**把有据的方法表达置为候选，不把它置为权威。首版只需保持主要判断、触发边界、任务所需来源、
  已内化的生成关系、行动与返回关系；尚无证据的完备外观会掩盖真实未知。P 与 theory 链接可以记录血统，
  但不能代替方法正文。
- **改写**发生在对象与边界仍成立而表达未能稳定恢复方法时。文字变好不等于设计变对，改写后仍需行为证据。
- **拆分**只在两个可独立触发、独立失败、独立验证又能重组的主要判断已经出现时成立。篇幅长或小节多不是
  拆分理由，按需细节可以留在 reference。
- **合并**发生在两个 skills 实际拥有同一对象、触发和成功关系，且 Agent 无法有意义地区分它们时。共享术语
  或受众不够。
- **降级**把不再拥有独立判断的内容归还更真实的形式：知识归文档/reference，项目常量归局部指令，确定性
  变换归工具，硬属性归 runtime/base。
- **删除**承认差距已经消失、被其他拥有者覆盖、没有净收益或无法可靠维护。历史由版本历史或 archive 承担；
  会继续误触发的兼容壳不是退役。

生命周期变化应与证据影响相称。一个新近、具体或被某个 reviewer 详细描述的问题，不因占据注意就成为主要
问题；频率、影响、证据强度、修复成本及其与整体的关系共同决定改动落在哪一层。

## Review：设计与表达分开判断

review 的首要问题不是「这份文字还能怎样优化」，而是「这个 skill 载体是否仍应存在」。它同时观察六个彼此
相关但不能互相代替的面：

1. **成立性：** 行为差距仍存在，且没有被模型、环境、现有方法或工具关闭。
2. **对象与边界：** 名称、正反触发、最近邻和主要判断指向同一个对象。
3. **形式与上下文：** 主判断和由条目生成的必要关系留在可激活表达中，分支细节按需读取；任务事实的 canonical source 没有被复制，理论链接也没有被误作运行时前置阅读。
4. **Agent 表达：** 普通使用者只凭 skill 载体即可恢复来源地位、判断标准、允许效果、未知、返回与完成关系，而不只是角色、口号或 P 编号。
5. **行为与回归：** 代表性任务中目标行为改善，非范围被拒绝，已有能力没有退化。
6. **体系关系：** 邻接 skills 没有重叠、矛盾、循环依赖，也没有把各自负责的局部问题抬成全局中心。

概念形成、形式选择、人类写作、Agent 表达和委派方法都可以成为 review 的不同观察面；它们也可以反过来
检查 skill-formation 自身。但一种方法成功应用于自己，只能产生修改候选，不能证明自己的设计正确。
作者解释意图，独立 reviewer 提供有据的语义判断，行为对照观察效果，人类决定是否接受；这些关系不应由
一个自评动作折叠。

## 证据等级与主张边界

skill 载体的证据不是一个笼统的「通过」。不同观察只能支持相应强度的主张：

```text
format-valid
    → behavior-observed
    → boundary-supported
    → matched improvement
    → regression-supported
```

- `format-valid`：载体、元数据、链接或确定性结构符合显式契约。
- `behavior-observed`：在命名任务中观察到目标行为；尚不能把变化归因于 skill。
- `boundary-supported`：正例、反例和相邻 owner 的任务支持触发与拒绝边界。
- `matched improvement`：相同模型、材料、工具、harness 和环境下，只有目标 skill 不同的对照支持改善归因。
- `regression-supported`：代表性任务和多次 trial 支持改善在后续变化后仍保持。

等级描述可说到什么，不是一个自动晋级流程，也不是普遍正确性的证明。机械 grader 只能证明其断言范围内的
结构事实；语义 reviewer 可以比较来源忠实、边界和行动质量，但其结论仍是带不确定性的主张；随机 Agent
输出的一次成功不能替代对照与回归。没有 matched baseline 就不声称因果改善，没有反例就不声称边界成立，
没有长期观察就不声称稳定。

## 人类接受与理论边界

人类接受拥有者决定目标是否值得、残余风险是否可承受、维护成本是否合理，以及一个候选 skill 载体是否进入
living tree。Agent 作者和 reviewer 可以提交候选、观察、反对意见与未知，不能以一致投票、分数或自洽文字
取得接受权威。接受也不把候选变成永恒真理；它是在当前证据与环境下承担继续使用的决定。

研究、理论、skill、评审和接受因此各守一层：研究保存证据与未知；理论解释稳定区分与推导关系；skill 表达
具体环境中的方法；评审形成关于设计和行为的主张；人类接受决定是否采纳。任何一层都不因引用另一层而取得
后者的权威。

本文只在证据改变「什么是 skill、它与相邻形式怎样分界、什么主张需要什么证据」这些理论区分时修订。
某个模型的触发怪癖、一次措辞失败、单个目录不顺或某项局部任务的偏好，先由对应表达和环境处理；它们不能
仅因被发现就反写哲学序列或扩张本理论。
