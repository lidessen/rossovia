# 表达与形式

> 本文是 living theory。它吸收 [`theory/research/expression-and-form.md`](research/expression-and-form.md)
> 的研究结论，解释现行哲学条目在表达问题中的冲撞如何生成方法。它不新增或改写哲学条目，不规定统一文风、
> 固定模板或运行时协议，也不直接创建 skill。

## 定位与血统

**主血统：** P01（认识·来源）、P05（分析·特殊性）、P14（解决·表达）。

**支持：** P02（认识·证据）、P06（分析·简化）、P08（分析·问题边界）、P09（解决·主次）、
P11（解决·成本）、P15（检验·手段）、P16（检验·时点）。

这些条目在表达环境中形成五组冲撞：真实来源与表达目的相冲，要求表达既有方向又不越过事实；同一语义与不同
使用关系相冲，生成不同形式；语义完整与篇幅、注意力、token 成本相冲，生成有重点的压缩；正名与实践主体的
理解、判断和行动相冲，生成可用表达；表达意图与真实接收效果相冲，生成行为检验与回归。

## Thesis：表达是语义在使用关系中的保真变换

表达不是给既有文字换一种更漂亮的写法，也不是把内容装进文章、列表或 schema。它把一个已有身份、来源与
边界的语义对象，变换为接收者在具体环境中能够理解、判断或行动的形式，同时保持那些会改变意义与行动的关系。

```text
语义对象与来源边界
        ×
受众 · 目的 · 行动 · 媒介
        ↓
存在／载体形式
        +
载体内组织与表达
        ↓
理解 · 判断 · 行动
        ↓
真实接收效果与修订证据
```

这里的**语义对象**包括对象身份、定义、事实状态、主张强度、范围、因果、证据归属、约束、权威与未知。
本文所说的**形式**有两层，不由同一个专项方法统包：

- **存在／载体形式**判断语义对象是否需要一个新载体，以及它应当成为当前任务表达、项目局部指令、普通文档、
  reference、skill 载体、工具或 runtime、projection 还是有限计划，并保持其权威、生命周期与维护关系。
  这一层由 `form-selection` 拥有。
- **载体内组织形式**判断既定载体中怎样使用 prose、列表、表格、步骤或 schema 来选择、排列、连接和展开语义。
  面向人的组织由 `human-writing` 拥有，面向 Agent 的组织由 `agent-expression` 拥有。

两层互相约束。法律表单、API schema、界面空间或加载机制等外部契约，可以限制载体内的组织，也可否决一个载体候选；
它们不因此把载体选择与载体内写作合成同一项判断。

来源边界在逻辑上先于表达关系。受众和目的可以改变解释深度、顺序与举例，不能创造来源没有支持的事实、动机、
因果或成熟度。这个先后是诊断原则，不是固定工作流；媒介限制或接收结果可能迫使写作者回头缩小目的、补做调查，
甚至重新界定对象。

## 两层形式都受四项使用关系约束

无论是选择存在／载体形式，还是在既定载体内组织表达，都不能由主题、作者偏好或“给谁看”单独推出。至少要同时恢复
四项关系：

| 关系 | 核心问题 | 它主要改变什么 |
|---|---|---|
| 受众 | 谁在接收，已知什么，使用何种词汇，拥有何种权限与判断能力？ | 前提、解释深度、术语、例子与语气 |
| 目的 | 这次表达为什么存在，希望改变何种理解、判断、记忆或能力？ | 取材边界、重点和整体推进 |
| 行动 | 接收者实际要阅读、学习、查询、比较、决策、执行，还是交给程序解析？ | 论证、步骤、表格、契约、schema 等操作形态 |
| 媒介 | 内容怎样到达、被检索、调用、更新和验证；有哪些外部契约？ | 导航、层级、篇幅、结构化程度和维护方式 |

目的与行动不能合并。改变理解可以是完整目的而没有即时步骤；一次查询可以是即时行动，却不决定使用者最终想
解决什么。媒介也不只是排版：法律表单、API schema、界面空间、加载上下文与发布机制会先限制候选形式，但仍
不能替代受众和内容判断。

对存在／载体形式，由此选择的是**最小真实形式**，不是最短文本、最少文件或最低 token 数。最小意味着不增加无主权威、
重复维护和无用机制，同时完整承载当前使用关系。有时无需新载体；有时长 reference，或由一个语义源生成的多个视图才是更小、更真实的解。
对载体内组织，“最小”同样服从承重语义与真实接收效果，不按文字数或标题数裁决。

## 面向人的表达：使关系可理解

人需要的不只是事实集合，还需要看见事实之间为什么如此连接。面向人的表达应让当前读者恢复与目的相关的因果、
对比、限定、递进、例证和结论，并按读者已有知识决定哪些前提需要展开。所谓自然、好读或有作者声音，只能是这种
真实关系被顺畅理解后的表现，不能独立于来源成为目标。

这不规定 prose 优于列表。论证和解释通常需要连续推进；reference、词表、变更记录和界面文本可以有意保持条目
独立。判断标准不是表面像不像文章，而是接收者能否在媒介允许的成本内恢复所需意义、依据和下一步。

关系化也有风险。为了让叙述顺滑而补出未经支持的动机、因果或背景，会得到表面完整、语义失真的文章。因此人的
表达始终同时接受两项约束：来源决定可以说什么，使用关系决定怎样让这个人理解或行动。

## 面向 Agent 的表达：建立可判断、可行动的条件

Agent-facing 内容不是更短、更硬或更多列表的人类文章。它的区别在接收关系：接收者会据此选择工具、改变对象、
产生效果并返回证据。因此表达必须显露真正会改变判断和行动的条件。按任务需要，这些条件包括：

- 正在处理的对象、期望改变，以及邻近但不合格的结果；
- 输入、来源地位和事实状态，尤其是指令、现状、候选、未知与仅供参考材料的区别；
- 允许效果、权限与停止边界；
- 判断标准、成功证据和最终接受者；
- 返回给谁、返回什么，以及缺失、冲突、失败或能力不足时必须暴露什么。

只有会改变当前理解、判断、允许行动或必要返回的条件才应进入表达。低风险且可从真实上下文稳定恢复的细节可以
让 Agent 推断；把所有可能分支写入提示词会制造冲突、稀释重点并增加上下文成本。反过来，不能因为模型通常能
猜到，就省略对象身份、来源权威、硬约束、效果边界或验收含义。

结构化输出只在接收端需要机械解析或契约符合时天然占优；需要解释、取舍和语义判断时，完整 prose 可能更真实。
格式符合只能证明格式，不能证明事实正确、任务相关或已被接受。

## 字段形态与分类：label、enum、属性组合

类型或分类的设计，首先不是选择一个熟悉的字段名，而是判断这项区分是否是独立的语义对象、由谁拥有、需要怎样
被消费，以及它在时间中如何演化。`label`、`enum` 和属性组合不是同一信息的三种写法；选错形式会把开放观察
伪装成封闭事实，把多个正交维度压成一个不稳定值，或重复存储本来可以从权威属性派生的分类。

| 形式 | 在什么关系成立时使用 | 不应承担什么 |
| --- | --- | --- |
| **label / 标签** | 开放集合、描述性标记、检索/分组或当前语境下的工作指称；新值可以自然出现，标签本身不要求所有消费者共享永久含义 | 不作为权限、路由、验收、生命周期或安全判断的唯一依据；若下游必须按它分支，它已经需要更强的结构化契约 |
| **enum / 枚举** | 值集合虽可演化，但每个值的语义、适用范围、owner 和兼容规则足够长期稳定；消费者需要机械校验或对已知分支作明确判断，并且未知/扩展值有诚实处理方式 | 不把当前恰好出现的有限样本、短期 workflow、provider 名单或易变分类直接冻结成公共枚举；不以 enum 代替证据、接受或完整生命周期 |
| **属性组合** | 区分由多个相对正交、可独立变化的维度共同产生，新的组合是合法且有意义的；分类可以由这些权威属性派生 | 不为每个组合制造一个乘积枚举，也不在属性已是 canonical source 时再存一个会漂移的总类别 |
| **派生分类 / 不新增字段** | 所谓类型只是已有权威对象、关系或属性的视图，删除它不会丢失独立事实、来源或历史观察 | 不把方便查询误写成新的事实、owner 或长期 schema |

若不同分类值会携带不同 payload、约束或允许动作，应考虑带判别项的 variant/discriminated union；不要用一串
标签或互相冲突的布尔值让消费者自行猜结构。若要保留“当时观察到的类别”，而不是从当前属性重算，则把它作为有
来源和时间的 observation 记录，不要让派生 projection 冒充历史事实。

枚举的慎重原则不是“永远不加值”，而是要求 enum value 的身份和语义足够持久：集合可以在明确 owner、版本和
兼容/未知规则下扩展，但不能让不同版本或消费者静默改变同一个值的含义。只要值的变化速度高于其消费者的兼容
周期，优先使用 label、开放属性或带版本的领域对象，等稳定关系形成后再重新判断是否提升为 enum。

### 选择前的最小问题

1. 这项分类是否有独立事实、来源、owner 或历史意义？若没有，先从现有权威属性派生，不加字段。
2. 新的合法值出现时，现有消费者能否在不误判的情况下继续工作？若不能，不能把开放观察草率写成 enum。
3. 分类的各维度能否独立变化？若能，优先保留原子属性；若组合携带不同结构，再用 variant 表达。
4. 该值是否会驱动权限、路由、效果、验收或生命周期？若会，label 不够，必须补足结构化契约与 owner；这不等于
   自动增加 runtime 机制。
5. 删除这个字段后，是否会丢失无法由其他属性重建的事实或历史观察？若不会，它多半只是 projection，不应成为第二
   authority。
6. 新值、重命名、废止、跨版本读取和未知值的处理是否可回读？若不能，enum 的长期稳定性尚未成立。

这些问题是设计判断，不是固定 schema 或全局分类器。一个字段在一个 domain 中可以是 enum，在另一个 domain 中
只能是 label；受众、目的、行动、媒介、owner 和生命周期改变时应重新判断。字段形式也不能取得状态、权限、接受或
执行保证；那些关系仍由对应的 domain source、protocol、harness 或 runtime owner 拥有。

### 状态不是标签串，也不是组合枚举

状态字段尤其容易把不同关系压成一个值。例如把
`review-complete / source-observed / acceptance-pending / no-open-wave` 写进一个 `status`，表面上像是
“更完整的状态”，实际上混合了生命周期、证据、决策去向、执行面和历史事件。这既不是稳定 enum，也不是有明确
语义的 label，而是一个会随每轮工作无限增长的组合字符串。

设计状态时先按关系拆开：

- **生命周期 `status`：** 只表达对象自身所处的稳定生命周期，通常一次只能有一个当前值；它的值、转换、终止和
  owner 必须能长期共同判断。研究记录例如可以有 `active`、`settled`、`archived`，但这不是全项目通用枚举。
- **独立属性：** `evidence`、`disposition`、`authorization`、`execution`、`owner` 等若各自独立改变判断，
  就保留为独立属性；它们不是 `status` 的附加词，也不因为经常一起出现就合并。
- **`label`：** 只做开放的描述、检索或分组，例如“planning-maintenance”；它可以有多个，也可以出现新值，
  但不能单独驱动生命周期、路由、权限、验收或效果。
- **事件/里程碑：** “review completed”“projection reconciled”“trial-input prepared”是已经发生的事件，
  应进入有时间和来源的 lineage/record；它们不能继续堆在当前状态里。
- **派生视图：** 面向人可以把上述字段并排展示或按需组合，但该组合是 projection，不是 canonical `status`，
  不能被消费者反向解析成一个新的公共枚举。

以 planning checkpoint 为例，最小表达应接近：

```yaml
status: closed
standing: reconciled
execution: no-open-wave
authorization: implementation-not-authorized
labels: [planning-maintenance]
```

这里的字段值只是该领域的当前 projection，不是全项目预注册的 enum。若某种属性组合真的决定不同 payload、约束
或允许动作，应定义有名字的结构化 variant/discriminated union；不要把它编码成斜杠字符串，也不要为每个正交
维度组合制造乘积枚举。

表达可以陈述权限、效果与成功条件，却不拥有这些事实。必须跨提示词变化、进程重启或绕过首选措辞仍然成立的
状态、权限与效果边界属于 harness base 或其他机制；最终接受仍属于人或明确受托的接受者。继续增加 prompt 不能
替代运行时强制、机械验证或接受权。

## 双受众：一个语义源，不同表达视图

同时给人和 Agent 使用，不意味着写一个大文件迫使两者以同样顺序读取，也不意味着分别维护两套都自称现行的
正文。人的视图通常需要理由、背景、例子和阅读导航；Agent 的视图通常要突出触发、输入、边界、行动、返回和
验收。它们可以有不同结构和篇幅，但必须从同一个语义源取得对象定义、事实状态、硬约束、权威与接受边界。

**单一语义源**指一个语义事实只有一个明确的权威回答，不指所有内容必须在一个物理文件。不同视图可以引用、
包含或由它生成；若因局部可用性而复制，必须有与风险相称的同步或回归办法。派生视图是 projection，不因更便于
消费而取得独立权威。

单一来源只减少漂移，不保证来源正确。源本身仍需调查、验证和人类接受；否则统一只会使错误更一致。两类视图也
不必包含完全相同的内容：讨论历史和价值判断可以只服务人的接受，已经采纳的执行边界可以只在 Agent 入口突出。
共同的是承重语义，不是相同措辞。

## 承重语义先于 token economy

简洁、篇幅、延迟、注意力和 token 都是表达成本，不是意义裁判。压缩前先确定哪些内容承担当前理解、判断或行动；
删除后若会改变以下任一项，它就是**承重语义**：对象身份，主张真值或强度，因果与优先关系，适用范围，证据归属，
行动与效果边界，失败处理，或接受判断。

先保留承重语义，再压缩不承重的重复、礼仪性前言、无信息总结、泛泛鼓励、无关背景和不能改变判断的例子。
安全操作、教学、记忆和恢复可能让重复本身承重；是否冗余取决于它是否改变错误概率和接收效果，而不是是否出现
第二次。

这条原则同时拒绝两个极端：默认简洁不能覆盖明确的完整表达要求，“正常表达”也不是无限展开的许可证。过长会
增加注意稀释、冲突、截断、延迟和成本，并可能把主结论埋没。最好的表达是对当前关系**足够且无无效负担**：
一字不应因 token 偏好而删掉承重意义，一段也不应仅因显得充分而保留。

当模型或 harness 存在默认 verbosity 偏好时，任务表达应明确指出必须保留的事实、决定、限定、边界和下一步，
而不是只要求“详细一点”或“不要简洁”。供应商默认会变化；需要在代表任务上重测，不能把当前模型症状固化为
永恒规则。

## 检验：文本质量由接收效果证明

表达是否成立，最终要回到它承诺的变化：人能否准确复述、判断或行动；Agent 能否在边界内完成正确变换并返回
可解释证据；双受众面对同一事实变化时是否保持语义一致。机械检查可以发现断链、格式错误和字段缺失，不能单独
证明理解、语义忠实或行动正确。

检验应比较语义源、表达结果与实际接收效果，而不是只检查字数、标题密度、列表比例或某些“AI 味”词语。一个
表面缺陷若没有改变理解、判断、行动或维护成本，只值得局部修正；只有重复证据显示方法边界错误，才上升为理论或
skill 设计问题。

## 形式落地的普通检查

形式确定后，文件名和目录只做与产物相称的落地检查：名称是否指向已经定义的对象；目录是否符合拥有者、受众、
权威与生命周期；canonical source 与摘要、索引或 projection 是否分明；living 入口是否能找到它且不会把
`archive/` 当作现行设计。确需 rename 或 move 时同步更新 living 引用，不复制出第二份权威源。

路径问题没有具体失败就不触发结构重构。只有多轮真实失败证明这些判断不能由形式选择吸收，才重新调查它是否
具有不可约的独立对象。

## 与专项 skills 的关系

本文的「表达」是一般的语义保真变换。skill 载体是 skill 方法面向 Agent 的一种选择性加载表达；载体的一次
激活在具体任务中产生的行为与产物，才是 `gene-expression.md` 所说的表型。一般表达、skill 载体与激活实例
因此是包含关系中的不同位置，不能互相代称。

本理论提供共同语义根，专项 skills 分别承担不同判断：

- `concept-articulation` 在表达之前确立对象、边界、定义和名称；表达可以暴露定义不稳，但不能替它创造对象。
- `form-selection` 把受众、目的、行动、媒介和外部契约用于存在／载体形式选择，并包含普通的文件名与目录落地检查。
- `human-writing` 在既定载体内，把来源边界与人的理解关系组织为具体文章、说明或界面文字。
- `agent-expression` 在既定载体内，把任务语义组织为 Agent 可判断、可行动、可返回的内容，并校正会损伤承重语义的简洁偏好。
- `dual-audience-expression` 维护共享语义核、不同受众视图及其共同回归，防止产生第二权威。
- `agent-delegation` 使用 Agent-facing 表达形成贡献边界与返回契约，但委派拓扑、综合和责任重连不属于本理论。

这些 skill 是否应独立存在、如何拆分或合并，由 `skill-formation` 与行为证据判断，不能因为本文分了章节就直接推出。
反过来，专项 skills 对本文的实际应用若持续暴露概念、边界或推导错误，应修订理论；单次措辞不佳只修表达。

## 修订纪律

先修拥有问题的层：事实或定义错误回到语义源；存在／载体形式错误修 `form-selection`；既定载体内的组织没有承载应有关系，修相应的人或 Agent 表达；
权限和状态无法强制回到 harness 机制；实际接收效果与预期不符则形成下一轮验证。只有证据改变上述区分或推导，
才修改本理论。模型偏好、局部文风、单个路径和一次失败不取得全局重要性。
