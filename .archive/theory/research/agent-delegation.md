# Research — Agent 委派、贡献边界与整体重组

**状态：** `bounded research / no-proposal`  
**日期：** 2026-08-24  
**问题：** 一个拥有当前整体的 Agent 何时应把工作变成一个或多个有界贡献，怎样让接收者能够独立行动而不取得整体权威，以及返回的主张和证据怎样重新接回原任务？

本研究为后续委派理论与 `agent-delegation` skill 提供证据和区分。它不修改哲学序列，不创建 skill，不规定固定 Agent 数、角色枚举或拓扑，也不实现 child Run、并发锁、取消、恢复、持久队列等 runtime 机制。

## 1. 来源与证据边界

### 1.1 现行项目来源

- [`theory/philosophy.md`](../philosophy.md) 是哲学序列的唯一源。委派主要由 P09「抓住主要矛盾」、P05「具体问题具体分析」和 P11「治大国若烹小鲜」共同约束：只把真正需要另一个注意面或效果拥有者的部分分出去，并使协调扰动与任务后果相称。
- P01/P02 要求贡献来自真实对象、来源和调查，而不是来自偏好的角色名；P04 要求未知和未覆盖范围保持可见；P06/P07 约束分解后的形式足够简单、从可成的真实边界入手；P14 要求接收者看到的名称与任务实质一致；P15/P16 要求通过实际结果和结束时的回归重检判断委派是否有用。
- P12/P13 只在存在对抗、偏差或独立批评需要时提供支持：认识生产者与环境造成的相关误差，再选择隔离、反方调查或独立评审。它们不推出每个任务都要设置 adversarial reviewer。
- [`theory/gene-expression.md`](../gene-expression.md) 说明委派只能是条目在具体 Agent 环境中「冲」出的方法，不是新的哲学条目。Agent 数、拓扑、prompt 和 runtime 都属于环境化表达。
- [`theory/harness/theory.md`](../harness/theory.md) 已确立本研究的直接边界：Task 是期望改变、对象与源、环境、效果、证据和接受拥有者之间的关系；Plan 保存整体义务；拓扑是可替换方法；分解只发生在可独立知道的源、可分离效果、有界上下文、稳定接口和可重建证据处。

因此，本研究不是另造一个总协调理论，而是把 `harness.md` 的任务变换关系收窄到一个行为问题：**何时形成有界贡献，以及怎样使这些贡献不丢失整体关系。**

## 2. 从哲学序列推导委派判断

委派不是由「有几个 Agent」或「任务有几个主题」推出，而由以下环境冲撞形成：

| 环境中的冲撞 | 相关条目 | 形成的判断 |
|---|---|---|
| Main 的注意和 context 有限 × 原任务仍需一个整体拥有者 | P09、P11 | 分出去的是能减少主要注意冲突的贡献，不是整体责任；Main 保留跨贡献关系与综合 |
| 并行可降低延迟、扩大源覆盖 × 协调、token 与重建都有成本 | P05、P06、P11 | 逐案选择最小有用拓扑；简单、局部、已在手的工作保持直接 |
| 文件、主题和角色看似可拆 × 源、约束或效果实际耦合 | P01、P02、P05 | 先证明真实边界，再命名 worker；目录数量和角色名称不是分解证据 |
| 贡献者需要自主行动 × 它不能猜测整体与允许效果 | P04、P14 | 给出足以改变行动的对象、来源、边界、下游用途、未知和返回条件 |
| producer 熟悉产物 × 熟悉也会带来相关盲点 | P12、P13、P15 | 高后果语义判断可使用隔离的 reviewer；producer 自检仍有用，但不冒充独立证据 |
| 局部结果需要压缩 × 压缩会丢掉路径、限定和未知 | P02、P04、P15 | 返回不是只有结论；必须留下能重建主张与原源/效果的证据关系 |
| 一轮委派似乎成功 × 模型、任务和相邻方法继续变化 | P03、P16 | 通过代表任务、反例、回归和真实后果复议拓扑，不把首次成功永久化 |

委派由此拥有一个主要判断：

> 当前整体中，是否存在一个把注意、来源、效果或独立评审真实分开的有界贡献；若存在，怎样让接收者在不取得整体权威的情况下完成并返回可重建的主张？

## 3. 基本对象与所有权

### 3.1 整体、贡献和拓扑

**整体（whole）**不是最长的 prompt 或所有文件的集合，而是原 Task/Plan 中必须同时成立的关系：期望结果、硬约束、权威源、效果与接受边界、跨部分不变量、证据和完成条件。

**有界贡献（bounded contribution）**是整体中的一个局部变换：一个接收者可以凭命名输入和源，在明确效果边界内独立推进，并返回足以让拥有者恢复其与整体关系的主张和证据。贡献可以是调查、实现、比较、反证、机械检查或语义评审；职业角色名本身不是贡献。

**拓扑（topology）**只是贡献之间在当前环境中的执行关系：直接、顺序、并行或嵌套。它不改变 Task 的含义，也不另造接受拥有者。

### 3.2 Main Agent 是关系位置，不是万能角色

这里的 **Main Agent** 指当前持有整体关系、负责向原请求者重组结果的 Agent。一个 child 在自己收到的贡献内可以成为后续局部贡献的 Main，但不会因此取得父级整体。Main 应保留：

- 当前 Task/Plan 的结果、硬约束、权威源和接受关系；
- 哪些贡献已分出、各自依赖和效果边界、哪些义务仍未覆盖；
- 跨贡献不变量、矛盾和重连条件；
- 对返回主张采用、复核、降级为线索或拒绝的综合判断；
- 面向原请求者的一个完整候选与诚实未知。

Main 不必亲自完成每个局部细节，也不应把 child 已经完成的工作全部重做来表演「负责」。但它必须能解释为什么该贡献可以被采用，哪些来源或检查支持它，以及哪些限制仍然存在。主 Agent 的综合责任也不等于最终接受权；除非 Principal 明确委派，采纳、发布、合并或其他不可逆承诺仍属于原接受拥有者。

### 3.3 Producer、reviewer 与 acceptance 不能互换

- **producer/writer** 可以形成候选、记录自己的来源、运行机械检查和做语义自检；这些都是生产证据，不建立独立正确性。
- **reviewer** 在知道原任务、权威源、候选和验收关系的条件下形成关于适配性、缺陷和未知的独立主张。它不生产被评对象，不修复后再宣称原对象已通过，也不因「reviewer」名称获得合并、发布或接受权。
- **acceptance owner** 决定候选是否值得采纳以及残余风险是否可承担。它可以依赖 producer、机械检查和 reviewer 的不同证据，但这些证据不会自动替它做决定。

独立性是有范围的，不是绝对属性。两个 reviewer 使用同一模型、同一摘要或同一错误源，结论仍可能相关；新增角色或重复 prompt 不会自动增加独立证据。

## 4. 何时委派，何时拒绝

### 4.1 支持委派的关系

一个贡献至少应有一个具体收益，并且重组成本可承受：

1. **注意隔离：** 某个深调查或局部实现会占据大量 context，但其返回可以压缩为 Main 所需的决定与证据。
2. **延迟改善：** 两个贡献在输入、下一步判断和效果上互不等待，并行能改变真实完成时间。
3. **来源分离：** 不同源族、假设或对立解释可以独立调查，之后能按同一个整体问题调和。
4. **效果隔离：** 不同贡献拥有不相交的写入/外部效果，或环境已经提供真实的单写者/事务边界。
5. **专门能力：** 接收者拥有 Main 当前没有、且调用收益高于交接成本的工具、环境或知识面。
6. **独立语义证据：** producer bias、复杂开放判断或高后果候选使新鲜 reviewer 的发现会改变接受判断。

「用户明确要求 sub-agent」可以使委派成为请求的一部分，但仍不能取消效果安全、来源真实性和整体重组。无法安全并行的部分应顺序执行或保持直接，并解释实际边界。

### 4.2 应拒绝或收窄委派的关系

- Main 已经持有全部必要 context，局部工作很短，写贡献契约和重读返回比直接完成更贵。
- 下一步依赖上一步的语义判断，预先并行会让多个 Agent 在失效前提上工作。
- 多个写者会改同一 mutable surface、共同定义同一 contract，且环境没有可证明的效果隔离。
- 所有贡献必须共享大部分 context，压缩会丢失决定性关系；external evidence 也指出依赖密集任务是当前 multi-agent 的弱适配面。
- 只能按文件、人数、职业或宽泛主题切分，不能写出独立输入、局部变换、效果和重连证据。
- 预期收益只是「多一些意见」「让所有 Agent 都忙」或「输出更多」，却没有不同来源、假设、能力或评审关系。
- 原问题尚未形成对象或接受条件。此时应先重建 Task，而不是用 fan-out 把歧义复制到多个 context。
- 需要在提示被忽略、进程重启或并发冲突时仍保持 child identity、writer exclusion、取消、恢复或持久证据。这是 runtime/base 问题，不能靠委派 skill 的措辞保证。

拒绝不等于永远保持单 Agent。可以先做只读探针、明确接口、冻结源或串行完成承重判断，再重新评估后续贡献是否已经获得真边界。

## 5. 贡献契约：让接收者无需猜测

贡献契约不是固定 JSON schema 或角色模板，而是接收者行动所需的最小关系。一个可执行贡献通常需要回答：

| 关系 | 接收者必须知道什么 | 常见失败 |
|---|---|---|
| 整体与下游用途 | 原任务要改变什么；本贡献会被谁用于哪个后续判断 | child 把局部报告当最终答案，或优化了与整体无关的目标 |
| 对象与局部变换 | 正在处理哪个对象，要调查、改写、实现、比较还是评审什么 | 用 `researcher`、`reviewer`、文件名或主题代替实际贡献 |
| 来源与 standing | 必读材料、版本/时间、权威关系；哪些只是线索或 archive | 依据过期摘要、把历史材料当现行源 |
| 约束与非目标 | 必须保持什么；明确不拥有什么、不应扩张到哪里 | 局部 agent 顺手重构相邻体系，或把自己的问题升为主线 |
| 环境与能力 | 工作位置、可用工具、缺失能力、必要资源边界 | child 猜测路径、工具或外部访问，形成不可复现结果 |
| 效果边界 | 可以读、写或调用到哪里；谁拥有同一 mutable effect | 多写者冲突、越权外部效果、reviewer 改坏被评对象 |
| 依赖与拓扑 | 它依赖谁的哪项稳定结果；能否再委派；何时必须等待或返回 | 嵌套扩散、在失效前提上并行、重复执行同一贡献 |
| 完成与返回 | 什么算贡献完成或诚实失败；Main 需要什么形状的结果 | 返回长轨迹但没有判断，或只给结论没有证据 |
| 证据与未知 | 精确来源/变更、观察、机械检查、解释性主张、覆盖和残余未知 | 摘要漂移、把无法验证说成通过、遗漏未覆盖范围 |
| 权威 | 谁能评审、接受、合并或发布；child 的返回能建立到哪一层 | producer、reviewer 或多数票取得了不存在的接受权 |

具体任务只写会改变接收者行动的内容，不机械填满字段。低风险、短贡献可以是一段完整 prose；下游程序确实需要解析时才使用结构化载体。简短不是目标，充分也不是无限 context：与本地行动无关的 Main 历史应省略，但承重边界不能因 token 节约而消失。

## 6. 拓扑选择

### 6.1 直接执行

当整体已经局部、下一步判断或效果紧密耦合、交接无法减少注意时，由一个拥有者直接完成。直接是需要主动考虑的合法选择，不是「没有使用多 Agent」。一个 routine edit、一次短检索或依赖同一心智模型的连续推导通常落在这里。

### 6.2 顺序贡献

当前一贡献会确立后一贡献的对象、源、接口或验收条件时采用顺序。例如先调查现行契约，再由 writer 实现；先形成候选，再由 reviewer 检查 exact candidate。顺序仍可以由不同 Agent 承担，但后者必须收到已稳定的实际产物与证据，不能在预测结果上提前开工。

### 6.3 独立并行

只有下列关系同时足够清楚时并行：

- 各贡献的输入或源面可区分；
- 一个贡献不会使另一个贡献的前提失效；
- 效果不重叠，或真实机制已经强制隔离；
- Main 能按命名义务分别判断覆盖、矛盾和未知；
- 延迟、注意隔离、覆盖或独立证据收益大于协调成本。

研究型并行应给出不同来源族、假设、反例或比较对象；复制同一宽 prompt 往往只生成相关搜索与重复结论。实现型并行首先按接口和效果边界切，不按文件数量机械平均。官方编译器实验中「大量不同失败测试可并行、一个 kernel 瓶颈不可并行」正是这一边界的环境证据，而不是某种固定工程流程。

### 6.4 嵌套委派

嵌套只有在 child 执行中发现了一个新的、可独立行动且能抵偿再次交接成本的贡献时成立。它必须：

- 沿用父贡献的整体、来源和非目标，不重新定义父任务；
- 让效果与权威保持相同或更窄；
- 明确 immediate parent 是合成和重连拥有者；
- 把嵌套返回先接回父贡献，再由父贡献接回更上层整体；
- 在环境没有相应 capability、身份或恢复保证时诚实返回，而不模拟 child lifecycle。

层数不是质量，也不是天然风险；额外一层必须由更低 context 冲突、效果隔离、延迟或独立证据收益挣得。固定深度和固定 fan-out 都会把方法误写成 Plan。

## 7. Writer / reviewer 隔离

### 7.1 为什么隔离

producer 熟悉意图和实现，因此最适合做第一轮自检；同样的熟悉也会使遗漏的前提、选择性来源和既有解释在第二次阅读中继续隐形。独立 reviewer 的价值不是「更聪明」，而是**让语义判断来自一个没有参与形成候选的证据位置**。

本项目据此采用以下方法推论：

- writer 和最终 reviewer 不是同一个生产 context；
- reviewer 读取原 Task/Plan、权威源、exact candidate、相关机械证据和明确 rubric；
- reviewer 不需要 producer 的完整推理轨迹，也不应被「作者已经认为哪里正确」预设结论；必要设计理由应作为候选中的可审查主张出现；
- 最终 reviewer 默认不写被评对象。若它修复候选，它已成为新 producer，修订后的对象需要新的 review 关系；
- producer 自检、机械检查和 reviewer findings 分别标注，不能统称为一个 `verified`；
- reviewer 可以返回 `yes / no / uncertain`、风险排序和证据，但不接受、合并、发布或替 Principal 承担残余风险。

### 7.2 隔离的限度

角色名、新 context 或 read-only 权限只提供独立性的部分条件。共享错误规格、同一失真摘要、相同模型倾向或互相泄漏的修改都可能使评审相关。因而应准确表述「独立于 producer 的生成过程和写效果」，不要声称 reviewer 客观无误。

对低后果、机械可判的局部修改，测试加人检可能已足够，不必为形式完整制造 reviewer。对开放设计、概念边界、来源忠实或即将产生重大/不可逆效果的候选，独立语义评审更可能改变接受判断。

## 8. 证据怎样重连整体

sub-agent 返回的是**带证据的局部主张**，不是自动事实。Main 需要恢复如下关系：

```text
整体义务
  → 有界贡献与覆盖范围
  → delegate 的观察 / 候选 / 评审主张
  → 精确来源、变更或效果证据
  → Main 的重查、机械检查或独立 review
  → 对整体义务的 standing：满足 / 未满足 / uncertain
```

### 8.1 一个可重组的返回

根据贡献类型，返回应保留会改变下游判断的部分：

- 结论或候选是什么，它回答整体中的哪项义务；
- 实际读取的文件、URL、记录及其版本/日期，不只给二手摘要；
- 哪些是观察，哪些是机械符合，哪些是解释性判断；
- 写了什么、触发了什么效果、实际运行了哪些检查；
- 已覆盖和明确未覆盖的范围；
- 反例、冲突、失败与未知；
- Main 是否必须重读/重跑，或在什么命名条件下可以使用该主张；
- 如果该贡献被嵌套委派，证据怎样经过 immediate parent 进入当前返回。

压缩可以丢弃冗余搜索轨迹和无关中间输出，不能丢掉决定性来源、限定和未知。只返回「done」「looks good」或无出处的长总结都不能重组。

### 8.2 综合不是拼接或投票

Main 对多个返回执行的是关系恢复：按原权威源比较相互矛盾的主张，检查跨贡献不变量和未覆盖义务，必要时向现有 owner 追问或发起新的有界探针。多个 Agent 给出同一意见可能只是共享 prompt、来源或偏差，不以数量取得真理或接受权。

Main 也不应为了「亲自验证」重做每次局部探索。重查强度按主张后果、来源可追溯性、证据质量、可逆性和独立 review 需求确定：低后果事实可抽查或按明确来源采用；承重概念、共享 contract、重大效果和不可逆决定需要更强的直接检查与接受关系。

## 9. 过度委派与局部问题被放大

### 9.1 常见失真

1. **新近性放大：** 一个刚发现的具体问题因描述最详细而被误当作整体主线。
2. **负责范围放大：** 每个 specialist 自然优化自己收到的局部对象，随后把局部完整性写成全局必要性。
3. **fan-out 伪共识：** 相同 prompt 或相关来源产生多份近似报告，看起来像独立证据。
4. **输出量替代影响：** 长报告、更多文件或更多发现被当成贡献价值，压过更短但承重的义务。
5. **协调自我繁殖：** 为管理 delegates 再创建 coordinator、reviewer 和状态文档，新增对象的成本超过原工作。
6. **分解锁定：** 初次切分成为身份或目录，后续证据显示耦合时仍不愿恢复直接/顺序执行。
7. **无限研究：** 没有停止条件的 sub-agent 持续追踪边缘来源，无法形成可接受的 bounded unknown。

Anthropic 的 multi-agent Research 复盘也记录了简单查询生成大量 sub-agent、无止境搜索和互相用更新分散注意的早期失败，并因此强调按问题复杂度缩放努力和明确边界。这是环境证据，不是要求本项目采用其数字化配额。

### 9.2 比例校正

Main 在综合前把每个发现重新放回整体，比较：

- 它影响哪个原始义务或接受条件；
- 发生频率与影响范围有多大；
- 后果是否可逆、是否真的阻塞主结果；
- 证据是观察、单次判断还是独立/回归支持；
- 最小修复落在局部表达、现有 skill、理论还是 runtime；
- 修复和协调成本是否与收益相称。

一个问题不会因为被某个 sub-agent 专门研究、出现多次同源报告、名称很具体或讨论篇幅很长而自动提高全局权重。委派契约应明确 non-goals 和下游用途；返回应把发现标为局部主张，而不是擅自重写整体优先级。最终优先级仍由 Main 依据原 Plan 的主次关系综合。

## 10. 反命题、反证与边界案例

### 「多 Agent 天然比单 Agent 好」

反证：官方研究把改善集中在高价值、重并行、广度搜索任务，也报告显著 token 成本和依赖密集领域的不适配。近期编译器实验进一步显示，共享一个瓶颈时增加 Agent 只会重复和冲突。可接受的较弱结论是：真实并行或隔离能在特定任务上换取收益。

### 「为了保持整体，Main 应该自己完成所有工作」

反证：独立 context 对大范围研究可以降低 Main 的注意污染，专门能力和并行来源也可能明显提高覆盖。整体拥有是保留关系、综合和接受边界，不是垄断所有局部劳动。

### 「只要给每个 Agent 不同角色，就已经分工」

反证：`researcher`、`writer`、`reviewer` 没有命名对象、来源、效果和返回。外部复盘也显示宽泛短指令会导致重复搜索和覆盖缺口。角色最多是帮助理解的表面形式，不能代替贡献契约。

### 「独立 reviewer 的意见可以作为最终真相」

反证：reviewer 仍可能受错误源、模型相关性和 rubric 缺陷影响；Agent eval 资料也要求组合不同 grader 并由人校准。review 是给接受拥有者的语义证据，不是接受本身。

### 「Main 只要把报告拼起来即可」

反证：partial claims 可能覆盖重叠、前提冲突或共同遗漏。没有跨贡献不变量与来源 standing 的重组，拼接只制造更长文本。综合必须回到原 Task/Plan。

### 「给 child 完整上下文最安全」

反证：过多无关历史会稀释主要对象并复制 Main 的偏差；过度压缩又会丢承重关系。真实目标是 receiver-specific 的充分 context：保留会改变本地行动与返回的部分，并提供回到权威源的路径。

### 「并行写入冲突可以靠更强 prompt 避免」

反证：当单写者、事务、取消、恢复或 child identity 必须在模型不遵守时仍成立，它们属于 runtime/base。skill 可以教选择边界，不能强制硬属性。

## 11. 行为验证建议

后续 `agent-delegation` theory 和 skill 应使用相同任务、材料、模型、工具和 harness 比较 direct baseline 与 delegated treatment；无法隔离变量时只声称观察到行为，不声称由 skill 因果改善。根据 Agent eval 的一手建议，关键任务使用多次 trial、干净环境和正反平衡集，并主要评价最终产物、证据和效果，而不是固定工具调用路径。

### 11.1 代表任务

- **应并行：** 多个一手来源族可独立调查，要求覆盖、来源质量、冲突与未知重连。
- **应直接：** 一个短局部任务，Main 已持有完整 context，交接成本明显更高。
- **应顺序：** 后续实现必须等待前置 contract/定义被实际确立。
- **拒绝多写者：** 两个候选贡献会修改同一 contract 或 mutable file surface，且没有效果隔离。
- **独立 review：** writer 形成候选后，新 context reviewer 根据相同源检查；验证 reviewer 不修改、不接受，writer 自检不冒充独立 review。
- **嵌套边界：** child 发现新贡献；一例应再委派，一例应自己完成或返回，检查权限变窄和证据经 immediate parent 回接。
- **局部放大：** 多个 specialist 返回严重程度不同的问题，验证 Main 按原义务、影响与证据排序，而不是按报告长度或数量排序。
- **no-proposal：** 调查没有形成真实切分收益，正确结果是保持直接或明确未知，不为了展示能力创建 swarm。

### 11.2 分开观察的接口

1. **选择：** 是否在应委派时形成贡献、在反例中保持直接或顺序。
2. **契约：** 接收者能否从局部表达恢复对象、来源 standing、边界、效果、下游用途和返回。
3. **执行：** contributors 是否重复、越界、互相污染输入或修改同一效果。
4. **返回：** 是否保留精确证据、覆盖、未知和需要 Main 复核的条件。
5. **重组：** Main 是否恢复跨贡献不变量、解决矛盾、保持未覆盖义务，而非拼接或投票。
6. **评审：** producer 自检、机械检查、独立语义 review 和人类接受是否保持不同主张。
7. **比例：** 是否因新近性、agent 数、局部角色或输出量扭曲整体主次。
8. **成本：** attention、延迟、token、协调与冲突成本是否换来了可观察收益。

机械检查只能确认命名文件、effects、返回字段或测试等显式事实；语义 reviewer 判断任务忠实、切分合理、证据充分与局部放大；人类决定收益是否值得成本。没有 matched baseline 不声称委派改善，没有反例不声称拒绝边界成立，没有回归不声称稳定。

## 12. Archive 的吸收、修订与拒绝

### 吸收

- Main 保留 whole outcome、综合和最终响应责任；child 只拥有有界贡献。
- 分解从独立来源、效果、上下文和证据开始，不从 Agent 数、文件数或角色清单开始。
- receiver-facing contract 需要下游用途、局部变换、non-goals、效果边界与 evidence-bearing return。
- writer 自检与独立 reviewer 分离；reviewer 不能接受或产生未授权效果。
- 证据必须经过 immediate parent 逐层重连；分歧回到源和整体，不以投票处理。
- direct、sequential、parallel、nested 是条件化方法，Plan 不绑定 provider、worker count 或固定深度。

### 修订或拒绝

- 不继承旧 skill 的 Primary/Supporting 固定格式与旧 P-ID 血统；本研究已从现行哲学序列重新推导。
- 不把 `native delegate`、`injected sub-worker`、persistent child Run、Work Cell 或某个计划投影写进通用委派理论。这些属于具体 harness/runtime mapping。
- 不把「一个贡献对应一个 child Run」「共享 worktree 单写者」写成 prompt 保证。需要强制时由未来 runtime/base 设计拥有，本轮只命名理论边界。
- 不预设 Main 必须等待、同步批次、固定数量、固定深度或固定 reviewer 数。
- 不保留旧 `agent-communication` 式的大容器。概念、形式、Agent 表达和委派可以交叉 review，但各自拥有不同主要判断。
- 不把 archive 中一次 forward probe、单个项目习惯或供应商案例当成跨环境的 causal proof。

## 13. No-proposal 与未决问题

本研究的 `no-proposal` 有三层含义：

1. **不提议新增或修改哲学序列条目。** 现行 P01/P02/P04/P05/P06/P07/P09/P11/P12/P13/P14/P15/P16 已足以生成委派方法。
2. **不提议 runtime。** child identity、并发排他、effect containment、取消、恢复、retry 和持久证据需要另有真实失败与硬属性论证。
3. **不自动授权新 skill。** 本研究支持先写委派理论，再由项目自己的 `skill-formation` 判断是否、怎样形成 `agent-delegation`；其触发与行为仍需独立验证。

仍待前向行为研究：

- 不同模型和 harness 对贡献契约长度、prose/结构化表达和嵌套说明的恢复差异。
- Main 在不重做全部局部工作时，怎样选择足够而不过量的 recheck；应按后果与证据 standing 形成条件，而不是统一比例。
- writer/reviewer 隔离中，哪些 producer rationale 是理解候选所必需，哪些会造成锚定；需要 matched review probe。
- 当多个 reviewer 共享模型或来源时，怎样准确声明独立范围并观察相关失败。
- 并行研究何时真正降低 Main attention，何时只是把综合成本推迟到返回时。
- 对局部问题放大的比例检查能否稳定改变优先级，还是只增加一段不会影响行动的提示。
- capability 提升后，哪些委派指导已成为冗余；应通过 direct-vs-delegated ablation 和回归判断。

## 14. 结论

委派不是把一个任务切成更多 prompt，而是把整体中的一个真实局部变换交给另一个行动者，同时保持它与原 Task/Plan 的关系可重建。最短有效链是：

```text
重建整体义务与接受关系
→ 识别能减少注意、延迟、效果冲突或 producer bias 的真实贡献边界
→ 比较 direct / sequential / parallel / nested 的收益与协调成本
→ 给接收者充分而有界的贡献契约
→ 返回局部主张、精确证据、覆盖与未知
→ Main 按原源与跨贡献不变量重组
→ 独立 review 在需要时提供语义证据
→ 原接受拥有者决定是否采纳
```

没有真实边界时保持整体；没有可重建证据时把返回当线索；需要硬保证时归还 runtime；局部发现没有改变原义务时不把它抬成主线。Main 保留的是整体关系，不是所有劳动；child 获得的是贡献权，不是整体权威。
