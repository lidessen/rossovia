# Research — 表达与形式

**Status:** `bounded research / no proposal`  
**Date:** 2026-08-24  
**Question:** 同一份真实语义怎样根据受众、目的、行动和媒介选择合适的表达形式；面向人、面向 Agent、同时面向两者时分别需要什么；简洁、verbosity 与 token 成本应处在什么位置？

本笔记只为后续理论与 skill 设计提供可追溯证据。它不采纳理论，不创建 skill，不修改哲学序列，也不把 archive 的旧结论恢复成现行设计。现行术语以 [`theory/gene-expression.md`](../gene-expression.md) 为准；archive 只作历史证据。

## 发现一：形式由使用关系共同决定，不由主题或受众单独决定

Google 要求先回答读者已经知道什么、为什么读、读后应理解或能够完成什么；Diátaxis 则显示，同一个技术对象在“学习 / 工作”与“行动 / 认知”位置不同，会需要不同形式。Microsoft 的扫描与导航建议进一步表明，阅读媒介和使用情境会改变内容实现。

由此可形成一个待理论化的四项判断框架：

| 决定项 | 要回答的问题 | 它主要改变什么 |
|---|---|---|
| 受众 | 谁在接收；已有何种知识、词汇、权限和判断能力？ | 术语解释深度、默认前提、举例和语气 |
| 目的 | 表达为什么现在存在；希望接收者理解、学习、判断、记忆还是完成什么？ | 取材边界、重点与整体推进 |
| 行动 | 接收者下一步实际要做什么；是阅读、比较、决策、执行还是让程序解析？ | 论证、步骤、表格、契约、schema 或其他操作形态 |
| 媒介 | 内容经何种载体到达；如何被阅读、检索、调用、更新与验证？ | 篇幅、导航、层级、可扫描性、结构化程度和可维护方式 |

“目的”与“行动”不能合并：一份理论说明的目的可以是改变理解，却没有即时操作步骤；一份 API reference 的即时用途是支撑工作中的查询，却不替使用者决定最终业务目的。四项也不是固定模板，而是防止单因解释的最小问题集。

### 反证与边界

- 有些形式首先受外部契约约束，例如 JSON schema、法律表单、论文投稿格式；这时媒介或验收方先限制候选形式，但仍不能代替内容与受众判断。
- Diátaxis 的 reference 明确主要跟随被描述对象的结构，不完全跟随某一个用户任务。这反驳“所有形式都只按受众目标组织”的强版本。
- 同一产物可能服务多个真实需要，混合形式并非必然错误；只有边界混淆使接收者无法学习、查询或行动时，才有拆分依据。
- “最小形式”不等于“最短文本”或“最少文件”。最小指不增加无主的权威、重复维护或无用机制；有时完整论证、长 reference 或多个有明确关系的视图才是最小可用解。

## 发现二：面向人的表达需要恢复关系，但必须先受真实语义约束

人的写作至少涉及两类不能互相替代的正确性：

1. **可以说什么。** 事实、定义、因果、否定、范围、程度、归属和未知必须能回到来源。Google 对可核验主张的要求支持这条边界。
2. **怎样使这个人理解或行动。** 读者已有知识、阅读目的、场合和媒介决定解释深度、信息顺序、论证推进、例子和语气。Google、Microsoft 与 Diátaxis 都从不同侧面支持这点。

因此，“自然”“不像 AI”“好读”不能成为脱离来源与关系的独立风格目标。archive 探针尤其显示，明确读者与预期变化能改善文档推进，却也会诱发模型补全更顺滑但未经支持的动机和连接。关系为表达提供方向，来源为表达划定可说边界；两者缺一都可能得到表面自然、实际失真的文本。

对于人的长文，段落之间通常需要可恢复的关系，例如因果、对比、限定、递进、例证或结论；对于 reference、词表、变更记录等查询型内容，条目可以有意保持独立。不能把“连续 prose”或“清单”任一方设成默认优越形式。

### 反证与边界

- 短按钮、错误消息、日志字段和表单标签没有完整文章式推进；它们仍然是面向人的表达，但主要受局部行动与界面空间约束。
- 强调 writer voice 可能把项目事实变成个人姿态。没有足够同作者、同媒介、同受众的材料时，只能做任务局部的语气适配，不能宣称恢复了一个稳定人格。
- 表面模式只能用于末端诊断。标题、列表、短句、破折号、术语或正式语气都可能在特定媒介里正确；不存在一张可靠的“AI 味禁用词表”。

## 发现三：面向 Agent 的表达是行动条件，不只是更结构化的人类文章

OpenAI 当前指引要求为复杂任务保留 domain context、hard constraints、approval boundaries 与 success criteria；Anthropic 要求清晰、具体地说明目标形式和约束，并在多文档场景标明来源；Google 的 LLM 写作指导要求给出 role、audience、document type 与 purpose。这些资料共同支持：Agent-facing 内容必须让接收 Agent 能在真实上下文里判断和行动，而非只让文字“看起来清楚”。

一个 Agent-facing 表达至少可能需要以下承重语义；具体任务只保留会改变行动的部分：

- 对象与目标：正在处理什么，什么结果才算目标而不是邻近产物；
- 来源与事实状态：哪些是事实、指令、候选、未知或仅供参考，来源之间谁更权威；
- 允许效果与权限边界：能读、能写、能执行到哪里，何时必须停止或请求确认；
- 判断与成功标准：结果要满足什么，什么证据可观察，谁有最终接受权；
- 输入与返回：需要读取什么，返回给谁，以何种可消费形式返回；
- 失败语义：缺信息、冲突、验证失败或能力不足时，应该显式暴露什么。

这并不意味着所有 Agent 指令都要写成 schema。下游程序必须解析时，结构化输出有真实价值；需要语义判断、解释与取舍时，完整 prose 可能更能保留关系。结构化与自然语言也是形式选择，不能先验代表“给 Agent 看”。

### 反证与边界

- 当前模型能够从上下文推断许多低风险细节。把所有可能情况都写进 prompt 会重复、冲突、稀释重点，并增加上下文成本。OpenAI 当前资料甚至报告，部分 coding-agent 评估中更精简的 prompt 同时提高分数并降低 token；结果随 workload 变化，必须用代表任务验证。
- 明确要求与结构只能改善可控性，不能把语义判断变成机械保证。输出符合 schema 也不等于事实、建议或接受结论正确。
- Agent-facing 表达不拥有执行状态与最终权威。需要强制状态转换、不可绕过的权限或机械验证时，问题可能属于 runtime，而不是继续加 prompt。

## 发现四：双受众应共享语义源，不必共享一种表面形式

给人看的理由与给 Agent 的行动指令会有不同信息顺序和表现形态，但它们不能各自维护一套对象定义、事实状态、约束和权威关系。否则一次修改后就可能出现两个都自称现行的版本。

本轮可支持的较弱结论是：

- **共享语义核**：对象身份、正式定义、关键术语、事实状态、硬约束、权威和接受边界只设一个明确的 canonical source。
- **按受众表达**：人的视图可以展开背景、理由、例子和阅读导航；Agent 的视图可以突出触发、输入、边界、行动和返回。
- **显式派生关系**：两种表达分开时，至少一方应声明其来源，或由可重建过程生成；共同片段可复用而不是手工复制。Microsoft Learn 的 include 是这一做法的一个具体实现例，而非唯一实现。
- **共同回归**：同一事实或约束改变后，检查两类受众得到的语义是否仍一致；表面措辞不必相同。

“单一语义源”是当前证据支持的设计假设，不是已经被跨项目实验确立的定律。它也不等于“一个大文件同时塞进所有人类说明和所有 Agent 指令”。如果共用物理文件让人难以阅读、让 Agent 加载过多无关上下文，应该保留一个事实源并派生或链接不同视图。

### 反证与边界

- 某些短内容为了局部可用性会被有意复制；只要存在明确同步机制、风险低且收益可证，物理重复不必一律禁止。
- 人类接受的解释可能包含价值判断与讨论历史，而 Agent 的执行入口只需要已采纳约束；二者不应被错误压平成完全相同的正文。
- 共享源不能自行解决错误源的问题。若 canonical source 本身未经验证，统一只会让错误更一致。

## 发现五：简洁和 token economy 是成本约束，不是语义裁判

OpenAI 当前明确警告，宽泛的 “be concise” 或 “keep it short” 可能令回答过短，并建议压缩时先说明必须保留的事实、决定、限定和下一步。Anthropic 当前也指出，较简洁的模型可能为效率略过详细总结，需要任务方明确所需输出。另一方面，Google 与 Microsoft 的写作材料都支持删除无关信息、帮助扫描；OpenAI 的 lean-prompt 观察还说明，减少重复指令可能同时改善质量和成本。

因此，证据不支持“越长越好”，也不支持“越短越好”。更稳妥的候选规则是：**先确定完成理解、判断或行动所需的承重语义，再压缩不承重的表达。**

本轮把“承重表达”暂定为：删除后会改变对象身份、主张真值或强度、因果与优先关系、适用范围、证据归属、行动边界、失败处理或接受判断的内容。它常包括：

- 定义、关键事实与必要区别；
- 否定、模态、范围、例外和未知；
- 支撑结论所需的证据与归属；
- 目标、约束、权限、下一步和验收条件；
- 让段落或步骤不能被任意换序的关键关系。

压缩可以优先移除重复陈述、礼仪性前言、无信息的总结、泛泛鼓励、与当前目的无关的背景、不能改变判断的例子和由标题再次复述的句子。这里的顺序只是待测试假设；不同媒介仍可能需要礼貌、冗余或重复来承担安全、记忆和可访问性。

### 反证与边界

- 长文本会增加延迟、成本、截断、注意稀释和冲突风险，也可能把主结论埋没。保护承重表达不能成为无限展开的许可证。
- 安全操作、教学和高风险交接有时需要有意重复；重复是否冗余取决于它是否改变错误概率和恢复能力。
- 当前供应商的 verbosity 默认会变化。后续 skill 若编码具体模型症状，应先观察运行环境，而不是把 2026-08 的文档固化成长期人格判断。

## 形式落地时的普通检查

文件名与目录结构属于形式落地后的常规检查，不是本研究的独立对象。一个产物确定要存在时，顺手回答即可：

1. 文件名是否准确指称已经定义的对象，而不是沿用历史阶段名或过宽标签？
2. 目录是否与内容的拥有者、受众、权威和生命周期一致？
3. 是否只有一个 canonical source；副本、索引、摘要或生成结果是否明确为引用或 projection？
4. living 入口是否能找到它，且不会把 `archive/` 误认成现行设计？
5. rename / move 若确有必要，是否同步更新 living 引用并避免制造第二份源？

没有具体失败就不为路径制造重构。只有后续多轮证据显示这组判断反复出现、不能被形式选择吸收，才重新调查它是否拥有不可约的独立问题。

## 综合假设：先保真，再关系化，再实现形式

archive 曾提出一条从来源边界到表面残留的因果链。本轮公开证据分别支持其中若干节点，但没有证明严格单向或固定阶段。可供后续行为实验使用的较弱版本是：

```text
语义对象与来源边界
  → 受众、目的与预期行动
    → 媒介和载体
      → 结构、推进与局部表达
        → 模型／harness 默认的校正
          → 表面修订与落地检查
```

实际写作可以往返迭代。例如媒介限制可能迫使重新缩小目的，行为测试也可能暴露对象尚未定义。这个顺序的价值是诊断时优先寻找上游缺口，不是强迫每个短任务展示一套工作坊流程。

## 与现行哲学序列的候选关系

以下只记录后续 theory agent 可检验的血统，不构成理论采纳：

| 研究发现 | 候选条目 | 待检验的“冲” |
|---|---|---|
| 先恢复真实对象与来源，再表达 | P01 实事求是、P02 没有调查没有发言权 | 来源事实与表达目的相冲，形成 claim boundary 与未知披露 |
| 形式依受众、目的、行动和媒介而变 | P05 具体问题具体分析、P08 问题边界 | 同一语义在不同使用环境中冲出不同载体与组织 |
| 简洁服从承重语义，过长也要损 | P06 为学日益为道日损、P09 抓住主要矛盾、P11 治大国若烹小鲜 | 完整与压缩相冲，形成按重要性保留、按成本删减的方法 |
| 名称、事实和行动相接 | P14 名不正则言不顺 | 对象定义与实践主体的理解／行动相冲，形成可执行表达 |
| 表达是否有效需真实任务检验 | P15 实践是检验真理的唯一标准、P16 慎终如始则无败事 | 文本意图与实际理解／行动相冲，形成行为 probe 与回归 |

“给人”“给 Agent”“双受众”暂看是同一表达问题在不同环境中的三种冲撞，不据此新增哲学条目。

## 反方总检视

1. **关系决定论过强。** 明确受众和目的不能替代事实核验，archive 已观察到更自然的无据连接。
2. **四项框架可能仍不全。** 法规、组织权威、可访问性、翻译、安全和版本兼容也会决定形式；它们应作为具体环境约束进入，而不是先扩成一张万能表。
3. **单一语义源有集中错误风险。** 它减少漂移，却放大源错误；必须保留验证与接受，而不能把 canonical 等同于真。
4. **Agent 与人的区别可能被夸大。** 两者都需要真实语义、上下文与合适形式；Agent-facing 内容不是天然更短、更硬或更列表化，人类内容也可能需要精确契约。
5. **反 token 扭曲可能反向制造冗长。** 如果“正常表达”被理解为必须充分展开，Agent 会把次要背景当承重内容。只有相同任务上的理解、行动、完整性、成本和错误率对照能决定取舍。
6. **供应商建议会漂移。** OpenAI、Anthropic 当前行为是环境证据，不能成为稳定哲学源；新模型和新 harness 必须重测。

## Disposition

### Adopt as research basis

- 形式选择同时检查受众、目的、行动和媒介，而不从“文章 / skill / schema”等偏好名词出发。
- 面向人的表达先受来源边界约束，再恢复写作者—读者—场合—目的关系。
- 面向 Agent 的表达以能否正确判断和行动为准，显式保留会改变行为的事实、边界、返回与验收。
- 双受众共享语义源但允许不同视图；统一语义不等于统一物理文件或统一文风。
- token 和篇幅是成本；压缩不得改变承重语义，增加篇幅也必须有任务收益。

### Revise from archive

- 保留“来源 → 关系 → 形式 → 表面”的诊断方向，但降级为可往返、待行为实验的假设，不宣称已证明固定因果链。
- 保留 form-guidance 的“不要先选喜欢的名词”和最小真实形式经验；不继承其已经分配好的 skill、runtime、artifact-organization 边界。
- 保留 document-writing 的来源边界、写作关系和整体验证；不继承旧 P-ID 血统，也不把一个旧 skill 直接恢复成现行答案。

### No proposal

- 不提议新增、删除或改写哲学条目。
- 不提议创建 expression、writing、form-selection 或 dual-audience skill；是否成 skill 由后续 `skill-formation` 理论与行为证据裁决。
- 不提议独立的文件名／目录理论或 skill，也不提议本轮重命名、移动任何 living 文件。
- 不提议统一字数、固定模板、禁用词表、默认 Markdown 密度或统一 verbosity。
- 不提议让人类文档和 Agent 指令共用一个大文件；只保留“同源且可重建”的待验证方向。
- 不提议用 prompt 代替 schema、runtime、机械验证或人类接受权。

## 后续验证问题

- 相同源材料下，四项关系包是否比只给主题或只给受众稳定改善形式选择？
- 加入来源边界后，是否能保留关系化写作的连贯性，同时减少无据因果和动机补全？
- 明示“必须保留的承重语义”是否比笼统“不要太简洁”更能抵抗上层 verbosity 偏置？
- 双受众采用共享语义核与分层视图时，是否比两份手工正文减少漂移，同时不增加 Agent 上下文负担？
- `form-selection` 能否自然覆盖文件名和落点检查；若能，就不应再形成独立方法。
