# Agent 委派

> 本文是 living theory。它吸收 [`theory/research/agent-delegation.md`](research/agent-delegation.md)
> 的研究结论，解释现行哲学条目在多 Agent 环境中怎样冲出委派方法。它不新增或改写哲学条目，不规定
> 固定 Agent 数、角色、拓扑或贡献格式，也不实现 child Run、并发、取消、恢复等 harness base 机制。

## 定位与血统

**主血统：** P05（分析·特殊性）、P09（解决·主次）、P11（解决·成本）。

**支持：** P01（认识·来源）、P02（认识·证据）、P03（认识·深化）、P04（认识·已知边界）、
P06（分析·简化）、P07（分析·入手点）、P12（对抗·知）、P13（对抗·应）、P14（解决·表达）、
P15（检验·手段）、P16（检验·时点）。

这些条目在 Agent 环境中形成几组冲撞：Main 的注意和 context 有限，但原任务仍需要一个整体拥有者；并行、
隔离和专门能力可能扩大覆盖或降低延迟，但交接、token、冲突和重组都有成本；贡献者需要足够上下文自主行动，
却不能因此取得整体权威；局部结果必须压缩返回，压缩又不能切断主张与来源、效果和未知的关系；producer 最熟悉
候选，熟悉同时也会形成相关盲点。委派方法由这些冲撞生成，不由可用 Agent 数或预设角色生成。

## Thesis：委派是保持整体关系的有界转交

委派不是把任务切成更多 prompt，也不是让更多 Agent 同时工作。它把原任务中的一个局部变换交给另一个行动者，
使其能够在明确来源和效果边界内独立推进，同时让返回仍可接回原任务。分出去的是**有界贡献**，不是整体责任。

```text
整体义务与接受关系
      ↓ 识别真实边界
有界贡献 × 接收者环境
      ↓ 局部行动
候选、观察、证据与未知
      ↓ 重连与综合
一个面向原任务的整体候选
```

整体、贡献和拓扑是不同对象。**整体**是期望结果、硬约束、权威源、效果与接受边界、跨部分不变量、证据和
完成条件必须同时成立的关系，不是最长的 prompt 或全部文件。**贡献**是其中可由一个接收者独立推进、并以证据
重连的局部变换。**拓扑**只是这些贡献在当前环境中的执行关系；它不能改变 Task 的含义或创造新的接受拥有者。

因此，委派是否成立取决于转交后能否同时保持两件事：接收者无需猜测即可行动，Main 无需重做全部工作即可恢复
局部结果与整体的关系。缺少前者只是模糊交代；缺少后者只是把注意和责任一起丢了出去。

## Main 拥有整体关系，不垄断劳动

Main Agent 是一个关系位置：当前持有整体、负责把局部贡献重组并向原请求者形成一个候选的 Agent。一个 child
可以在自身贡献内再成为局部 Main，但这不会把父级整体或接受权一并下放。

Main 保留原 Task/Plan 的结果、约束、权威源和接受关系，知道哪些义务已分出、哪些仍未覆盖，并拥有跨贡献冲突、
不变量与重连条件的综合判断。它不必亲自完成每项调查和实现，也不应为表演负责而把局部工作全部重做；它必须能
说明为什么采用、降级为线索或拒绝某项返回，以及最终还有哪些未知。

这种综合责任不同于最终接受权。除非 Principal 明确委派，采纳、合并、发布或其他不可逆承诺仍属于原接受拥有者。
Main 能形成完整候选，不能仅凭其位置证明候选已经被接受。

## 分解只发生在真实贡献边界

文件数量、主题数量、职业角色、可用 Agent 数和输出篇幅都不是分解证据。一个边界真实，是因为局部贡献至少在
来源、注意、下一步判断、效果或独立评审位置上能够分离，并且返回后可以重组。常见的真实收益包括：隔离会淹没
Main context 的深调查，并行处理互不等待的来源面，调用 Main 不具备的环境或能力，把不相交的效果交给不同拥有者，
或让未参与生产的人形成独立语义证据。

收益必须抵偿交接和重组成本。Main 已持有全部必要 context 的短任务，下一步依赖前一步语义判断的工作，共享同一
mutable surface 的多写者，以及必须携带大部分共同关系才不会失真的问题，通常应保持直接或顺序。原任务对象、
来源和接受条件尚未恢复时，fan-out 只会把歧义复制到多个 context。

真实边界也可以在工作中变化。先调查可能确立一个原先不存在的接口，后续才适合并行；一个共同瓶颈可能使已经
分出的工作重新耦合。分解不是身份或目录，一旦证据改变，恢复整体或改成顺序不是失败，而是 P05 对当前特殊性的
重新判断。

## 贡献契约保持行动与重连

有界贡献需要一个接收者可用的关系表达，而不是固定字段表。它应让接收者恢复：整体要改变什么、本贡献服务哪个
下游判断、局部对象和变换是什么、哪些来源有何 standing、必须保持与明确不做什么、可以造成哪些效果、依赖什么、
怎样算完成或诚实失败，以及应返回哪些证据、覆盖和未知。

具体表达只保留会改变本地行动或下游综合的内容。把 Main 的全部历史倾倒给 child 会稀释对象并复制偏差；只给
角色名、主题或一句目标则迫使 child 猜测权威、边界和成功含义。充分 context 因而是 receiver-specific 的：能让
接收者独立判断，又能指回权威源，不以 token 节约删掉承重关系，也不以“完整”为由复制无关上下文。

贡献契约只表达效果边界，不创造效果权威。它可以要求只读调查、限制写入面或说明 reviewer 不修改候选；若这些
属性必须在提示被忽略、并发冲突或进程恢复后仍成立，就需要 harness base 的真实强制，而不是更强措辞。

## 拓扑服从贡献之间的真实关系

直接、顺序、并行与嵌套是可替换方法，不是 Plan 原语或质量等级：

- 整体局部、判断或效果紧密耦合时，直接执行保持关系最少失真；
- 后一贡献的对象、接口或验收取决于前一贡献的实际结果时，顺序承接真实依赖；
- 输入、前提和效果可分，Main 能分别判断覆盖、冲突和未知时，并行才会把额外 context 换成延迟、覆盖或独立性收益；
- child 在执行中发现新的真实边界，且收益高于再次交接成本时，嵌套才成立；返回先接回 immediate parent，再逐层
  接回整体。

额外 Agent、层数和 fan-out 都必须由当前关系挣得。复制同一个宽 prompt 通常产生相关搜索和伪共识；按文件机械
平均可能掩盖共享 contract 或效果冲突。Plan 保存的是结果、约束、依赖、证据、接受和重连义务，不绑定 provider、
worker 数、固定深度或某种 swarm 载体。

## Producer、reviewer 与接受者保持分离

Producer/writer 可以形成候选、记录来源、运行机械检查并做语义自检；这些是生产证据，不是独立正确性。
Reviewer 的价值不在角色名称，而在它没有参与 exact candidate 的形成、没有被授予被评对象的写效果，并能依据
原任务、权威源、候选和验收关系形成新的语义主张。

Reviewer 若直接修复候选，就成为新 producer；修改后的对象需要新的 review 关系。Reviewer 可以指出缺陷、风险、
证据与 `yes / no / uncertain`，不能因评审身份取得合并、发布或接受权。低后果且机械可判的局部修改不必为了
形式完整制造 reviewer；概念边界、来源忠实、开放设计或重大效果更可能需要独立语义证据。

独立性始终有范围。新 context、只读效果和作者隔离能减少一部分相关性，但共享错误规格、同一失真摘要或相同模型
倾向仍会产生共同盲点。多个 reviewer 的一致也可能只是相关证据，不能以票数代替来源比较和接受判断。

## 证据重连使局部贡献回到整体

Child 返回的是带 standing 的局部主张，不是自动事实。可重组的返回应区分观察、机械符合、解释性判断与候选，
保留精确来源或实际变更、覆盖和未覆盖范围、失败、反例、未知，以及 Main 必须重读或重跑的条件。压缩可以删去
冗余搜索轨迹，不能切断决定性来源、限定和效果证据。

Main 的综合不是拼接报告或多数投票，而是恢复关系：把每项返回放回原义务，按权威源处理冲突，检查跨贡献不变量
和共同遗漏，并决定证据足以支持哪种强度的主张。重查强度服从后果、可逆性、来源可追溯性和证据质量；低后果且
有精确来源的观察可抽查采用，承重 contract、概念、重大效果和不可逆决定需要更强的直接检查与接受关系。

嵌套委派不改变这项义务。每一层 immediate parent 都拥有当前贡献的合成与证据重连，不能把孙级无出处的摘要
直接抬到顶层。链路中任何一层无法恢复来源或效果时，顶层最多把结果当线索。

## 比例：局部发现不取得全局主次

委派会放大 specialist 的注意，也容易放大其对象的重要性。新近、具体、写得最长或被多个相关 Agent 重复报告的
问题，不因此成为整体主线。每项发现回到原 Task/Plan 后，仍要按它影响的义务、发生范围和频率、后果与可逆性、
证据强度以及修复和协调成本判断位置。

贡献者拥有发现和论证局部问题的责任，不拥有重写整体优先级的权威。贡献表达应给出 non-goals 与下游用途，返回
应如实标记局部 standing；Main 依据 P09 恢复主次。如果问题只改变一次措辞、一个文件或现有 skill 的局部表达，
就修拥有它的层；只有重复证据改变不可约判断时，才上升到 skill 或理论。专门研究本身不是升级证据。

过度委派也接受同样校正：为管理 delegates 不断新建 coordinator、reviewer、状态文档或目录，如果协调对象的成本
超过原工作，就没有产生净贡献。无停止条件的研究、为了让所有 Agent 忙而 fan-out，以及因初次切分形成身份后拒绝
合并，都把方法变成了目的。

## 方法表达与 harness base 的边界

委派理论和未来 skill 可以教 Agent 识别贡献边界、选择拓扑、表达接收者 context、隔离生产与评审、返回证据并
综合。只要这些方法改变而同一 Task、Run、effect、evidence 和 acceptance 契约仍保持真实，它们属于方法表达。

必须在模型不遵循提示、供应商替换、并发、进程重启或恢复后仍成立的 child identity、单写者、事务、取消、效果
隔离、因果同一性和持久证据，属于 [`harness/theory.md`](harness/theory.md) 所说的 base 或适配器。一次越界或提示失败可以暴露
方法问题，不能单独授权新 runtime；反之，硬属性缺失也不能靠委派 skill 无限补 prompt。

委派与 [`expression.md`](expression.md) 相邻但不重叠。Agent-facing 表达负责让一个贡献可判断、可行动、可返回；
委派拥有的是贡献是否应分出、贡献之间怎样关联以及返回怎样重组。概念表达负责对象、定义和名称，形式选择负责
载体与普通落点；它们可以改善贡献契约，不能替代整体与权威关系。

## 检验与修订纪律

委派方法是否成立，要比较 direct baseline 与 delegated treatment 的最终产物、证据、效果和成本，而不是工具调用
路径、Agent 数或输出量。正例要观察真实并行、隔离或专门能力能否产生收益；反例要观察方法能否保持直接或顺序；
回归还要覆盖多写者冲突、writer/reviewer 隔离、嵌套重连、共同遗漏和局部问题放大。没有 matched baseline，
不声称收益由委派造成；没有拒绝案例，不声称边界已经成立。

先修拥有问题的最小层：贡献表达不足就修具体表达；拓扑选择反复失败就修委派 skill；代表性证据改变整体、贡献、
重连或权威之间的解释关系，才修本文；需要提示外硬保证则回到 harness base 的研究。供应商案例、单次成功、一个
目录或某位 reviewer 的关注，不单独成为理论变更依据。

本文不提议新增哲学条目、固定角色体系、统一贡献 schema、强制多 Agent 流程或 runtime 实现。委派继续成立，
只因为在当前环境里，一个真实有界贡献能以相称成本改善整体结果，同时不让整体责任、证据和接受关系失落。
