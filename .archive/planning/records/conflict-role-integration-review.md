# 冲突角色整合候选审查

状态：`definition-boundary-observed / revision-applied / independent-review-complete / hold-dependent / acceptance-pending`。

关联 main goal：`01a0370c-d215-7680-909f-6145a34dc1bf`。

本记录处理用户提出的“多个互斥人格形成统一自我个体 Agent”的 experiment candidate。它只把含混
假设拆成可观察对象、最近邻和必要前置，不把输出中的人格风格、角色协调或自我描述写成意识或统一
主体已经存在。

## 1. 来源与问题

主要来源：

- [`inbox-history.md`](../inbox-history.md) 的 `IN-2026-08-24-001E`：用户提出以多个相互冲突的角色/人格
  形成“统一自我个体 Agent”，并将人的意识思维与矛盾想法联系起来；
- [`roadmap.md`](../roadmap.md) 的“冲突角色整合实验”候选：依赖概念碎片输出候选的定义与证据；
- [`concept-fragment-output-disposition.md`](concept-fragment-output-disposition.md)：只允许观察输出
  形式，不从文字推出未经语言处理的内部思维；
- [`../theory/harness/theory.md`](../../theory/harness/theory.md)：Task、Run、角色、证据、语义 review、
  acceptance 与方法/机制的所有权边界；
- [`../theory/harness/iterative-improvement.md`](../../theory/harness/iterative-improvement.md)：controlled
  delta、反例、unknown、独立 review 与不把一次结果升级为理论的规则。

当前问题不是“能否复刻人的意识”，而是：**在一个具体任务中，多个相互冲突的角色视角能否形成更有
用、更稳定、可解释且不越权的跨角色决策与行动关系？**

## 2. 七个对象必须分开

| 对象 | 可观察定义 | 不能直接推出 |
| --- | --- | --- |
| role-conditioned behavior | 在同一任务/来源下，不同 role lens 产生可区分的关注点、候选或表达 | role 是独立人格、意识主体或真实心理状态 |
| mutually exclusive role constraint | 在同一 task/source/context 下，两个 role lens 对目标解释、约束、风险或行动选择提出不能同时满足的要求；它是 fixture/候选属性 | 存在多个独立人格、心智模块或“脑内声音” |
| role conflict | 两个或多个 role-conditioned candidate 因上述约束发生可重建的不一致 | 冲突一定来自人格主体或意识流 |
| cross-role coordination | Agent 能保留冲突来源，说明取舍，形成一个后续可执行的候选、保留分歧、停止或交 owner | 已形成统一自我、主观体验或单一内部观察者 |
| functional identity continuity | 跨 role 切换仍能保持任务身份、已接受约束、承诺、经验归属和行动责任的可观察连续关系 | 已形成主观体验、现象意识或形而上的统一自我 |
| ontological unified self | 关于多个 role/过程背后存在一个独立、持续且统一主体的本体论主张；不是功能性身份的简称 | 功能连续、协调结果、行为一致或 self-model 不能单独推出该主体存在 |
| consciousness / subjective experience | 关于第一人称体验、感受或现象意识的哲学/科学主张 | 不能由输出风格、第一人称、自我报告、记忆连续或行为一致单独证明 |

本项目当前真正有资格研究的是前五项的行为关系；`consciousness / subjective experience` 与
`ontological unified self` 只能分别作为待研究的外部假设或哲学问题，不能成为当前 experiment 的成功条件或
runtime 字段。用户原话中的“互斥人格”和“统一自我”暂保留为 raw hypothesis，不作为本记录的工程
对象名称。

## 3. 最小可观察对象

暂用 **跨角色协调行为**（`cross-role coordination behavior`）作为 working designation。这里的 `role lens`
不是人格或心理模块，而是由 role id、来源、目标解释、约束、风险偏好和允许行动组成的可回溯条件化
视角；`role identity` 只指这组来源与约束在记录中的操作性标识。一次 episode 至少包含：

```text
同一 task/source/effect boundary
          ↓
两个或多个有来源的 role lens / candidate
          ↓
可重建的分歧或冲突
          ↓
协调：选择、组合、保留分歧、停止或交给 owner
          ↓
后续 action / output / effect
          ↓
结果、纠偏、持续性和下一判断
```

它要求观察“冲突是否改变了正确的下一行动，以及协调是否保持了目标和边界”，并可另观察跨 role
切换后的功能性身份连续；不是观察 Agent 是否说了“我有多个自我”。如果最好的结果是保留不确定性、
明确分歧或请求 owner，这也可能是合格协调；强行合成一个声音不是成功定义。

### 可比较的关系

- **role diversity：** 角色是否提供了不同且有来源的候选，而非同义改写；
- **coordination quality：** 是否能解释冲突、保留关键约束并形成与目标相关的下一步；
- **cross-context stability：** 在相同适用范围内，协调结果是否保持而不是随机换声线；
- **functional identity continuity：** role 切换后，任务身份、已接受约束、承诺、经验归属和责任关系是否
  能够连续重建；
- **correction behavior：** 发现错误后能否修正角色判断、保留未知或重新交 owner；
- **cost and boundary：** 增加的调用、上下文、延迟、人工负担和越权风险；
- **evidence provenance：** 每个 role/candidate 的来源、作用和不确定性是否可回溯。

这些是候选观察维度，不是已经冻结的 eval 指标；没有真实 consumer 和 card 时不能形成 Run。

## 4. 最近邻与排除

| 最近邻 | 它可以回答什么 | 为什么不等同于跨角色协调行为 |
| --- | --- | --- |
| 概念碎片式输出 | 是否能改变外显输出的粒度和形式 | 输出碎片不证明有多个角色或跨角色整合 |
| persona / role prompt | 是否能按不同角色表达关注点或策略 | 角色提示可能只是条件化表达，不产生独立主体 |
| ensemble / debate / multi-agent | 多个候选是否互相批评、投票或合成 | 投票/合成是编排方法，不证明单一统一自我 |
| planning / arbitration | 如何处理冲突候选、约束和下一行动 | 通用仲裁、投票或拼接若没有可回溯 role 来源、冲突依据和约束保留，只说明编排结果，不等同于跨角色协调 |
| memory | 过去状态、承诺和责任能否影响后续行为 | 有记忆不等于跨 role 的功能性身份连续，更不等于主观体验 |
| functional identity continuity | 跨切换后任务身份、约束、承诺、经验归属和责任能否纵向重建 | 功能连续不等于本体论统一自我或意识 |
| ontological unified self | 是否有一个持续的统一主体或本体论自我 | 功能身份、行为一致或自我模型不能单独证明本体论主张 |
| consciousness / subjective experience | 是否存在第一人称体验、感受或现象意识 | 任何本项目输出、行为、自报或记忆都不能单独证明意识 |
| self-model / self-report | Agent 如何描述自己的状态与边界 | 自报是输出证据，不能单独证明所述内部状态 |

特别排除：角色数量、互斥程度、第一人称频率、输出更长、叙述更连贯或自我报告更确信，都不能作为
“功能性身份连续”成立的充分证据；它们也不能作为本体论统一自我或意识成立的证据。功能性身份连续
可以通过跨情境、跨切换的行为关系研究；本体论统一自我与意识则分别不能由本项目的输出和 Run 单独推出。

## 5. 与 PL-11 的依赖关系

PL-11 的概念碎片候选可以为不同 role/candidate 的外显表达提供一个可能的观察载体，但它只定义输出
对象，不能提供 role identity、冲突来源、协调质量或统一自我证据。因而：

- PL-11 是当前实验方向的前置候选，但 PL-11 的定义 review 不等于 PL-12 的实验接受；
- 只有当 PL-11 产生可复用、可区分且不被误读为内部思维的输出对象后，才决定是否建立 role treatment；
- PL-12 仍需自己的 role definition、冲突 fixture、baseline/treatment、effect boundary、reviewer 和
  acceptance；不能借用 PL-11 的结果或名称完成归因。

## 6. 方案比较与当前处置

| 方案 | 判断 | 当前处置 |
| --- | --- | --- |
| A. 直接验证“多个互斥人格具有意识/主观体验” | 成功对象不可由当前输出和行为定义，容易把自报或风格当内部事实 | `no-proposal-for-consciousness-claim` |
| B. 直接验证“多个互斥人格形成形而上的统一自我” | 这是独立的本体论主张，不能由功能连续、行为一致或自我模型单独推出 | `no-proposal-for-ontological-unified-self` |
| C. 比较跨角色协调行为 | 有清楚的 episode 行为对象，但依赖 PL-11、真实 consumer 和可重建 card | **保留 definition candidate**；当前 `hold-dependent` |
| D. 单独比较功能性身份连续 | 是纵向跨切换对象，必须与单次冲突协调分开接受和归因 | **保留 definition candidate**；当前 `hold-dependent` |
| E. 用多个 Agent/模块投票或辩论代替人格 | 可作为一种 treatment/topology，但不能改变对象定义或自动取得 role 来源与约束保留 | `candidate-later`；不预先选架构 |
| F. 立即引入 persistent self、identity registry 或统一 memory | 当前没有必须由新机制承担的失败或 owner | `no-proposal-now`；不实现、不建 registry |

当前最小处置为：`retain-cross-role-definition-and-functional-continuity-definition /
hold-on-PL11-and-real-consumer /
no-proposal-for-consciousness-claim-and-ontological-unified-self / route-to-experiment-owner`。这不否定未来研究意识、主体性或
多视角协同，只关闭把它们提前写成同一个工程对象的路径。

## 7. 后续最小研究入口

若 PL-11 和真实 consumer 后续成立，先比较最小条件：

1. 单一 reactive/单视角 baseline；
2. 多 role candidate 但无强制统一的 treatment；
3. 多 role candidate 加明确的协调/保留分歧方法，单独归因跨角色协调行为；
4. 在明确 role switch 和观察窗口后，再单独归因功能性身份连续。

固定 task、source、model、harness、wake、权限和 effect boundary；对协调 episode 观察 role diversity、
协调质量、有效推进、错误/越权、纠偏成本和 owner burden；对身份连续另行观察跨 role switch 的任务身份、
约束、承诺、经验归属和责任重建。是否存在本体论“统一自我”或 consciousness 不列为当前 acceptance
指标，除非另有具备科学与伦理依据的独立研究设计和接受 owner。

## 8. 证据上限、允许效果与回返

- **当前 evidence standing：** 用户假设、PL-11 的输出边界、harness theory 的对象/证据规则和本次
  definition review；没有 role integration Run、matched improvement、协调行为证据、功能性身份连续证据、
  本体论统一自我证据、意识证据或 experiment acceptance。
- **允许效果：** 细化 PL-12 的可观察对象、记录其对 PL-11 的依赖、保留未来 experiment entry，并同步
  planning projections。
- **禁止效果：** 不创建 unified-self theory、persona skill、identity/memory registry、scheduler、
  runtime state，不启动 experiment/eval Run，不从 Agent 自报或文本风格推断意识。
- **revisit：** PL-11 的 accepted observable object、named experiment/eval consumer、冲突 fixture、
  可重建 baseline/treatment、独立 review、风险/伦理接受关系或 decision-changing counterexample 出现
  时重开；协调行为与功能性身份连续分别重建其对象、变量、归因和接受；仅有更强的“像人”叙述不重开。

本记录完成的是 PL-12 的定义边界审查，不完成 PL-11 接受、experiment acceptance、意识判断或系统实现。

## 9. 独立审查返回

- 首次独立审查：`revise`。审查指出两项会改变判断的缺口：原表把“统一自我”和“意识”放在同一对象中；
  “互斥人格”仍可能被读成未经定义的心理实体。
- 本次修订：将功能性身份连续与意识/主观体验、本体论统一自我分开；把互斥改写为同一 task/source/context
  下可观察的角色约束/fixture 属性，并将五项行为对象与两项不可直接推出的主张分别处置。
- 第二次独立复读：`revise`。审查发现最近邻仍合并统一自我与意识，方案 C 合并协调与功能性身份连续，且
  `role lens/identity` 与普通仲裁的边界不足。
- 本次再次修订：拆开 memory、functional identity continuity、ontological unified self 与 consciousness；
  将协调和身份连续分成独立方案、观察和归因，并补充 role 的操作性定义及普通仲裁的排除条件。
- 第三次独立复读：`revise`。审查发现 `ontological unified self` 仍未作为第 2 节的独立对象定义，不能只
  作为最近邻或方案处置出现。
- 本次修订：将对象表明确扩展为七项，并分别说明功能性身份连续、本体论统一自我与 consciousness 的边界。
- 修订后的第四次独立复读：`accept`。确认七个对象已分别定义；`role lens/identity` 只是可回溯操作性标签，
  普通仲裁/投票/拼接不自动取得跨角色协调的来源与约束关系；PL-11 依赖、证据上限、hold、禁止实现和
  acceptance 边界均未越界。该 verdict 只完成 definition review，不接受 experiment、skill、theory、WorkCell
  或 runtime。
